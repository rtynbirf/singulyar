# F-005 · ТРАНСПОРТНАЯ ДИСЦИПЛИНА: webtorrent-маршрут файлов зала ·22

**Статус:** утверждена 2026-11-13, ДО подключения маршрута (issue #68 п.6).
**Место маршрута:** СИНГУЛЯР_22_СВЯЗЬ.html, блок «РОЙ ФАЙЛОВ» (v1.26).
**Библиотека:** `webtorrent.min.js` (ESM-бандл, лежит в корне дома как материал).
**Страж соответствия:** `ИНСТРУМЕНТЫ/test_webtorrent_22.mjs` — проверяет, что код не вышел за границы этой дисциплины. Любое изменение маршрута = обновление этого документа в том же коммите (дом не притворяется).

---

## 1. Что это за маршрут

`webtorrent-маршрут` — передача запечатанных файлов между устройствами зала ·22 через WebTorrent: сидирование запечатанного блоба (`client.seed`) и докачка (`client.add`) по магниту, который едет по СУЩЕСТВУЮЩЕМУ каналу зала ·22 (запечатанный текст, AES-GCM, тот же ключ фразы). Маршрут закрывает границу, честно записанную в подкапотке ·22 с v1.25: «голос/файл между устройствами — следующий такт».

## 2. Что маршрут РАСКРЫВАЕТ (честно, без умолчаний)

| Кто смотрит | Что видит |
| --- | --- |
| Публичные WebSocket-трекеры WebTorrent | infohash (sha1 метаданных торрента) и IP:порт каждого участника; оператор трекера может коррелировать участников одного зала по infohash |
| Пиры WebRTC | запечатанный поток байтов — AES-GCM-256 шум; ключ фразы не ходит ни проводом, ни торентом |
| Оператор домашней сети | факт WebRTC/WebSocket-трафика, объём |
| Сам torrent | в него кладётся КОНСТАНТНОЕ нейтральное имя `зал22.bin`; исходное имя файла в торент не идёт — оно едет ТОЛЬКО в маркере по запечатанному каналу текста ·22 (AES-GCM). Уникальность infohash каждого файла даёт случайный IV внутри запечатанных байтов, имя не участвует |

DHT (Kademlia по UDP) в браузере недоступен — открытие только через трекеры, перечисленные в константе маршрута; список трекеров публичный и одинаковый у отправителя и получателя.

## 3. Что маршрут ПИШЕТ В ЖУРНАЛ

Журнал маршрута — **только локально на устройстве** (`#жрФайл` в ·22; по сети не уходит, в durable-журнал ·22 не попадает):

- фазы: включён / трекеры N / пиры M / байты скачано / ошибка (текст ошибки);
- магнит (infohash) и размер запечатанного блоба.

Чего в журнале НЕТ: содержимого файлов, исходных имён файлов, ключей фраз, текстов зала.

## 4. Что маршрут НЕ делает (границы)

1. **Не грузится при открытии страницы.** `webtorrent.min.js` подключается динамическим скриптом только по явному клику «включить p2p-файлы зала». OFF — состояние по умолчанию; закрытие вкладки выключает маршрут.
2. **Не работает без крипты.** Маршрут требует включённой КРИПТЫ (фраза зала): нет ключа — честный отказ, открытые файлы в публичные трекеры не ездят.
3. **Не печатает файл вне зала.** Запечатывание — ключом эпохи КРИПТЫ зала ·22; вскрывает только тот, у кого фраза.
4. **Не пишет на серверы дома.** Дом без сервера: трекеры — публичные, данные — пир-в-пир.
5. **Не смешивает залы.** infohash зависит от содержимого запечатанного блоба (случайный IV на каждый файл) — залы не коррелируются через имя/структуру торента сильнее, чем заявлено в §2.
6. **Не подменяет собственную сеть ·22.** Сигналинг зала, звонок, текст — без изменений; маршрут — ДОПОЛНЕНИЕ для файлов.

## 5. Режимы

- `выкл` (по умолчанию): ни скрипта, ни клиента, ни сокетов.
- `вкл`: клиент поднят, сидируем свои запечатанные файлы до закрытия вкладки, качаем по пришедшим магнитам. Кнопка выключения — та же (idempotent destroy).

## 6. Хвосты (честно)

- Симметричный NAT может не пробиться (медиа P2P без TURN — известная граница ·22; файловый маршрут наследует её).
- Публичный трекер может отвалиться — маршрут не чинит чужие сервисы, честно пишет ошибку в журнал.
- Голосовые между устройствами (длительные медиа) — отдельный такт, в дисциплину файлов не входит.
