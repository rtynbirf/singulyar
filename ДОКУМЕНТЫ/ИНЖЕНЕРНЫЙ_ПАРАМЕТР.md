## 1. Инвариант

**Изменение представления не уменьшает множество доступных человеку
функций и параметров.**

Цепочка каждого параметра:

```text
PARAMETER → DISCOVERABLE → INSPECTABLE → CONTROLLABLE → PERSISTENT → REVERSIBLE
```

Параметр, который нельзя найти, посмотреть, поменять руками, сохранить
и откатить — не параметр, а каприз системы. Простота — это режим
представления (`simple`), а не урезание множества возможностей: `full`
всегда не меньше `simple`. Это тот же инвариант, что и у лица дома:
«Что хотите сделать?» — и всегда рядом «Я сам».

## 3. Capability-цепочка (честная проверка возможностей)

```text
API_PRESENT → RUNTIME_REQUEST → RUNTIME_RESULT → VERDICT
```

Наличие API в навигаторе ещё не доказывает, что возможность реально
работает: Wake Lock требует secure context и видимости, SpeechRecognition
и Media Session поддержаны не везде. VERDICT ставится только по факту
запроса в рантайме. `UNKNOWN ≠ FAIL`: незнаем — говорим «незнаем».

## 5. Дисциплина критики: PROBLEM → ALTERNATIVE → WHY → TEST

Каждое замечание к baseline живёт только в паре с альтернативой и тестом.

- **Embedded media.** PROBLEM: 5,7 МБ медиагрузки внутри программного
  документа. ALTERNATIVE: отдельный ассет + манифест. WHY BETTER: независимое
  кэширование, замена, контрольная сумма. ТЕСТ: офлайн-закон дома всё равно
  держит медиа у человека — здесь пока baseline 1:1, решение за владельцем.
- **Capability detection.** PROBLEM: `"wakeLock" in navigator → PASS`
  доказывает только наличие имени. ALTERNATIVE: цепочка из §3. WHY: имя ≠
  работающая возможность. ТЕСТ: тест двери прогоняет цепочку в браузере
  (браузерная часть — отдельная дисциплина, см. `test_s30_browser.py`).

## 6. Что зафиксировано в baseline (факты, не оценки)

Baseline `kvartirnik.html` = **5 723 784 байта**, 11 `<script>`-блоков,
1 `<style>`-блок, встроенный аудиоресурс; внутри уже живут persistence,
JSON import/export, клавиатурное управление, диагностические подсистемы,
Speech Recognition, Speech Synthesis, MediaRecorder, Wake Lock. Большой
единый файл — не приговор: функциональная сложность сохраняется, а
структурная связанность снижается архитектурой

```text
Presentation → Application/Domain → State + Parameter Registry →
Capability Adapters → Browser/OS
```

33-файловый инженерный прототип (SHA-256
`8d0abeed2ef548bfeeacb1e7a1b11983834085e46f997836bd503023cd4e72a8`) —
рабочая заготовка этой архитектуры: 5/5 unit-тестов и 8/8 статических
проверок архитектуры пройдены; честные UNKNOWN перечислены в его
release gate. В дом он входит дверью ·31 в форме baseline 1:1 — новые
модули не пишутся, пока существующий не встал адаптером на примитивы.
