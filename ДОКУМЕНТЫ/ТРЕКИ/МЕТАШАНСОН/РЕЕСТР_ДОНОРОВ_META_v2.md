## 1. Узел parseLRC-плеер — ПРИНЯТ каноном `lrc-ядро/0.1`

- Канон: `ДОКУМЕНТЫ/ТРЕКИ/КАРАОКЕ_СИНХРОН/src/lrc-ядро.mjs` · тесты `tests/test_lrc_ядро.mjs` — **18/18** (`node --test`).
- Порт: `js/lrc-core.js` (`window.__ЛРЦ`, ES2019, IIFE) — генерирован из канона механически, vm-сверка ≡ байт-в-байт; в пре-кэше воркера (v199).
- Что взято: разбор LRC/ELRC (позиционные дроби `.5 == 500 мс`, множественные метки, enhanced-слова `<mm:ss.xx>`, ID-теги + `offset` с честным отказом на двусмысленности, стабильная сортировка) + обратная сборка `собратьLRC`.
- Что НЕ взято из донора: DOM-вывод донора (innerHTML) — панель дома строит DOM через createElement/textContent; автозапуск плеера — не входит (плеер зала канонен).
- Законы канона: 0 сети / 0 случайности / 0 часов / вход не мутируется / честные русские отказы.

## 2. Узел «самосборщик-скрипт» (build_singular_meta.py) — ОТВЕРГНУТ из рантайма дома

- Причина: сборочные скрипты живут в Песочнице агентов, не в доме (дом — ноль node_modules и ноль сборки в рантайме, закон репы); сборка прототипа одним скриптом противоречит такт-ритуалу (сборка релиза — цех такта, стадии 1–8).
- Судьба: остаётся в блокноте владельца как донор методики; в дом не входит. Если владельцу нужен офлайн-сборщик — канон отдельного трека по приказу.

## 3. Узел «св-кэш-список» — ОТВЕРГНУТ

- Причина: Service Worker дома (`sw15.js`) — оркестратор с защищёнными AI-кэшами, потолками S15_MAX/S15_MAX_BYTES, поколениями v199 и R-05-нормализацией ключей — сильнее донорского списка; дубль стратегии кэша = два источника правды (запрещено «один факт — одно место»).

## 4. Антипаттерны донора — ОТВЕРГНУТЫ законами дома (как и предписывала строка М9)

- `alert/prompt/confirm` — против доступности (дом: честные карточки и aria-live).
- `Math.random()` в «метриках» — против честности (дом: числа только из измерений/реестра; детерминизм канонов).
- Дубли живых дверей ·16/·17/·24/·25 в прототипе — против комода и манифеста-нити (дверь одна, факты не двоятся).
