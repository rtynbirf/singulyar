# 03 · Архитектура

## 1. Слои
```
Событие .harm  ──►  Загрузчик/валидатор  ──►  Планировщик (PulseEngine)
                                                    │ единые аудио-часы
        Профиль (оси) ──► Резолвер каналов ──► Рендереры: текст · свет · звук · вибро · кнопки
                                                    │
                                   Журнал доступа ◄─┘ (каждое обращение к устройству)
        Хранилище устройства (IndexedDB + WebCrypto)      Сеть: выключена по умолчанию
```

## 2. Решения и обоснования
| Решение | Почему | Альтернатива, которую отвергли |
|---|---|---|
| Единые аудио-часы (`AudioContext.currentTime`) | Таймеры страницы дрожат и замедляются в фоне | `setTimeout`: не даёт ±25 мс |
| Планировщик с упреждением ~120 мс | Звук ставится в очередь заранее, точность до сэмпла | Запуск звука в момент события |
| Профиль из осей, ярлыки только пресеты | Люди не вписываются в ярлыки; событие не должно знать диагноз | Фиксированные «ADHD / аутизм / …» |
| Резолвер каналов | Событие говорит «кульминация», резолвер выбирает свет, вибро или текст по профилю | Разные версии события на каждый профиль |
| Вибро как необязательный канал | На iOS его нет; у людей разная чувствительность | Вибро как единственный канал |
| Один файл `.harm` | Переносимость, офлайн, подпись автора | Облачный сервер событий |
| IndexedDB + WebCrypto в MVP | Просто, надёжно, достаточно | Solid-под сразу: сложно, мало экосистемы |
| Локальное распознавание речи | Принцип «данные не уходят» | Web Speech API: в ряде браузеров идёт через облако |

## 3. Синхронизация (подробно)
1. Планировщик каждые 25 мс ставит в очередь события, которые наступят в ближайшие 120 мс, по аудио-часам.
2. Для текста и света используется `requestAnimationFrame`, время берётся как `currentTime − задержка вывода − сдвиг пользователя`.
3. Задержка вывода берётся из `outputLatency` (если есть) и дополняется ручной калибровкой: пользователь двигает сдвиг до совпадения звука и подсветки.
4. Вкладка ушла в фон: воспроизведение останавливается, а не продолжается рассинхронизированным (поведение прототипа).

## 4. Резолвер каналов
Вход: маркер события `{intent, payload}` и профиль. Выход: набор действий по каналам.
- `intent: accent` → при `vibro>0` короткий импульс; при `motion≠none` световой пульс; при `output=braille` точка на дисплее; всегда текстовая метка в расшифровке.
- `intent: sceneChange` → смена палитры и плотности; при `motion=none` мгновенно, без перехода.
- Правило: **каждый смысл доставляется минимум двумя каналами**, один из них всегда текст.

## 5. Модули
| Модуль | Ответственность |
|---|---|
| `core/pulse` | Часы, планировщик, калибровка |
| `core/profile` | Оси, пресеты, экспорт/импорт, системные настройки |
| `core/resolver` | Правила intent → каналы |
| `core/ledger` | Журнал доступа, права, отзыв |
| `render/text` | TextPulse, расшифровка |
| `render/light` | Палитры, пульс, ограничение вспышек |
| `render/haptic` | Vibration API и запасные каналы |
| `input/clap` | Детектор хлопков |
| `input/voice` | Локальное распознавание (позже) |
| `format/harm` | Чтение, валидация, подпись |
| `net/rtc` | Совместные события (позже) |
| `plugins` | Изолированные расширения (позже) |

## 6. Токены дизайна
Цвета, размеры текста, длительности и радиусы живут в CSS custom properties. Сцена задаёт значения по умолчанию, профиль переопределяет. Контраст проверяется автоматически для всех пар «текст/фон» во всех сценах (≥ 4.5:1 для обычного текста).
