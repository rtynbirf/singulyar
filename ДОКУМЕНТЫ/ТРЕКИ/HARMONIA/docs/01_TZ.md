# 01 · Техническое задание HARMONIA v1.0

## 1. Цель
Открытая платформа для создания и проведения интерактивных событий. Каждый участник получает событие в своём формате (визуал, звук, вибро, текст, темп) по собственному профилю. Данные профиля и взаимодействий остаются на устройстве участника.

## 2. Пользователи
| Роль | Задача |
|---|---|
| Участник | Открыть событие, подстроить под себя, быть уверенным, что данные не уходят |
| Автор события | Собрать событие из маркеров на временной шкале, проверить на разных профилях, выпустить файлом |
| Организатор | Провести событие вживую (хлопки, ответы), увидеть обезличенную статистику |
| Разработчик | Расширить платформу плагином или встроить плеер |

## 3. Функциональные требования
Приоритеты: M — обязательно для MVP, S — после MVP.

### 3.1 Плеер событий (M)
- F1. Воспроизведение события из файла `.harm` без сети (M).
- F2. Текст-пульс с четырьмя уровнями гранулярности: буква, слог, слово, строка (M).
- F3. Единые часы: все каналы привязаны к аудио-часам. Дрейф ≤ 25 мс за 10 минут (M).
- F4. Калибровка задержки: пользователь двигает сдвиг ±300 мс, значение хранится в профиле (M).
- F5. Расшифровка событий текстом, доступная без темпа (M).
- F6. Сцены (День, Вечеринка, Дети, Романтика) как наборы значений: палитра, плотность, темп (M).

### 3.2 Профиль доступности (M)
- F7. Оси из `04_PROFILE_SPEC.md`: движение, текст, контраст, темп, громкость, вибро, ввод, вывод (M).
- F8. Автоначальные значения из системных настроек (`prefers-reduced-motion`, `prefers-contrast`) (M).
- F9. Экспорт и импорт профиля файлом JSON (M).
- F10. Событие получает только производные значения, никогда ярлыки нейротипа или диагнозы (M).

### 3.3 Журнал доступа (M)
- F11. Запись каждого обращения к микрофону, звуку, вибро, хранилищу, сети (M).
- F12. Журнал виден в интерфейсе, экспортируется, очищается пользователем (M).
- F13. Любая сетевая отправка по умолчанию запрещена и требует отдельного явного согласия на одно событие (M).

### 3.4 Каналы ввода и вывода
- F14. Вибро через Vibration API, если доступен; всегда дублируется световым пульсом (M).
- F15. Хлопки: определение по резкому росту энергии в полосе 1–4 кГц, минимальный интервал 150 мс, обработка только на устройстве (M).
- F16. Голосовые ответы через локальное распознавание (Whisper, WebGPU / WASM). Облачное распознавание отключено по умолчанию (S).
- F17. Альтернативы жестам: любое действие доступно кнопкой, клавиатурой, переключателем (M).

### 3.5 Автор (S)
- F18. Редактор временной шкалы: маркеры text / scene / haptic / light / button, предпросмотр на 3 профилях одновременно (S).
- F19. Экспорт события в `.harm` с подписью Ed25519 (S).
- F20. Проверка события: `harm validate` в CLI и проверка в редакторе (S).

### 3.6 Совместное участие (S)
- F21. Синхронный просмотр нескольких людей через WebRTC, до 8 пиров, дальше релей (S).
- F22. Передаются только агрегаты (интенсивность хлопка, номер ответа), без аудио и без идентификаторов (S).

### 3.7 Расширения (S)
- F23. Плагины в изолированных iframe с декларацией разрешений, без сети по умолчанию (S).

## 4. Требования к доступности
- Соответствие WCAG 2.2 AA для всех экранов, в том числе: размер целей ≥ 24×24 px (в прототипе 44×44), видимый фокус, не скрытый другими элементами, альтернативы перетаскиванию, без запрета вставки в поля (SC 2.4.11, 2.5.7, 2.5.8, 3.3.7, 3.3.8).
- Не более 3 вспышек в секунду (SC 2.3.1). При `motion = none` вспышек нет.
- Реальное тестирование: минимум 5 человек из каждой группы (слепые и слабовидящие, глухие и слабослышащие, дислексия и когнитивные особенности, моторные ограничения, чувствительность к стимулам).
- Совместимость со скринридерами: NVDA, JAWS, VoiceOver, TalkBack.

## 5. Требования к приватности
- Ноль сторонних скриптов, шрифтов, аналитики. Строгий CSP.
- Данные профиля и журнал: локальное хранилище, шифрование ключом, неизвлекаемым из WebCrypto (S).
- Никаких обещаний, которые технически нельзя выполнить: интерфейс говорит «удалено на этом устройстве», а не «удалено везде».
- Подробнее: `05_PRIVACY_THREAT_MODEL.md`.

## 6. Нефункциональные требования
| Параметр | Требование |
|---|---|
| Запуск | LCP < 2.0 с на среднем Android, INP < 200 мс |
| Размер | Ядро ≤ 150 КБ gzip, плеер без медиа ≤ 400 КБ |
| Офлайн | 100% функций плеера без сети |
| Браузеры | Последние две версии Chrome, Edge, Firefox, Safari |
| Лицензии | Код MIT, документация CC BY 4.0, формат открыт |
| Локализация | Русский, английский; строки во внешнем словаре |

## 7. Технологический стек
- Ядро: TypeScript, Web Components (Lit), CSS custom properties для токенов.
- Аудио: Web Audio API, AudioWorklet для детектора хлопков в фазе 2.
- Хранение: IndexedDB + WebCrypto. Solid-совместимость отложена на год 2.
- Сеть (фаза 3): WebRTC DataChannel, самохостящийся релей.
- Локальный ИИ (фаза 3): Transformers.js, ONNX Runtime Web, WebGPU с откатом на WASM.
- Тесты: Playwright, axe-core, Lighthouse CI, ручные сценарии с пользователями.

## 8. Критерии приёмки MVP
1. Событие `.harm` открывается офлайн в браузере без установки.
2. Три разных профиля видят и ощущают его по-разному, смысл одинаков.
3. Журнал показывает все обращения приложения, скрытых нет (проверяется через DevTools Network: 0 запросов).
4. Дрейф ≤ 25 мс на 10-минутном треке.
5. 0 критичных нарушений в axe-core и 0 блокирующих замечаний от пользователей-тестировщиков.

## 9. Вне объёма MVP
Платёжные функции, соцсеть, рекомендательные алгоритмы, нейроинтерфейсы, облачное хранение профилей.
