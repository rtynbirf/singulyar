# ПРОТОКОЛ ЖИВОГО ДРЕЙФА · ГАРМОНИЯ (фаза 2, такт v10.73 «СВОД»)

**Кто исполняет:** владелец 👤 (замер физически требует реального устройства — аудио-часы
в headless-браузере не стенные, поэтому фаза 1 честно ограничилась симуляцией).
**Что меряем:** дрейф диспетчеризации пульса против АУДИО-часов реального устройства —
`maxLateMs` из `measureDrift()` движка (`src/pulse-engine.mjs`).
**Бюджет:** ≤ **25 мс** (`DRIFT_BUDGET_MS`; движок сам возвращает `withinBudget`).
Эталон симуляции (фаза 1): худший `maxLateMs` = **12,65 мс** за 8 прогонов × 10 минут —
это отсечка, с которой сравниваем живой результат.

## Честные границы протокола (читать до замера)

- Движок плеера живёт в модульной области страницы и наружу не отдаётся (приватность
  и простота фазы 1). Проба ниже создаёт **отдельный экземпляр того же модуля
  планировщика** (`../src/pulse-engine.mjs` — буквально тот же файл, что играет в плеере)
  на реальных аудио-часах устройства. Это честный живой аналог `tests/drift-measure.mjs`,
  а не телеметрия (её нет и не будет — CSP запрещает любые соединения).
- Меряем дважды: **на покое** и **под нагрузкой** (пока плеер играет демо со светом,
  звуком и подсветкой слогов). Второй замер ближе к жизни зала.
- Положительный `maxLateMs` — единственный нормируемый показатель. Отрицательный
  (`maxEarlyMs`) — это диспетчеризация внутри окна упреждения 120 мс, по построению
  норма; **не брак**. Время применения у потребителя всегда точное (событие несёт
  аудио-момент `at`).
- Проба меряет таймеры страницы против аудио-часов. Bluetooth-наушники и прочие
  задержки вывода (`outputLatency`) на дрейф диспетчеризации не влияют — их плеер
  учитывает отдельно (§3.3 архитектуры).

## Что понадобится

1. Устройство, на котором будет жить плеер (телефон или ноутбук), заряд > 50 %,
   энергосбережение выключено.
2. Браузер с DevTools-консолью: Chrome/Edge/Firefox на любом, Safari на macOS
   (на iPhone — через Web Inspector с Mac, см. «Если нет консоли»).
3. Папка ГАРМОНИИ (player/ + src/) — локально или прод-страница Pages.

## Подготовка

1. **Локально:** в корне ГАРМОНИИ запустить `python3 -m http.server 8000` и открыть
   `http://localhost:8000/player/index.html` (на телефоне — через Wi-Fi-адрес компьютера
   или USB-туннель). **Или** открыть прод-страницу плеера на Pages — CSP и модули
   там те же.
2. Убедиться, что страница рабочая: заголовок «ГАРМОНИЯ · плеер событий», кнопка
   «Играть», расшифровка. Должно быть написано «Событие проверено, готово к запуску».
3. Открыть DevTools → вкладка **Console**.
4. Условия прогона: экран включён, вкладка активна и **не сворачивается** весь прогон
   (в фоновой вкладке таймеры замирают — движок честно ставит паузу по >1 с зазору,
   и прогон будет забракован как недействительный), прочие вкладки/приложения закрыть.

## Шаг 1 — холодный замер (покой)

5. Нажать «Играть», затем сразу «Пауза» (один клик разблокирует аудио-часы браузера).
6. Вставить в Console пробу целиком (Приложение A) и нажать Enter.
7. Ждать: `MIN` минут + 5 с (по умолчанию 3 мин). Вкладку не трогать.
8. Проба сама напечатает `console.table` с `maxLateMs`, `maxEarlyMs`, `lateCount`,
   `stalls` и вердикт, а также положит результат в `window.__driftLog`.

## Шаг 2 — замер под нагрузкой

9. Нажать «Играть» и **не останавливать** демо (идут звук, подсветка слогов, сцена).
10. Повторить шаги 6–8 (та же проба во второй раз).
11. Оба шага повторить **по 2 прогона** (перезагружать страницу между прогонами не
    обязательно, но проба обязана закончиться вердиктом до следующего старта).

## Шаг 3 — что записать

Таблица в файл лога (см. «Экспорт»):

| Поле | Откуда |
|---|---|
| дата, время | проба кладёт ISO-дату в `__driftLog.дата` |
| устройство, ОС, браузер, версия | проба кладёт `navigator.userAgent` |
| режим | «покой» / «под нагрузкой» — вписать руками в `__driftLog.режим` |
| длительность, событий | `MIN` и `samples` (сколько диспетчеризаций меряно) |
| **maxLateMs** | главный показатель (мс опоздания против аудио-часов) |
| maxEarlyMs, lateCount | для наблюдения (ранние — норма; lateCount — сколько раз опоздали хоть на йоту) |
| stalls | замирания главного потока >1 с; `stalls > 0` → прогон недействителен |
| вердикт | «в бюджете» / «вне бюджета» |

## Критерии пропуска / брака

- **ПРОПУСК:** во всех четырёх прогонах (покой ×2, нагрузка ×2): `stalls = 0`
  и `maxLateMs ≤ 25,000 мс` (проба печатает «ВЕРДИКТ: в бюджете»).
- **ПЕРЕЗАПУСК (прогон не считать):** `stalls > 0` — вкладка спала или главный поток
  замирал; убрать причину (фон, выключение экрана, тяжёлая параллельная задача) и
  повторить прогон.
- **БРАК:** в обоих режимах, по два прогона подряд, `maxLateMs > 25 мс`. Тогда:
  1) записать условия (устройство, заряд, тема энергосбережения, открытый DevTools на
  слабом телефоне сам добавляет нагрузку — попробовать remote-отладку с выключенным
  окном инспектора); 2) повторить после перезагрузки устройства; 3) если брак
  стабилен — пометить строку «ЖИВОЙ ДРЕЙФ» в карте как БРАК, приложить лог, поднимать
  разбор (кандидаты: троттлинг таймеров ОС, агрессивный энергосберегающий режим,
  аномалия конкретного браузера).
- Отдельно сравнить с эталоном симуляции 12,65 мс: живой результат до ~25 мс —
  в бюджете; заметно хуже симуляции, но в бюджете — записать честно, решение о
  годности не меняется (бюджет — единственный критерий).

## Экспорт лога

- В Console: `copy(JSON.stringify(window.__driftLog, null, 2))` — буфер обмена;
  вставить в файл `доки/живой-дрейф-<ГГГГ-ММ-ДД>.txt` (JSON-строки по прогону) —
  файл поедет в репозиторий следующей волной (фаза 3 его заберёт).
- Если `copy` недоступен (Firefox): ПКМ по выводу `console.table` → «Сохранить как»,
  или скриншот таблицы.
- Устройства без консоли: Android — `chrome://inspect` через USB с компьютера
  (удалённая консоль той же страницы); iPhone — Safari на Mac → «Разработка» →
  Web Inspector. Если и это недоступно — честно пометить в карте «устройство без
  консоли, замер перенесён на другое» и провести замер на доступном устройстве,
  указав его в логе.

## Приложение A — проба (вставить в Console целиком)

```js
(async () => {
  const MIN = 3;   // минут на прогон; 10 — как в симуляции фазы 1
  const { PulseEngine } = await import('../src/pulse-engine.mjs');
  const ctx = new AudioContext();
  await ctx.resume();
  if (ctx.state !== 'running') {
    console.error('Аудио-часы не пошли (state=' + ctx.state + '): кликните по странице и запустите пробу снова.');
    return;
  }
  const bpm = 120;
  const events = [];
  for (let i = 0; i < Math.round(MIN * 60 * (bpm / 60)); i++) {
    events.push({ beat: i, type: 'text', data: {}, alt: 'проба' });
  }
  const stalls = [];
  const engine = new PulseEngine({
    clock: { now: () => ctx.currentTime },   // РЕАЛЬНЫЕ аудио-часы устройства
    events, bpm,
    useTimer: true,                          // реальные таймеры страницы — то, что меряем
    onEvent: () => {},
    onStall: (s) => stalls.push(s),          // замирание >1 с — прогон недействителен
  });
  engine.play();
  console.log('Проба пошла: ' + MIN + ' мин · bpm ' + bpm + ' · событий ' + events.length + '. Вкладку не сворачивать.');
  setTimeout(() => {
    const d = engine.measureDrift();
    engine.dispose(); ctx.close();
    window.__driftLog = {
      дата: new Date().toISOString(),
      устройство: navigator.userAgent,
      ядер: navigator.hardwareConcurrency ?? null,
      режим: 'укажите: покой / под нагрузкой',
      минут: MIN, событий_план: events.length, stalls,
      ...d,
    };
    console.table([window.__driftLog]);
    console.log(d.withinBudget
      ? 'ВЕРДИКТ: в бюджете (maxLateMs ≤ 25 мс)'
      : 'ВЕРДИКТ: ВНЕ БЮДЖЕТА — протокол, раздел «Если брак»');
    console.log('Экспорт: copy(JSON.stringify(window.__driftLog, null, 2)) → вставить в файл лога.');
  }, MIN * 60 * 1000 + 5000);
})();
```

Ожидаемый вид результата: `samples` ≈ `событий_план`, `maxEarlyMs` в пределах −120 мс
(окно упреждения), `maxLateMs` — единственный судья бюджета, `stalls: []`.
