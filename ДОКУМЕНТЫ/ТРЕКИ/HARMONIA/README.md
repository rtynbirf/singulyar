# HARMONIA · пакет проекта v0.1

Платформа интерактивных событий (концерт, лекция, тренинг, детский праздник), где **одно событие подстраивается под каждого участника**: свет, звук, вибро и текст подбираются под его профиль доступности. Выросла из страницы ЛАДОМ (СИНГУЛЯР · «ОБЕРЕГ» · «Просто люби»).

## Как попробовать прототип
1. Откройте `prototype/index.html` в Chrome, Edge, Firefox или Safari.
2. Нажмите «Играть». Звук синтезируется в браузере, файлов нет.
3. Смените сцену, настройте профиль. Он сохраняется только на устройстве.
4. «Хлопки» включают микрофон только для поиска хлопков. Звук не записывается и не передаётся.
5. Журнал внизу показывает каждое обращение приложения к устройству.

## Честные ограничения прототипа
- Прототип проверен только чтением кода, не прогонялся в живых браузерах и на реальных устройствах. Первым делом пройдите `docs/06_QA_PLAN.md`, раздел «Дымовой тест».
- Вибро работает только там, где браузер поддерживает Vibration API (Android: Chrome, Edge, Firefox, Samsung Internet). На iPhone и ноутбуках пульс идёт светом.
- Детектор хлопков при громкой музыке из колонок срабатывает ложно: нужны наушники или тихий режим.
- Сервер, синхронизация между людьми и редактор событий в прототип не входят (см. ТЗ, фазы 2–3).
- Лицензия: MIT для кода, CC BY 4.0 для документации (`LICENSE`). Тексты песен в демо оригинальные.

## Детектор хлопков — фазы 2–3 (такт v10.80 «ХВОСТЫ», задача Г3)

| Путь | Что это |
|---|---|
| `src/clap-detector.mjs` | Детектор хлопков: чистая DSP-функция `detectClaps(buffer, sampleRate)` (разовый разбор) + потоковый `ClapTracker` + обвязка `createClapDetector({ audioContext, sourceNode, onClap })` для AudioWorkletNode. 0 сети, 0 внешних импортов, работает в node и браузере. |
| `tests/test_clap_detector.mjs` | node:test-набор рядом с sim-clock: синтетика 48 кГц (шум — детерминированный mulberry32), время хлопков ±10 мс, двойной, рефрактерность, шум/тон/тишина без срабатываний, контракт событий, reset, поток через несколько feed, честный фолбэк. |

Как считает: энергия окон 5 мс → адаптивный порог (медиана скользящего окна 500 мс × 5, нижняя планка) → хлопок = резкий рост (≥ 3× предыдущего окна) со спадом до ≤ 25% пика быстрее 120 мс → рефрактерность 180 мс → два хлопка с интервалом 180–600 мс дают отдельное событие «двойной». Событие: `{ t, энергия, индекс, тип }` (t — секунды аудио-часов; у «двойной» ещё `t2` и `интервалМс`).

Архитектура обвязки (честно): в аудио-потоке живёт только крошечное реле (AudioWorkletProcessor, blob-модуль — сеть не нужна), которое пересылает блоки сэмплов с абсолютным индексом; весь разбор ведёт тот же `ClapTracker`, что протестирован в node. Нет AudioWorklet — `createClapDetector` возвращает честный отказ `{ ok:false, причина }` с безопасными no-op start/stop: имитации детектора нет.

Честные ограничения: порог эмпирический, проверен на синтетике тестов; громкая музыка из колонок даёт ложные срабатывания (ограничение прототипа выше остаётся в силе — наушники или тихий режим); живой микрофонный прогон и подстройка порога в реальном зале — 👤 владельца (фаза 3). Прогон: `node --test tests/test_clap_detector.mjs` — 13/13 зелёные; `node --check src/clap-detector.mjs` — чисто.
