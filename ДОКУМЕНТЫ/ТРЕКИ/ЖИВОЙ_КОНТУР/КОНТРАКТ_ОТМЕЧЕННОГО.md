# КОНТРАКТ ОТМЕЧЕННОГО «ЖИВОГО КОНТУРА» — схема данных v1

**Трек:** Живой контур · Такт v10.73 «СВОД» · Задача 2-b · Дата: 2026-10-12
**Статус:** согласовано по Этапу 0 (аудит зала ·31 — `ЭТАП_0_АУДИТ.md`); это финальная схема, по которой Этап 1 пишет код.
**Источники сверки:** ТЗ комплекта 03 (§3.3 «Память отмеченного»), пример комплекта 07 (§3 «Пример структуры локальных данных»), реалии кода зала (строки файла указаны по копии из аудита).

> **СТАТУС РЕАЛИЗАЦИИ (выровнено тактом v10.78 «СЛОГ», С54):** канон реализации Этапа 1 — ключ **`kv.контур`** в localStorage (структура `{ [песня]: { [строка]: { т:{ [нормСлово]: {в,с,n,t}, … }, с, t } } }`, код v10.75 «СВЕДЕНИЕ КАРТ», принят коллегами). Схема `s31.zhkontur.v1` ниже — исходный проект Этапа 0, живёт как референс: `songId` (videoId из каталога фонда) = ключ песни в kv.контур; `lineIndex` = индекс оси `window.SONG.cues`; `status(understood|return)` = `с("понял"|"вернусь")`; `ts` = поле `t` (мс). `hapticAccent` (Этап 3, v10.78) реализован **без второй ручки**: силу и сам факт вибро-акцента масштабирует ось haptic `__ПРОФИЛЬ` — одна ручка на ось, дублей состояния нет (выключенная ось — тишина; РЕЛАКС молчит; «не вспомнил» не вибрирует).

---

## 1. Задача контракта

Хранить **локально** список выражений/строк, которые человек сам отметил во время пения («Понял» / «Хочу вернуться»), чтобы: (а) мягко подсвечивать их при следующих прослушиваниях той же песни (если включён возврат), (б) предлагать необязательное послепесенное повторение 1–3 элементов, (в) экспортировать/удалять только по явному действию.

ТЗ комплекта (03, §3.3): *«Структура минимальная: songId + lineIndex + wordRange (опционально) + timestamp + status (понял / хочу вернуться). Удаление реально удаляет данные.»*

## 2. Решения по реалиям зала (что и почему поправлено против примера 07)

| Вопрос | Пример комплекта (07 §3) | Реалия зала (аудит) | Решение v1 |
|---|---|---|---|
| Где взять songId | «uuid-or-hash» | В `window.SONG` **поля id нет** (стр. 1142: только `i/t/artist/dur/…`); id песен живут в каталоге фонда `window.__ЗАЛ.КАТАЛОГ` (`{"t":"Просто люби…","v":"9ys_TVEtda8"}`, стр. 12311) | `songId` = **videoId из каталога фонда** (`__ЗАЛ.КАТАЛОГ[].v`); дом-песня = `9ys_TVEtda8`. Для треков вне каталога — честный отказ отметки «песня без id» |
| Индекс строки | `lineIndex` | Ось одна: `window.SONG.cues` (2875 «ЗАКОН ПОНИМАНИЙ»), в DOM — `el.dataset.i` (1351) | `lineIndex` = индекс по оси `cues`, 0-based, целое |
| Слово | `wordStart/wordEnd` | Слова как спаны `.tk` существуют **только на активной строке** (3592–3595); неактивная строка — цельный текст; слово зависит от языка отображения | `wordRange: {s,e}` — 0-based, полуоткрытый `[s,e)` **по словам строки выбранного языка** (сплит по whitespace); отсутствие = отмечена вся строка |
| Язык отметки | нет поля | В зале ось ЯЗЫКОВ: одна ось строк — много пониманий (`__LANGS`, 2791; `dataset.lang`, 2775); слова `wordRange` у разных языков разные | Добавлено поле **`lang`** (ключ языка из `__LANGS`, напр. `ru`, `es`, `ja`). Без него подсветка чужого языка была бы ложной |
| Текст отметки | `text` | Переводы могут правиться (редактура «ЧЕЛОВЕК РЕШАЕТ») — сверка по тексту могла бы лгать | Поле **`quote`** (≤160 символов, точный текст на момент отметки) — опционально, для честной сверки; не участвует в поиске, не показывается как «правда» |
| Статус | `status: "want_return"` | ТЗ ЗК: «понял / хочу вернуться» | enum **`"understood"` \| `"return"`** (ASCII для стабильности экспорта; UI-подписи «Понял»/«Хочу вернуться»; при импорте `"want_return"` маппится в `"return"`) |
| Время | `createdAt/lastSeenAt` | Минимум ТЗ: `timestamp` | **`ts`** — ISO 8601 UTC момента отметки; `lastSeen`/`times` — зарезервированы под Этап 2 («сколько раз возвращался»), в v1 не заполняются |
| Настройки | `settings{returnEnabled,hapticAccent,showBoth}` | Режим «Оба» в зале уже существует (три строки всегда, v10.11, стр. 4470) | Настройки живу́т рядом в том же доке: `returnEnabled` (подсветка), `hapticAccent` (Этап 3). Ручка «Оба» не добавляется — она уже есть в доме |

## 3. Финальная схема v1

Документ «Живого контура» — **один ключ** в едином доке дома:

```
Ключ: "s31.zhkontur.v1"            (в window.__СКЛАД → док s31.prefs.v2 + IDB «s31-склад», store "prefs")
```

```json
{
  "v": 1,
  "отметки": [
    {
      "id": "9ys_TVEtda8|es|6|2-4",
      "songId": "9ys_TVEtda8",
      "lang": "es",
      "lineIndex": 6,
      "wordRange": { "s": 2, "e": 4 },
      "quote": "Solo cree, y tu alma volará.",
      "ts": "2026-10-12T14:30:00.000Z",
      "status": "return"
    },
    {
      "id": "9ys_TVEtda8|ru|39",
      "songId": "9ys_TVEtda8",
      "lang": "ru",
      "lineIndex": 39,
      "ts": "2026-10-12T14:31:10.000Z",
      "status": "understood"
    }
  ],
  "настройки": { "returnEnabled": true, "hapticAccent": false }
}
```

### Поля и типы

| Поле | Тип / диапазон | Обяз. | Правило валидации |
|---|---|---|---|
| `id` | строка, вид `songId\|lang\|lineIndex` или `…\|s-e` | да | строится детерминированно; **дедуп по `id`** — повторный тап того же выражения открывает карточку текущей отметки, дубль не создаётся |
| `songId` | строка, `^[A-Za-z0-9_-]{5,16}$` (videoId 11 симв.) | да | должен присутствовать в каталоге фонда либо быть честно помечен «вне каталога» |
| `lang` | строка ≤ 8, ключ `__LANGS` | да | мимо списка языков дома → отметка хранится, подсветка честно не применяется |
| `lineIndex` | целое 0…3999 | да | при показе сверяется с текущей длиной оси; вне оси → честная пометка «строка вне оси», не подсвечиваем |
| `wordRange` | `{s: int ≥0, e: int > s}` ≤ 40 слов, или отсутствует | нет | полуоткрытый диапазон по словам строки языка `lang` |
| `quote` | строка ≤ 160 символов UTF-8 | нет | снимается с DOM (.txt/.sub) в момент отметки |
| `ts` | ISO 8601 UTC (`YYYY-MM-DDTHH:MM:SS.mmmZ`) | да | битая дата → запись отбрасывается при импорте |
| `status` | `"understood"` \| `"return"` | да | прочее значение → отказ записи (при импорте — пропуск с честным счётом) |
| `times` | целое ≥ 0 | нет | зарезервировано Этапом 2; v1 не пишет |
| `returnEnabled`, `hapticAccent` | boolean | нет | `hapticAccent` в Этапе 1 всегда `false` (вибро-акцент — Этап 3) |

### Лимиты

- **Не более 500 отметок** в доке (~75 КБ верхним пределом — безопасно для localStorage и для IDB). При попытке 501-й — честный тост «список полон — удалите лишнее», **никакого авто-выбрасывания** (дом не врёт и не теряет молча).
- Длина дока контролируется уже существующей пробой ЗДОРОВЬЕ памяти (запись→чтение→сверка, стр. 5219).

## 4. Хранилище — что выбрано и почему

**Механизм: `window.__СКЛАД.читай("s31.zhkontur.v1", дефолт)` / `__СКЛАД.пиши("s31.zhkontur.v1", док)`** (стр. 10988, 10992). Фолбэк, если СКЛАД не встал (старый байт/приватный режим): прямой `localStorage` того же ключа — дом живёт на доме, честно, как это уже делает СКЛАД («Фолбэк честный: IDB недоступен… — всё работает как раньше на localStorage», 10796).

Почему:
1. **С32** (комплект 06 и код зала): «Новые заметки и учебные метки подключаются к существующей памяти. Не заводится вторая система хранения» — СКЛАД и есть существующая память настроек (ЕДИНЫЙ ДОК v2, миграции, ЗДОРОВЬЕ-проба).
2. СКЛАД пишет сквозь оба места — дом `s31.prefs.v2` (синхронный старт) + IDB `prefs` (долговечно) — **удаление реально удаляет из обоих** (`докСохрани`, 10926–10929).
3. IDB-библиотека СКЛАДА — для больших данных (переводы, аккорды); отметки малы — им место в доке, рядом с настройками (буквально по ТЗ: «хранится локально рядом с существующими переводами и настройками», 03 §3.3).
4. Против хранения в ключе-родственнике `sng31.malish.v2` (память МАЛЫША): не смешивать — у МАЛЫША свой закон (I-01, сырьё/ревизия), у отметок — свой; у обоих один хозяин-док.
5. Профиль доступности — отдельная сущность (`kv.harmprofile`/оси живых рулей), учебный слой её **читает** (`__ПРОФИЛЬ.получи("haptic"/"motion"/"output")`), но никогда не пишет.

## 5. Правила жизненного цикла

**Добавление.** Тап → карточка → «Понял»/«Хочу вернуться» → сбор полей из DOM/оси (`dataset.i`, `dataset.lang`, спаны `.tk` для `wordRange`) → дедуп по `id` → вставка → `__СКЛАД.пиши`. Отметка не требует сети и не ждёт ничего асинхронного.

**Удаление (реальное).**
- Одна отметка: `отметки.splice(idx,1)` → `__СКЛАД.пиши` — док перезаписывается и в доме, и в IDB (put поверх ключа дока) — записи больше нет нигде.
- «Забыть всё»: `__СКЛАД.пиши("s31.zhkontur.v1", {v:1, отметки:[], настройки:…})` + прямой `localStorage.removeItem("s31.zhkontur.v1")` для чистоты — по образцу честного забывания МАЛЫША (`localStorage.removeItem(МАЛЫШ_КЛЮЧ)`, стр. 3014).
- Никаких «мягких» удалений, корзин и флагов `deleted` — ТЗ: «Удаление реально удаляет данные».

**Экспорт (только по явному действию).** Кнопка в ПУЛЬТ → ДАННЫЕ (рядом с экспортом настроек `exportPrefs`, 4340). Файл `zh-kontur-YYYY-MM-DD.json`:

```json
{ "schema": "zh-kontur/v1", "exported": "2026-10-12T15:00:00.000Z", "отметки": [ … ], "настройки": { … } }
```

Механика — как у дома: `Blob` + `URL.createObjectURL` + `a.download` (экспорт настроек exportPrefs, 4340–4356). Наружу едут только отметки и настройки — ничего служебного.

**Импорт (только по явному действию).** FileReader → JSON-гард (по образцу `importPrefs` 4356+ и `__ПРОФИЛЬ.импорт`, 12124): 
- `schema` отсутствует/новее v1 → **честный отказ** (правило дома: «формат новее дома — честный отказ», импорт профиля 12124);
- каждая запись валидируется по таблице §3 (songId-паттерн, ts-regex, status-enum, клампа wordRange/lineIndex), битые пропускаются с честным счётом «принято N, отброшено M»;
- merge по `id` (существующее — остаётся как в доме, чужое добавляется), лимит 500 соблюдается.

**Приватность (границы).**
- **0 сети**: ни `fetch`, ни XHR, ни телеметрии — контур не имеет сетевого кода вообще (у зала есть свой сетевой АВТО-ПЕРЕВОД — стр. 10455 — контур его не трогает и не использует).
- Отметки не покидают устройство, кроме явного экспорта файлом руками человека.
- Приватный режим браузера: хранилище может не писать — контур работает в памяти сеанса и честно говорит об этом, как уже делает проба памяти дома (2069: «Память настроек не пишет: приватный режим или переполнение. Вечер работает…»).

## 7. Совместимость с примером комплекта (07 §3)

Поле за полем: `lineIndex` — совпадает; `wordStart/wordEnd` → `wordRange {s,e}` (та же семантика, компактнее); `text` → `quote` (роль честной сверки); `status:"want_return"` → `"return"` (маппинг при импорте, обратная совместимость); `createdAt` → `ts`; `lastSeenAt/timesReturned` → зарезервированы (Этап 2); `settings.showBoth` → не нужна (режим «Оба» в доме уже всегда включён — три строки подачи); `songId` — уточнён до videoId каталога фонда. Миграций внутри v1 нет; будущие изменения — только добавлением `v:2` и функцией миграции в доке (цепочка миграций СКЛАДа, 10903–10920).
