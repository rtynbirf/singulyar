## 1 · KARAOKE-SYNC-SINGULARITY-2026 — энциклопедия синхронизации (11 документов, раздел 1.1–1.10)

Система: **полная ручная + автоматическая синхронизация текста караоке с моментом оригинального вокала**; принцип эмерджентности — AI-автоматизация и ручная точность в симбиозе; покрывает ВСЕ сценарии одновременно (мобильный / десктоп / полностью локальный / максимальная точность).

### 1.1 ТЗ (`01_TECHNICAL_SPECIFICATION_TZ.md`) — полное

- **Назначение:** синхронизация визуальных меток (буква/слог/слово/строка) с временной позицией оригинального вокала.
- **Область:** домашнее караоке; профессиональные бары и студии; контент (YouTube/TikTok/Instagram); обучение вокалу; локальные офлайн-системы; мобильные и десктопные устройства.
- **Must Have:** (2.1.1) разделение вокала/инструментала; word-level и syllable-level таймстампы; несколько AI-моделей (Audioshake, WhisperX, MusicAI, Demucs+WhisperX); выбор модели под жанр и язык. (2.1.2) визуальный timeline с waveform; drag & drop слов; resize handles; точный ввод в мс; глобальный offset; секционный сдвиг (куплет/припев); Split/Merge строк и слов; preview + loop + замедление. (2.1.3) уровни: line / word / syllable / character (опц.). (2.1.4) вход: MP3, WAV, FLAC, M4A, YouTube URL, LRC / Enhanced LRC / SRT / ASS / KFN; выход: Enhanced LRC, Standard LRC, SRT, WebVTT, ASS, JSON (word-level), CD+G. (2.1.5) кроссплатформенность: iOS/Android, Windows/macOS/Linux, Web, полностью локальный режим.
- **Should Have:** автодетект BPM и сетки долей; фонетическая разметка; дуэты (цвета вокалистов); batch-обработка; Undo/Redo 50+ уровней; горячие клавиши; экспорт караоке-видео с анимацией текста.
- **Could Have:** real-time pitch detection живого голоса (оценка); интеграция с аппаратными караоке-машинами (Ikarao, Singing Machine); облачная синхронизация проектов; совместное редактирование.
- **Нефункциональные:** точность word-level ≤ 50–80 мс (ручная доводка до 10–20 мс); AI-синхронизация 3–4 мин песни ≤ 90–120 с; отзывчивость редактора ≤ 16 мс; новичок получает приемлемый результат ≤ 10 мин; профессионал — полный контроль; приватность — локальный режим обязателен, работа без отправки аудио в облако.
- **Ограничения:** качество исходного аудио критично; точный текст песни повышает точность; экстремальный метал / быстрый рэп / сильный акцент требуют ручной работы.
- **Критерии приёмки:** (1) любая песня → word-level разметка; (2) ручное исправление любого слова с точностью до 50 мс; (3) экспорт в Enhanced LRC корректно играет в стандартных плеерах; (4) все сценарии покрыты без взаимного исключения.

### 1.2 Дорожная карта этапов 0–6 (`02_ROADMAP_DETAILED.md`) — полная

- **Этап 0 Подготовка:** приоритет сценария (помня, что все поддерживаются); качественное аудио (lossless или MP3 320); точный текст с прописанными повторами; выбор инструмента (макс. удобство → Youka; мобильный → Karaoke Sync; локальный+контроль → ELYSY; гибрид → комбинация).
- **Этап 1 Автосинхронизация:** загрузка аудио+текста; выбор модели (англ. поп/рок → Audioshake Alignment; неанглийский/сложный вокал → WhisperX/MusicAI; локальный → Demucs+WhisperX (ELYSY)); прогон 30–120 с; предварительное прослушивание.
- **Этап 2 Грубая ручная коррекция:** waveform на 1.0x; исправление уехавших строк, пропусков/лишних слов, границ секций; глобальный offset при систематическом сдвиге; промежуточное сохранение.
- **Этап 3 Точная доводка (word/syllable):** работа по секциям (куплет → припев → бридж); на каждое слово: выделить, loop + замедление 0.5–0.75x, подтянуть начало/конец по waveform и на слух, проверить совпадение с атакой согласной/гласной; особое внимание — быстрые пассажи и рэп, растянутые ноты, дыхания и паузы, бэк-вокал (решить, подсвечивать); проверить стыки строк без наложений и дыр.
- **Этап 4 Финальная валидация:** прослушать на 1.0x, 1.25x и 0.75x (выявляет скрытые ошибки); проверить на разных устройствах (телефон, большой экран, проектор); экспорт в Enhanced LRC; тест в целевом плеере/машине.
- **Этап 5 Экспорт и интеграция:** Enhanced LRC (основной), Standard LRC (совместимость), SRT/WebVTT (видео); аппаратные системы — Ikarao + KaraFun (Community или внешний файл), Singing Machine (USB/приложение), YouTube/локальные плееры; резервная копия проекта.
- **Этап 6 Оптимизация и повторяемость:** шаблоны настроек под жанры; документирование особенностей сложных песен; стандартизация naming и структуры папок при batch.
- **Временные ориентиры:** простая поп-песня (AI + лёгкая правка) 8–15 мин; средняя сложность 20–40 мин; сложная (быстрый рэп, нестандартный вокал, многослойность) 45–90 мин; профессиональный студийный уровень 1,5–3 часа.
- **Критерии готовности песни:** подсветка начинается в момент атаки звука (±50 мс); длительность подсветки = реальной длительности пения; нет визуальных «прыжков» и наложений; текст читается на большом экране; при пении вживую метка ощущается естественной, не «убегающей» и не «отстающей».

### 1.3 Workflows A–E без исключений (`03_WORKFLOWS_ALL_SCENARIOS.md`)

- **A. Мобильный (iOS/Android) — Karaoke Sync:** установить; импорт песни (файл/YouTube); вставить точный текст построчно; Timing → Start Timing — тапать в начале каждой строки; режим Words; перетащить непопавшие слова; Fine-tune (±0,1 с), Loop, 0.5x; экспорт Enhanced LRC; при необходимости — перенос на десктоп для финальной доводки. Плюс: можно делать везде. Минус: менее удобный waveform.
- **B. Десктоп — Youka (макс. удобство):** проект → аудио или YouTube-ссылка; точный текст с повторами; выбор sync-модели (Audioshake Alignment для английского); AI-синхронизация; Manual Sync: word blocks + waveform; drag/resize/точный ввод; split/merge/shift lines; Preview → Export (видео или lyrics-файлы). Альтернатива: LyricTime (чистый lyrics-editor без видео).
- **C. Полностью локальный (privacy + offline) — ELYSY (или KarLyricEditor + локальные модели):** установить (MIT, локальный); Demucs → чистый вокал; WhisperX → word-level таймстампы; matcher для выравнивания под точный текст; встроенный редактор: кнопки ±0,1/±0,3 с, мультивыбор + batch shift, 50 уровней Undo; экспорт eLRC/SRT; всё хранится локально. Самый безопасный и контролируемый путь.
- **D. Максимальная точность (студия) — гибридный pipeline:** локально Demucs+WhisperX (ELYSY) → черновая word-level разметка; импорт в Youka/профредактор; ручная доводка на большом мониторе с хорошими наушниками; работа по секциям с loop + 0.5x; проверка на нескольких устройствах; финальный экспорт в несколько форматов (eLRC + SRT + видео); архивирование с исходниками. Дополнительно: фонетическая транскрипция; атака согласных vs гласных; компенсация latency конкретной караоке-машины; отдельные offset-версии под экраны (телефон/ТВ/проектор).
- **E. Гибридный (рекомендуемый универсальный):** черновая работа на мобильном в дороге; основная доводка на десктопе; критичные песни — финальная проверка через ELYSY; мастер-файлы в Enhanced LRC + исходный проект. Объединяет преимущества всех и ничего не исключает.

### 1.5 Лучшие практики и алгоритмы (`05_BEST_PRACTICES_AND_ALGORITHMS.md`) — 7 блоков

1. **Алгоритм идеальной подсветки:** старт в момент атаки звука; гласные — ближе к началу звучания; согласные (особенно взрывные) — точно на атаку; длительность подсветки = реальная длительность пения + «хвост» 20–40 мс для комфорта.
2. **Правило 50–80 мс:** комфорт восприятия — ошибка ≤ 80 мс; профессиональный уровень ≤ 40–50 мс.
3. **Паузы и дыхания:** короткие (< 300 мс) обычно не выделяют строкой; длинные — отдельной «пустой» зоной или разрывом строк.
4. **Повторяющиеся припевы:** всегда прописывать полностью, никогда «×2»/«repeat».
5. **Бэк-вокал:** решение индивидуально — подсвечивать основной или отдельные цвета (если система поддерживает).
6. **Жанровые особенности:** поп/баллады — относительно легко; рэп/хип-хоп — syllable-level и очень точная ручная работа; рок/метал — сильная реверберация, сложнее для AI; опера/классика — крайне сложные растяжки.
7. **Алгоритм проверки:** 1.0x → 0.75x → 1.25x → большой экран → проверка «вживую» с микрофоном.

### 1.6 Руководство по внедрению (`06_IMPLEMENTATION_GUIDE.md`) — 4 профиля

Домашний пользователь: Karaoke Sync (мобильный) + Youka (десктоп), хранить eLRC, использовать с Ikarao/Singing Machine/YouTube. Контент-мейкер: Youka основной, экспорт видео + eLRC, batch через API (если доступно). Караоке-бар/студия: локальный сервер с ELYSY + библиотека eLRC, резервное копирование, стандартизация форматов. Максимальная приватность: только ELYSY + локальные модели, никакого облака.

### 1.7 Форматы файлов и стандарты (`07_FILE_FORMATS_AND_STANDARDS.md`)

Enhanced LRC — рекомендуемый основной (`[00:12.34]<00:12.34>Never <00:12.80>gonna…`); Standard LRC (`[00:12.34]Never gonna give you up`); SRT/WebVTT — для видео; ASS — продвинутое оформление; JSON word-level — для собственных плееров; CD+G — устаревающий, но ещё встречается. **Рекомендация: мастер-версия всегда в Enhanced LRC + исходный проект инструмента.**

### 1.8 Продвинутые техники (`08_ADVANCED_TECHNIQUES.md`) — 6 техник

Компенсация latency конкретной караоке-машины; разные offset-версии под разные экраны; фонетическая разметка для сложных языков; работа с полифоническим вокалом; BPM-сетка для выравнивания; «предвосхищающая» подсветка — текст появляется на 100–200 мс раньше звука.

### 1.9 Решение проблем и крайние случаи (`09_TROUBLESHOOTING_AND_EDGE_CASES.md`) — 5 пар

AI сильно ошибается → дать максимально точный текст + попробовать другую модель + ручная доводка. Быстрый рэп → syllable-level + работа на 0.5x + loop каждого слова. Сильная реверберация → предварительное разделение вокала (Demucs), работа по чистому вокалу. Разные версии песни → синхронизировать именно с той версией, которая будет играть. Latency Bluetooth/HDMI → глобальный отрицательный offset.

### 1.10 Тренды и развитие 2026–2028 (`10_FUTURE_TRENDS_2026_2028.md`) — 6 трендов

Полностью real-time AI-синхронизация на устройстве; интеграция с аппаратными караоке-машинами на уровне API; многоязычная фонетическая подсветка; адаптивная подсветка под темп живого исполнения; генеративные модели, создающие идеальный karaoke track из любой песни за секунды; стандартизация Enhanced LRC 2.0 с syllable и character level.

## 2 · СИНГУЛЯР · ПУЛЬС-СИНХРОН v1.0 — интеграционная спецификация (7 документов)

Название интеграции: **СИНГУЛЯР · ПУЛЬС-СИНХРОН v1.0**. Цель: встроить эмерджентный прототип точной синхронизации текста (слово/слог/буква) в архитектуру СИНГУЛЯРА без нарушения инвариантов дома. Прототип усиливает существующий «Текст-пульс» зала ·31 (режимы СТРОКА/СЛОВО/СЛОГ/БУКВА, движение указателя в такт музыке, точная синхронизация заявлена для «Просто люби»).

### 2.1 Что даёт интеграция и что обязано сохраниться

Сохранить ключевые принципы СИНГУЛЯРА: 100% офлайн; один файл = вся платформа (или модуль); человек первый (override всегда выигрывает); ноль внешних сетевых запросов в runtime; текст-пульс уже существует (слово/слог/буква); доступность (одна кнопка, вибро, озвучка, высокий контраст); суверенитет данных. Даёт: ручную и полуавтоматическую точную подстройку таймингов; Enhanced LRC / word-level / syllable-level; инструменты создания и правки синхрона для новых песен фонда; сохранение полной автономности.

### 2.2 Архитектурный fit (`01_ARCHITECTURE_FIT.md`)

- **Место в доме:** основная точка интеграции — дверь ·31 ЛАДОМ (караоке-зал «пространство своих»); вторичные — ·32 СЦЕНА (полные тексты), ·16 СУФЛЁР, ·20 ФОНЕТИКА; новый модуль предлагается как **·43 ПУЛЬС-СИНХРОН** (или расширение существующего Текст-пульса).

### 2.3 Спецификация модуля ·43 ПУЛЬС-СИНХРОН (`02_MODULE_SPEC_ПУЛЬС_СИНХРОН.md`)

- **Паспорт:** название ПУЛЬС-СИНХРОН; код двери (предложение) **·43**; версия 1.0.0; зависимости — Текст-пульс ·31, СУФЛЁР ·16 (опц.), ФОНЕТИКА ·20.
- **Назначение:** загружать/создавать точные тайминги (word/syllable/letter); редактировать вручную с визуальной точностью; экспортировать в формат, понятный Текст-пульсу ЛАДОМ; делать это полностью офлайн.
- **Режимы:** (2.1) просмотр существующего синхрона; (2.2) создание нового (черновик → ручная доводка); (2.3) правка существующего; (2.4) экспорт/импорт Enhanced LRC.
- **Интерфейс (Human-First):** Timeline + waveform (если доступен AudioContext); блоки слов, которые можно тянуть; кнопки **±0,05 / ±0,1 / ±0,3 с**; режим одной кнопки (сканирование + Пробел); озвучка текущей позиции; высокий контраст; сохранение состояния в IndexedDB.
- **Алгоритм работы:** человек загружает минусовку + текст (или выбирает из фонда) → система предлагает черновик (заранее подготовленный или простой line-level) → человек входит в редактор → правит word/syllable блоки → сохраняет → Текст-пульс ·31 начинает использовать новый синхрон.
- **Контракт с Текст-пульсом:** модуль отдаёт массив `{ text, startMs, endMs, level: "word"|"syllable"|"letter" }` или Enhanced LRC строку; Текст-пульс обязан принять более точный синхрон, если он есть, и упасть на более грубый уровень, если точного нет.

### 2.4 Дорожная карта внедрения по тактам (`03_ROADMAP_INTEGRATION.md`)

- **ТАКТ 0 Подготовка:** зафиксировать инварианты; согласовать формат данных с существующим Текст-пульсом; создать спецификацию модуля.

### 2.5 Технический контракт (`04_TECHNICAL_CONTRACT.md`)

```ts
interface SyncUnit {
  text: string;
  startMs: number;
  endMs: number;
  level: "line" | "word" | "syllable" | "letter";
  optional?: { confidence?: number; source?: "human" | "ai" | "hybrid"; }
}
interface SongSync {
  songId: string;
  version: string;
  units: SyncUnit[];
  globalOffsetMs?: number;
  created: string;
  modified: string;
}
```
- **Хранение:** IndexedDB (ключ songId + version); экспорт в файл (Enhanced LRC); возможность вшития в статический HTML (полностью офлайн-дистрибуция).
- **API модуля (внутренний):** `loadSync(songId)`; `saveSync(songId, data)`; `applyToPulse(songId)` (сообщает Текст-пульсу использовать этот синхрон); `exportEnhancedLRC(songId)`; `importEnhancedLRC(file)`.
- **Fallback-цепочка:** letter → syllable → word → line → plain text; человек всегда может принудительно выбрать уровень.

### 2.7 Совместимость и fallback (`06_COMPATIBILITY_AND_FALLBACK.md`)

Старые песни без точного синхрона работают как раньше (line-level или существующий механизм); новые точные синхроны Текст-пульс использует автоматически (более высокий уровень детализации); устройство без AudioContext/слабое — редактор деградирует до простого списка с ± кнопками (без waveform); режим одной кнопки полностью поддерживается (сканирование блоков + Пробел = выбрать/править); полностью офлайн — все данные локальные, никаких CDN и внешних API.

### 3.1 API полностью — 9 разделов

1. **Время и форматы тегов:** `msТег(ms, цифр)` — `mm:ss.xx` (цифр=2, как в LRC) или `mm:ss.xxx` (цифр=3); `msЧЧ(ms, запятая)` — `hh:mm:ss.mmm` (TTML/WebVTT; для SRT разделитель — запятая); `тегMs(т)` — разбор `'12:34.56' | '1:02:03.456' | '12:34'` → мс, не тег → `null`.
2. **Слова и слоги:** `слова(т)` — разбивка по пробелам; `норм(т)` — нижний регистр, ё→е, только буквы/цифры; `слоги(слово)` — приближённый слоговой разбор латиницы/кириллицы (правило Живого Контура v10.79: одна согласная — к следующей гласной, пара и больше — режем между юнитами, ь/ъ/й клеятся к своей согласной); для не-буквенных (CJK, цифры) — честно пустой ответ; `слогиИсх(слово, внешние)` — с сохранением регистра и дефисов; `вес(слово)` = max(1, число слогов) + 0.5 за хвостовую пунктуацию.
3. **Модель (черновик → SongSync):** `черновик(л)` — эвристика: время строки делится между словами пропорционально слоговым весам, помечается `src='draft'` (это НЕ измерение, а догадка); `изПесни(песня, опц)` — превращает `window.SONG` хоста (секунды → мс) в объект модели; **ось строк не меняется: правило «window.SONG.cues не трогаем»**; `клон(o)`; `История(макс)` — стек отмен/повторов (`поставь/отмена/повтор/можноОтмену/можноПовтор/глубина`).
4. **Правки (все на копии):** `двигатьСтарт` / `двигатьКонец` — с зажимом соседей (мин. 20 мс), пометка `src='human'`; `сдвинутьСтроку` / `сдвинутьДиапазон` / `сдвинутьВсё` — сдвиг по времени; `подтвердить` — «человек коснулся»; `слить` / `разделить` — склейка/разбиение слов.
5. **Валидатор `проверить(s)`:** честные метрики — ошибки (перекрытия, слишком короткие/длинные слова, вылет за окно строки ±500 мс, дыра > 2000 мс внутри строки) + предупреждения + статистика: единиц / человек / ии / импорт / черновик / **подтверждено_процент** (доля ручной проверки, НЕ точность).
6. **Форматы (экспорт/импорт):** `вLRC` (только строки); `вELRC`/`изELRC` — Enhanced LRC со словами `<mm:ss.xx>слово`, метаданные `[ti:…]`/`[re:…]`; `вSRT`, `вVTT`, `вTTML`; `вJSON`/`изJSON` — сериализация; `вHarm(s, опц, внешниеСлоги)` — формат `harm/0.1` для дома: веса слогов в долях от BPM; **по умолчанию берёт только строки без черновика — чтобы не тащить эвристику в честные данные** (опция `вклЧерновик` включает).
7. **Выравнивание ASR → текст:** `нормализоватьASR(j)` — принимает диалекты WhisperX (`word_segments`), faster-whisper/`segments[].words[]`, transformers.js (`chunks`), плоский список → `[{w,s,e}]` в мс; `выровнять(s, asr, {порог:0.6})` — глобальное выравнивание **Нидлмана–Вунша** (порядок слов сохраняется, припевы не слипаются); совпавшие получают время ASR (`src='ai'`), несовпавшие — интерполяция (`src='draft'`); вход не мутируется; `сравнить(A, B)` — «насколько A отличается от эталона B»: среднее/медиана/p90 расхождений в мс, доля в 50 и 80 мс; `сходство(a,b)` — через Левенштейна.
8. **FSRS-6 (память):** `FSRS(w, удержание)` — 21 параметр `W6` open-spaced-repetition; кривая забывания `R(t,S) = (1+factor·t/S)^(-decay)`; `интервал(S, r)` — дни до порога удержания; `S0(G)`, `D0(G)`, `Dновая`, `Sвспомнил`, `Sзабыл` (со стражем `min(·,S)` — авторское дополнение, помечено), `Sтотже`; `новая(id)`, `оценить(к, G, сейчас)` (оценки 1–4), `готовность(к, сейчас)`, `предпросмотр(к, сейчас)` (4 оценки → интервалы), `подпись(дни)` («1 мин», «3 дн», «2 мес»).
9. **Тренажёры:** `диктант(эталон, ответ)` — выравнивание слов по Левенштейну → ошибки заменено/пропущено/лишнее, флаг `точно`; `пропуски(units, правило)` — какие слова скрыть: `{каждое:k}` / `{отмеченные:Set}` / `{случайные:n, зерно}` (детерминизм по зерну); `эхоПлан(s, i0, i1, коэф)` — расписание «слушай строку → твоя очередь» (играть [a,b], пауза = длительность строки × коэф).

### 5.5 Архитектура и ADR

- **Инвариант:** ·31 остаётся локальным караоке-ядром; сетевой режим — добавочный адаптер; отключение сети/сбой сервера не ломают локальное воспроизведение, пульт, текст-пульс, доступность, запись, сцены.
- **Место в экосистеме:** ·31 интерфейс вечера; ·18 СОБЫТИЕ — модель комнаты/присутствия (в v0.2 временная комната на сервере, каноническая интеграция — следующий шаг); ·19 ЧЕЛОВЕК — будущая идентичность и отношения (нет аккаунтов/друзей); ·21 ОБЩЕНИЕ — будущая маршрутизация смысла (текстовый мост — временный адаптер); ·22 СВЯЗЬ — канонический транспорт (WebRTC/WebSocket — интеграционный адаптер, перевести на контракты ·22); ·30 ТКАНЬ — манифесты событий и согласование возможностей.
- **Поток v0.2:** `ЛАДОМ UI → WebSocket signalling → offer/answer/ICE → WebRTC audio peer-to-peer`; текст `UI → WebSocket server → второй участник`; озвучивание `текст → SpeechSynthesis → локальный звук`. **Нет** `ASR → translation → singing alignment → singing voice generation`; выбранные языки сообщают намерение, не запускают фиктивный перевод.
- **Поток целевой версии:** `исходный вокал + временные метки → singing ASR → варианты перевода → слоговое/нотное выравнивание → генерация певческого голоса → проверка качества → персональная дорожка получателя`; каждый адаптер версионируется (контракт входа/выхода, языковая пара, лицензия, правила хранения, confidence, тесты); низкая уверенность → `UNKNOWN` или исходный звук.
- **Ограничения v0.2:** комнаты в памяти, максимум два участника; STUN для демонстрации, TURN не настроен; нет E2E прикладного шифрования — сервер видит текст; WebRTC-аудио защищается механизмами WebRTC, но модель угроз проверяется отдельно; короткий пользовательский код комнаты; установщик патчит одной ссылкой с backup — проверяйте diff до commit.

- **Исследовательские основания (ссылки проверены 2026-10-13):** MDN WebRTC API / RTCPeerConnection / getUserMedia; MDN Web Speech API (SpeechSynthesis озвучивает текст, не превращает в пение); Meta Seamless (потоковый многоязычный S2ST существует — не доказывает качество перевода певческого голоса с сохранением мелодии и тембра pt-BR ↔ ja-JP). Вывод: разделить распознавание спетого текста, перевод смысла, согласование слогов/нот, генерацию вокала; измерять каждый этап отдельно; языковая опция UI ≠ поддержка языка моделью.

## 6 · Singulyar Universal Karaoke — прототип v0.1 (pt-BR ↔ ja-JP)

**Назначение:** технический стартовый комплект для совместного караоке между людьми, говорящими на разных языках. Центральный сценарий: участник в Бразилии поёт по-португальски в телефон; участник в Японии поёт по-японски; каждый слышит партнёра и получает его перевод на своём языке. **Прототип НЕ переводит живое пение в реальном времени и не превращает голос бразильца в его же голос, поющий по-японски** — намеренное инженерное разделение: рабочая передача звука проверяется отдельно от ещё не подключённого переводчика.

### 6.1 Что реально реализовано в архиве

Веб-интерфейс на русском с выбором языков участников; создание/вход в комнату по короткому коду; передача живого микрофонного аудио между двумя браузерами через WebRTC; WebSocket-сигналинг на собственном сервере (`src/server.js`, HTTP-статика + `/signal`); текстовый канал; демонстрационный караоке-пульт (текст оригинала, поле перевода, синтез речи браузером при наличии голоса языка); словарь-демо `src/phrasebook.js` (показ потока «исходная фраза → перевод → озвучивание», помечен демонстрационным); документация (архитектура, ТЗ, roadmap, тестирование, безопасность, исследования, ADR, критерии приёмки). Быстрый запуск: Node 20+, `npm install`, `npm start`, `http://localhost:8080` в двух окнах («Бразилия» pt-BR → ja-JP «Создать комнату»; «Япония» ja-JP → pt-BR «Подключиться» по коду); микрофон требует HTTPS или localhost; для двух физических телефонов в разных странах — сервер по HTTPS/WSS в интернете.

### 6.2 Сценарии, требования, критерии

- **US-01..US-07:** создать комнату (имя + языки + код, статус соединения); присоединиться (два участника); передать живой звук после явного разрешения микрофона; отправить текст (в будущем — через реальный адаптер); проверить TTS-озвучивание переведённой строки (отсутствие голоса языка — понятно обозначено); караоке-строка (оригинал + перевод; в целевой версии — синхронизация с музыкальными метками); остановить и выйти (микрофон off, WebRTC закрыт, выход из комнаты).
- **FR-01..FR-18:** телефон и компьютер; видимость и смена языков; код комнаты; сервер отклоняет третьего; микрофон только после действия пользователя; понятная ошибка при отказе доступа; звук WebRTC + сигналинг WebSocket; потеря связи в статусе; ограничение длины сообщений; демо-словарь маркирован; TTS по выбранному языку и доступному голосу; остановка синтеза; интерфейс не объявляет перевод живого пения, пока модуль не подключён; клавиатура и текстовые подписи; без постоянного хранения разговоров; замена переводчика без переписывания комнаты и UI; различение исходного аудио / распознанного текста / перевода / сгенерированного аудио в модели данных; подтверждение при неизвестном языке или низкой уверенности.
- **NFR-01..NFR-10:** мобильная компоновка от 320 CSS px; доступность (клавиатура, фокус, контраст, screen reader); приватность по умолчанию (без скрытого сохранения аудио); безопасность (HTTPS/WSS, проверка сообщений, лимиты, защита от перебора кодов); надёжность переподключения без дублей аудиодорожек; диагностические данные без содержания аудио/текста без согласия; версия и измеримые показатели каждого модуля; реестр возможностей языковых пар; без обещаний нулевой задержки и идеального тембра; видимая и обратимая деградация.
- **Критерии приёмки прототипа:** два клиента в комнате по коду; третий — отказ; звук в обе стороны в поддерживаемой сети; текст в обе стороны; демо-фразы корректны только для известных пар; TTS при наличии системного голоса; отключение микрофона останавливает отправку; выход отображается у другого; в интерфейсе явно указано, что живой перевод пения не реализован; `npm run check` без синтаксических ошибок.
- **Вне объёма v0.1:** реальный нейросетевой перевод; перевод пения в пение с сохранением голоса; синхронизация нот/слогов с оригиналом; многопользовательский хор; аккаунты, друзья, постоянные отношения, синхронизация устройств; запись и долговременное хранение; нативные мобильные приложения; гарантированная работа через все NAT без TURN.

### 6.3 Архитектура и модульные интерфейсы

Компоненты: Web UI (`index.html`, 19 287 Б) → сигналинг (`src/server.js`, 4 376 Б) → WebRTC (прямая передача аудио, сигналинг не передаёт медиа) → Speech Synthesis (системный, если поддерживает язык) → демонстрационный словарь (не машинный перевод) → будущие адаптеры. Целевая архитектура переводчика: `Микрофон/микс → Audio capture + timestamps → Voice/source separation (опц.) → Singing ASR + confidence → Text/phoneme/note alignment → Translation candidates → Syllable + prosody + note fitting → Singing voice conversion / synthesis → Quality gate + provenance labels → Remote playback + karaoke captions` — каждый модуль с интерфейсом, версией, языковой парой, форматами, тайм-аутом, уверенностью, метриками. **Ключевое решение:** не решать одним непрозрачным вызовом; сначала измеримые отдельные результаты: распознавание спетого вокала; перевод смысла; пригодность перевода к пению; сохранение мелодии и голоса; задержка и устойчивость. Данные: `sessionId`, `participantId`, `sequence`, `captureTime` (монотонная), `sourceLanguage` (BCP-47), `mediaKind` (`original-audio` / `translated-audio` / `text` / `karaoke-cue`), `confidence`, `modelId`/`modelVersion`, `retention`; без содержания песни/голоса в диагностике без согласия. Адаптеры: `ASRAdapter` (аудиофрагмент, язык/auto, метаданные времени → текст, таймстампы слов, confidence, модель/версия); `TranslationAdapter` (текст, исходный/целевой язык, контекст песни → несколько кандидатов, неоднозначность, confidence или UNKNOWN); `SingingAlignmentAdapter` (вокал/фонограмма, текст и/или MIDI/ноты → тайминг слов/слогов/нот + уверенность); `VocalGenerationAdapter` (перевод, фонетическая/слоговая разметка, мелодический таймлайн, разрешённый профиль голоса → аудио + отчёт об ограничениях; **чужой голос без отдельного явного согласия запрещён**); `QualityGate` (язык, пропуски, артефакты, превышение задержки, обязательные метаданные; может отклонить и вернуть исходный вокал/текст); `TransportAdapter` (дорожки с идентификаторами, sequence number, таймстампами; учёт задержки и джиттера). Ограничения сервера: временные комнаты в памяти; максимум два; нет аккаунтов/очередей/БД/rate limiting/TURN; короткий код не защита для чувствительных разговоров; нет TLS локально; перед публичным запуском — reverse proxy HTTPS/WSS, TURN, лимиты, модель авторизации.

### 6.4 Фазы 0–6 + ворота G0–G6 (сроки — ориентиры, не гарантии)

Фаза 0 запустить и проверить (1–3 дня): Node 20+, ручные тесты TEST_PLAN, браузеры и мобильные, дефекты и результаты → воспроизводимый стенд, ограничения, протокол. Фаза 1 безопасная базовая связь (1–2 недели): HTTPS/WSS, TURN и проверка NAT, случайные id комнат с энтропией, лимит попыток и срок жизни, переподключение, аудит сигналинга → устойчивый двухсторонний аудиоканал для пилотной группы. Фаза 2 настоящий перевод разговорной речи (2–6 недель после выбора модели): сравнить ≥2 ASR/S2ST для pt-BR ↔ ja-JP; политика хранения, место обработки, лицензия; `ASRAdapter` + `TranslationAdapter`; исходник/перевод/уверенность/исправление; испытания с реальными говорящими и акцентами → измеримый перевод речи (не пения). Фаза 3 караоке-текст (2–4 недели): законный набор песен; тайминг строк и слогов без копирования защищённых текстов; редактор сопоставления оригинала и перевода; проверка слогов, ударений, длительности фраз; синхронный показ → читать и петь перевод поверх фонограммы. Фаза 4 исследование перевода певческого голоса (4–12+ недель): разрешённые записи pt-BR/ja-JP; singing-ASR отдельно от обычного; сравнение разделения источников и SVC; выравнивание слогов с нотами и сохранение тембра; слепое прослушивание носителями обоих языков; каждая комбинация модель/язык/жанр отдельно → экспериментальный отчёт с ограничениями, ошибками, GO/NO-GO. Фаза 5 частная бета: согласие на обработку голоса, индикатор режима, удаление временных аудиоданных, доступность (субтитры, без рук), независимый review `CLAIM → CODE → OFFICIAL SPEC → TEST → VERDICT` → ограниченная бета с опубликованными возможностями и дефектами. Фаза 6 продуктовая готовность: нагрузочные и сетевые тесты, независимый security/privacy review, план реагирования на инциденты, совместимость версий клиента, лицензионный аудит моделей/данных/музыки, метрики без скрытого сбора → решение о выпуске на доказательствах. Ворота: **G0** локальный прототип стартует; **G1** двусторонний WebRTC на реальных сетях; **G2** перевод разговорной речи измерен для обеих сторон; **G3** караоке-текст синхронизирован и пригоден для исполнения; **G4** певческий перевод прошёл слепую оценку; **G5** безопасность, согласие, доступность проверены; **G6** решение о публичном выпуске. Каждый — `GO`/`CONDITIONAL GO`/`NO-GO`; не закрывать «выглядит хорошо» без тестового протокола.

### 6.5 ADR, безопасность, исследования

ADR-001 не имитировать готовый переводчик (нет фиктивной кнопки, словарь помечен демо) · ADR-002 WebRTC для аудио + WebSocket для сигналинга · ADR-003 не требовать сторонний мессенджер · ADR-004 TTS ≠ singing voice conversion · ADR-005 сначала измерения, потом обещания (ворота) · ADR-006 комната v0.1 = два участника · ADR-007 приватность по умолчанию. Безопасность: не использовать для секретных разговоров; код комнаты угадываем; локальный сигналинг без TLS; Web Speech зависит от браузера/ОС; перед публичным запуском 12 пунктов (HTTPS/WSS; TURN с ротацией; сильные id комнат; проверка членства на каждом сообщении; защита от перегрузки; модель согласия; указание облачной обработки; политика хранения и удаления записей/транскриптов/переводов/профилей; удаление по запросу; права на музыку и тексты; лицензии моделей; независимый тест до реальных пользователей). Голосовая идентичность: голос — персональные данные; не создавать профиль другого человека без явного согласия; не выдавать синтез за запись; показывать режим «оригинал / преобразованный / синтезированный». Исследовательские основания: MDN WebRTC/getUserMedia/RTCPeerConnection; MDN Web Speech API + SpeechRecognition (поддержка неодинакова, некоторые реализации серверные — не офлайн); Meta Seamless; певческая речь отличается от обычной (протяжные гласные, высоты, аккомпанемент, ритм, художественное произношение). **Критерий инженерной честности (5 запретов):** не называть TTS переводом певческого голоса; не считать словарь машинным переводом; не считать передачу WebRTC подтверждением языкового перевода; не утверждать сохранение личности голоса без проверки; не объявлять поддержку языка потому, что модель принимает его код.

### 7.5 Этапы зрелости и метрики (как строить и как проверять)

Строить не «100 разрозненных функций», а единое устройство с уровнями зрелости: **Этап 1** два человека действительно понимают друг друга (двусторонний перевод речи); **Этап 2** совместное караоке с переводом (синхронизация телефонов, singing ASR, перевод текста, общий тайминг, озвучивание; отдельно проверить сохранение музыкальности); **Этап 3** переведённое пение голосом самого человека (SVC, сохранение тембра, музыкального времени, фонетической выразительности — главный исследовательский этап, сравнительные испытания на реальных песнях); **Этап 4** общая музыкальная среда (дополнительные участники, другие языки, взаимодействие, доступность, управление записями, постоянные связи близких). Испытывать не только чистые студийные записи: обычные телефоны, бытовой шум, быстрые куплеты, длинные гласные, одновременное пение, нестабильный интернет. Фиксировать для каждой версии: точность распознавания слов отдельно по языкам; правильность смысла перевода; долю переведённых слов, которые удаётся спеть в исходной музыкальной фразе; задержку от исполнения до переведённого звука; сохранение узнаваемости голоса, мелодии, эмоций; пропуски/повторы/искажения/сбои соединения; результаты независимой оценки носителями обоих языков. Пороги — после предварительных испытаний, не придумывать заранее и не выдавать за достигнутые. **Главный критерий успеха:** человек в Японии не просто читает перевод песни бразильца — он слышит исполнение на своём языке, может подпевать, отвечать и продолжать совместную песню; и бразилец получает ту же возможность. Центральная инженерная задача Singulyar: не просто перевести язык, а сделать совместное действие возможным для людей, которые иначе не смогли бы полноценно участвовать в нём вместе. Финал диалога: архив создан, синтаксис проверен, тест установки/повторной установки/отката на тестовом HTML пройдены; полноценное сетевое тестирование и регрессия оригинала НЕ выполнены; замена файла на GitHub Pages НЕ заявлялась (исходный HTML не удалось перенести в среду сборки — поэтому пакет содержит интеграционный патч, а не готовую копию ЛАДОМ); для публичного сетевого режима — отдельный сервер HTTPS/WSS и TURN; перевод живого пения pt→ja с сохранением мелодии, ритма и голоса — следующий исследовательский этап, в архиве не имитируется.
