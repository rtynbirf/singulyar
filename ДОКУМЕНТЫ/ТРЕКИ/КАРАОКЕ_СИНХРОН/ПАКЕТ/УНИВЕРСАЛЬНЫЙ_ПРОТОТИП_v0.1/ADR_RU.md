# Архитектурные решения (ADR)

## ADR-001 — Не имитировать готовый переводчик
**Решение:** в v0.1 нет фиктивной кнопки «перевести живое пение». Словарь явно обозначен как демонстрационный.
**Причина:** отделить реально работающие каналы от исследовательской задачи.

## ADR-002 — WebRTC для исходного аудио
**Решение:** использовать `RTCPeerConnection` для аудиоканала и WebSocket для сигналинга.
**Причина:** это разделяет транспорт медиа и координацию соединения. Для production необходимо добавить TURN и проверить сетевую матрицу.

## ADR-003 — Не требовать сторонний мессенджер
**Решение:** создание комнаты, передача аудио и текстовый канал находятся в одном прототипе.
**Причина:** пользователь должен общаться внутри Singulyar.

## ADR-004 — TTS не равно singing voice conversion
**Решение:** системный синтез речи используется только для озвучивания текста.
**Причина:** TTS не сохраняет автоматически мелодию и личность певческого голоса.

## ADR-005 — Сначала измерения, потом обещания
**Решение:** этапы перевода пения имеют отдельные контрольные ворота.
**Причина:** качество, задержка и узнаваемость должны быть подтверждены испытаниями.

## ADR-006 — Комната v0.1 ограничена двумя участниками
**Решение:** третий участник получает отказ.
**Причина:** упрощает начальную проверку связи. Хор и маршрутизация нескольких голосов — последующий этап.

## ADR-007 — Приватность по умолчанию
**Решение:** нет постоянного хранения аудио и сообщений в прототипе.
**Причина:** снижение риска. Перед публичным запуском всё равно необходимы полноценные механизмы безопасности.
