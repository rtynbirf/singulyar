# План тестирования

Все тесты изначально `NOT RUN`. Не заменять статус на `PASS` до реального исполнения.

## Регрессия ·31
1. Страница открывается без JS-ошибок.
2. Локальное воспроизведение, пауза, перемотка и секции работают.
3. Сцены, пульт, текст-пульс, доступность и голосовые настройки работают.
4. Запись и экспорт, если поддерживаются исходной страницей, не сломаны.
5. Offline-поведение не зависит от наличия сервера связи.

## Интеграция
1. Установщик создаёт `.pre-ladom-bridge.bak`.
2. Установщик не вставляет script дважды при повторном запуске.
3. Rollback восстанавливает резервную копию.
4. Диалог доступен с клавиатуры и screen reader.
5. Ошибки микрофона и сервера видны пользователю.

## Сервер
1. `npm install` и `npm run check` проходят.
2. Сервер стартует на 8787.
3. Неправильный путь WebSocket отклоняется.
4. Два клиента создают и присоединяются к комнате.
5. Третий клиент получает отказ.
6. Сообщение длиной более 2000 символов отклоняется.
7. Некорректный JSON не завершает процесс.
8. При уходе участника другой получает `peer-left`.
9. Сервер не пишет аудио или сообщения в файлы.

## WebRTC
- Два клиента в одной сети.
- Два клиента в разных Wi-Fi.
- Один клиент в мобильной сети.
- Сеть с ограниченным UDP (потребуется TURN).
- Потеря пакетов, высокий RTT, переключение сети.
- Выход/повторный вход и выключение микрофона.

## Переводчик — только будущие этапы
Измерять по языковой паре и жанру отдельно: WER/CER, качество смысла у носителей языка, тайминг слогов, пригодность к исполнению, p50/p95 задержку, артефакты вокала, узнаваемость при согласии, отказ при низкой уверенности, CPU/RAM/энергию/трафик.

## Доказательная запись
`CLAIM → CODE → OFFICIAL SPEC → TEST → VERDICT`. Фиксировать версию, устройство, браузер, сеть, шаги, ожидаемое и фактическое поведение. `UNKNOWN` — правильный результат при недостатке доказательств.
