# Техническое задание — интеграция сетевого караоке в ·31 ЛАДОМ
Версия 0.2.0 · 2026-10-13 · Статус: интеграционный прототип, не production.

## Цель
Добавить в существующую страницу ЛАДОМ двухстороннюю связь между двумя участниками и подготовить проверяемую архитектуру персонального перевода пения, не разрушая автономный сценарий.

## Функциональные требования
- FR-01: текущие функции страницы работают без подключения к сетевому серверу.
- FR-02: новая кнопка открывает доступное диалоговое окно связи.
- FR-03: можно создать комнату или присоединиться по коду.
- FR-04: сервер отклоняет третьего участника.
- FR-05: микрофон включается только после явного нажатия и разрешения браузера.
- FR-06: участник может отключить микрофон без выхода.
- FR-07: звук передаётся по WebRTC при успешном согласовании сети.
- FR-08: текстовые сообщения доставляются второму участнику через сервер.
- FR-09: выбранные языки и имя участника показываются в UI, но не маскируются под реальную обработку.
- FR-10: можно локально озвучить введённый текст системным TTS.
- FR-11: пользователь видит статус соединения, ошибки и журнал сообщений.
- FR-12: Esc и кнопка закрытия закрывают панель.
- FR-13: уход закрывает микрофон, peer connection и WebSocket.
- FR-14: исходный код ·31 не удаляется и не заменяется.
- FR-15: установщик делает резервную копию до модификации.
- FR-16: реальный переводчик подключается через интерфейсы адаптеров, а не через фиктивный словарь.

## Нефункциональные требования
- NFR-01: клавиатурное управление, видимый фокус, aria-label/status/log.
- NFR-02: мобильный экран от 320 CSS px.
- NFR-03: никакого скрытого постоянного хранения голоса/текста.
- NFR-04: публичная связь только через TLS/WSS и настроенный TURN.
- NFR-05: ограничения длины и размера сообщений.
- NFR-06: языковые возможности объявляются на уровне каждой модели и пары.
- NFR-07: понятная деградация при потере сети.
- NFR-08: исходный звук, транскрипт, перевод и синтезированный звук — отдельные типы данных.

## Контракты будущих адаптеров
### SingingASRAdapter
Вход: аудио с временными метками, язык/auto, жанр (если известен). Выход: текст, таймкоды слов/слогов, confidence, версия модели.
### TranslationAdapter
Вход: текст, source locale, target locale, разрешённый контекст. Выход: несколько кандидатов, ambiguity/confidence, provenance.
### SingingAlignmentAdapter
Вход: оригинал, текст/перевод, MIDI или оценённая мелодия. Выход: сопоставление фонем/слогов/нот и ошибки тайминга.
### SingingVoiceAdapter
Вход: перевод, просодия, мелодический таймлайн и согласованный голосовой профиль. Выход: отдельная аудиодорожка и метаданные происхождения.
### QualityGate
Проверяет пропуски, язык, тайминг, артефакты, задержку и согласие на голосовое преобразование; при провале возвращает `UNKNOWN`/исходный поток.

## Критерии приёмки
- A-01: установщик изменяет HTML только одной ссылкой на JS; backup создан.
- A-02: rollback восстанавливает исходный HTML.
- A-03: панель открывается/закрывается клавиатурой и кнопкой.
- A-04: сервер запускается, `/signal` принимает WebSocket.
- A-05: два клиента создают/входят в комнату.
- A-06: третий клиент получает `room-full`.
- A-07: текст передаётся, пустой/слишком длинный текст отклоняется.
- A-08: WebRTC передаёт аудио в сети, где peer connectivity возможна.
- A-09: выключение микрофона прекращает передачу аудио.
- A-10: неизвестный/неподключённый переводчик честно обозначен как отсутствующий.
- A-11: существующие локальные караоке-сценарии проходят регрессию.
