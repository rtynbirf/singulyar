# СИНГУЛЯР ·31 ЛАДОМ — пакет интеграции связи v0.2.0

## Что это
Аддитивный интеграционный пакет к существующей странице `СИНГУЛЯР_31_ЛАДОМ.html`. Он добавляет кнопку **«СВЯЗЬ · спеть вместе»**, двухстороннюю передачу исходного аудио через WebRTC, текстовый канал через WebSocket и локальное озвучивание введённого текста браузерным TTS. Существующий движок караоке не переписывается.

**Это не завершённый переводчик певческого голоса.** Нет реального ASR спетого вокала, перевода текста, выравнивания слогов по нотам и генерации переведённого певческого голоса. UI это сообщает прямо.

## Состав
- `integration/ladom-network-bridge.js` — UI и WebRTC/WebSocket-клиент, добавляется поверх текущей страницы.
- `server/server.js` — минимальный WebSocket-сервер сигналинга, две стороны на комнату, текст и обмен WebRTC offer/answer/ICE.
- `scripts/install_patch.py` — вставляет одну ссылку на bridge в HTML и делает резервную копию.
- `scripts/rollback_patch.py` — откат HTML из резервной копии.
- `docs/` — архитектура, ТЗ, дорожная карта, исследования, безопасность, тест-план, ADR и каталог 100 направлений.
- `tests/` — smoke tests и проверки сервера.

## Установка в копию репозитория
1. Сделайте отдельную копию репозитория `rtynbirf/singulyar` и рабочую ветку.
2. Скопируйте каталог `integration/` и запустите установщик относительно оригинального файла:
   `python scripts/install_patch.py PATH/СИНГУЛЯР_31_ЛАДОМ.html PATH/ROOT/REPO`
3. Запустите локально статический сайт. Откройте страницу по `http://localhost`, не `file://`, чтобы запрос микрофона работал предсказуемо.
4. Отдельно запустите сервер по `server/README_RU.md`.
5. В интерфейсе введите `ws://localhost:8787/signal` только для локального теста (UI в текущей версии требует `wss://`; см. раздел «локальная проверка» в документации). Для публичного стенда используйте `wss://` за TLS reverse proxy.

## Важное замечание к v0.2.0
Публичный сайт GitHub Pages — статический хостинг, он не запускает этот WebSocket-сервер. Сервер надо развернуть отдельно. В интерфейсе намеренно принимается только `wss://` для снижения риска случайного подключения к незашифрованному серверу. Для локальной проверки используйте HTTPS-локальный прокси или измените ограничение только в своей тестовой копии; не публикуйте `ws://`.

## Протокол честности
- `PASS` только после фактического запуска теста.
- `NOT RUN` не означает успех.
- Передача звука ≠ перевод звука.
- TTS ≠ пение.
- Перевод текста ≠ перевод с сохранением мелодии и тембра.
