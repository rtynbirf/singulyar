### Воспроизведение стенда (команды Фазы 0)

```bash
# из каталога пакета УНИВЕРСАЛЬНЫЙ_ПРОТОТИП_v0.1 (раскладка репы — плоская):
mkdir -p src && cp server.js src/server.js && cp phrasebook.js src/phrasebook.js
npm install          # S-01: +1 пакет (ws), 0 уязвимостей
npm run check        # S-02: node --check src/server.js + src/phrasebook.js — чисто
npm start            # S-03: "Singulyar prototype listening on http://localhost:8080"
# открыть http://localhost:8080 в двух окнах (README «Быстрый запуск», шаги 1–5)
```

**Наблюдение Р-1 (раскладка):** `package.json` пакета ссылается на `src/server.js` и `src/phrasebook.js`, а поставка в репе плоская (оба файла лежат рядом с `index.html`). `npm start`/`npm run check` без перескладки падает («Cannot find module»). Это дефект упаковки поставки, не кода: перескладка однозначна и воспроизводима одной командой (выше). Сервер раздаёт `ROOT = ../` от `src/`, поэтому при раскладке `src/` все доки пакета доступны по HTTP (README_RU.md → HTTP 200). Код не правился.
**Наблюдение Р-2 (сеть для установки):** `npm install` требует одноразового доступа к registry (`ws`). Сам зал дома — офлайн-first, а этот прототип — референс на отдельном стенде; после установки сервер и сигналинг работают локально без внешней сети.

**Проверка раздачи:** `GET /` → HTTP 200, 19 287 Б, `Content-Type: text/html; charset=utf-8`; sha256 раздаваемого `index.html` = `f9c93f41f9e6d69e06bba7416e237aae66f3fca2e83c249b0a984b8a02247ffb` — совпадает с файлом пакета байт-в-байт. Попытка path traversal `../../etc/passwd` → 404 (гард `path.resolve` + `startsWith(ROOT)` работает).

## 6 · Реестр дефектов и наблюдений (формат TEST_PLAN §8)

**D-01 · Ренегоциация не-инициатора (дефект, измерен)**
- Версия: прототип v0.1.0 (пакет владельца, байты без изменений). Среда: headless Chromium 1200, localhost.
- Шаги: A «Создать комнату» → B «Подключиться по коду» → A «Включить микрофон» (оффер+ответ прошли, соединение connected) → B «Включить микрофон».
- Ожидание (README, шаг 4; FR-07): звук в обе стороны.
- Факт: дорожка B до A не доходит (`ontrack` у A не сработал, 6 с наблюдения). Корень: `pc.onnegotiationneeded` делает оффер только при `isInitiator`; дорожка, добавленная не-инициатором после ответа, не вызывает переоффер.
- Обходной порядок (проверен в S-08): не-инициатор включает микрофон до оффера инициатора — тогда обе дорожки в первичных SDP.
- Severity: средний (основной поток README шага 4 попадает в дефект 50/50 в зависимости от того, кто нажал первым).
- Решение (Фаза 1): perfect negotiation / переоффер на `negotiationneeded` у обеих сторон; регресс-проба — оба порядка. Код прототипа этим тактом не правился (байты владельца).

**D-02 · Статус-строка инициатора не обновляется на peer-joined (наблюдение)**
- Шаги: A создаёт комнату → B входит. Ожидание (S-06): оба видят «2 участник(а/ов)». Факт: у A статус остаётся «1 участник(а/ов)» до перезагрузки (статус пишется только в ветке `joined`); факт прихода партнёра A видит в ленте событий. Severity: низкий (косметика, информация доступна в ленте). Решение: обновлять статус и в `peer-joined`.

**D-03 · Остановка дорожки на транспорте не подтверждена (ограничение пробы)**
- Шаги: соединение connected, обе стороны с аудио → A «Выключить микрофон» → наблюдение приёмной дорожки B 7 с.
- Ожидание (S-13): исходный аудиопоток прекращается. Факт: `muted:false, readyState:'live'`, `mute`-событий 0.
- Интерпретация: UI-логика честна (локальные треки остановлены кодом `t.stop()`), но транспортный эффект в среде стенда не доказан — фейк-устройство/headless может вести себя иначе, чем реальный микрофон; как минимум это невоспроизводимое на песочнице измерение. Severity: требуется проверка в целевой среде. Решение: проба на реальных устройствах в G1 (👤), при подтверждении — дефект кода micOff (не хватает замены дорожки/ренегоциации).

**Р-1 · Раскладка поставки** — см. §1: `package.json` ждёт `src/`, поставка плоская. Однокомандная перескладка, код не тронут.
**Р-2 · Установка требует сети** — см. §1: `ws` ставится из registry одноразово; сервер дальше работает локально.
