# 01 · ВИДЕНИЕ, ГРАНИЦЫ, ПРИНЦИПЫ

## 1. Что это

OMNISPEAKER-1 — **проектная спецификация** универсальной амбиентной системы: акустика + микрофонный массив + (опционально) экран и камера + сенсоры + умный хаб + **локальный ИИ-агент** + опциональное облако + приватный контур. Не заявляется, что продукт существует.

> Формула устройства (исходная): `OMNISPEAKER-1 = акустика + микрофонный массив + экран + камера + сенсорный блок + умный хаб + локальный ИИ + облачный ИИ + медицинский радар + энергоузел + агентная ОС + приватный контур`.
> Ревизия: «медицинский радар» → **радар присутствия и wellness-сигналов**; «облачный ИИ» → **опциональный, по политике**.

## 2. Эмерджентное сингулярное свойство (ревизованное)

Исходная формулировка: «распределённый орган восприятия и действия дома». Ревизия сохраняет её и добавляет условие проверяемости:

```
Цель + Контекст + Инструменты + Политики + Обратная связь
  = ПРОВЕРЯЕМОЕ ДОСТИЖЕНИЕ СОСТОЯНИЯ МИРА
```

Человек говорит **цель** («Подготовь дом к возвращению»). Система сама выбирает устройства, сенсоры, время и способ, **показывает, что собирается сделать**, спрашивает только там, где это нужно, исполняет, откатывает при сбое и пишет неподделываемый журнал. Цель считается достигнутой только когда **двойник состояния дома** подтверждает результат.

Три свойства делают это «сингулярным», а не суммой функций:

1. **Единая точка принятия решений о доверии** (policy gate) — все 515 функций проходят через один контур.
2. **Единая событийная шина** — датчики, голос, расписание и устройства становятся событиями одного вида.
3. **Единый журнал** — любое действие объяснимо: кто, по чьей инструкции, по какому правилу, с каким результатом.

## 3. Принципы (инварианты)

| # | Принцип | Где обеспечивается |
|---|---|---|
| I-1 | **Offline-first**: всё, что нужно для безопасности и повседневного управления, работает без WAN | NFR-REL, док. 05 §12 |
| I-2 | **LLM предлагает — хост решает.** Модель не исполняет, не авторизует и не определяет риск | P-001…P-012 |
| I-3 | **Источник инструкции важнее её текста** (provenance): ТВ, веб, документы, письма не командуют | P-002 |
| I-4 | **Deny-by-default для облака**, health и биометрия никогда не покидают устройство | P-003, P-004 |
| I-5 | **Аппаратные выключатели** mic/cam/radio — прошивка не может их отменить | P-012, док. 09 |
| I-6 | **Стоп важнее всего** (P0) | FR-A7 |
| I-7 | **Safety — отдельный путь** (MCU, без LLM, без облака) | док. 05 §12 |
| I-8 | **Журнал нельзя исправить незаметно** | hash-chain |
| I-9 | **Не медицина**: напоминания, SOS, «нет движения N минут»; без диагнозов | док. 08 |
| I-10 | **Открытые стандарты** (Matter, Thread, MCP, Wyoming-подобные интерфейсы) вместо собственных | док. 06 |

## 4. Что НЕ является целью

- Замена врача, сертифицированной охранной/пожарной сигнализации или газового датчика.
- Скрытая выгрузка аудио/видео/данных здоровья.
- «Бог-агент» без policy engine и журнала.
- Обещание, что 515 функций войдут в один SKU: каталог — *бэклог возможностей*, v1.0 — подмножество tier M.

## 5. Персоны и ключевые сценарии

| Персона | Что важно | Ключевой сценарий |
|---|---|---|
| Владелец-техник | локальность, API, прозрачность | «Покажи, почему выключился свет» → журнал |
| Семья | простота, дети, приватность | «Режим Сон», детский профиль с согласием родителя |
| Пожилой родственник | безопасность без слежки | SOS, «нет движения 90 минут» → уведомить контакт |
| Человек с нарушением зрения/слуха/речи | доступность | режимы без экрана/голоса, субтитры, описание сцены |
| Гость | не получает чужих прав | гостевой профиль, нет памяти |

## 6. Критерий успеха концепции

1. «Подготовь дом к возвращению» → проверяемый план за ≤ 2 с (P/D-SKU), исполнение с откатом, дельта мира.
2. Атака «ТВ командует открыть дверь» блокируется на 100% тестов (док. 11).
3. С отключённым WAN проходят все M-функции.
4. Любую запись журнала нельзя изменить без обнаружения.
