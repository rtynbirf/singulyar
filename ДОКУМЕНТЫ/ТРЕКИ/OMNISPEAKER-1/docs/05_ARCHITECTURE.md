## 2. Аппаратные слои и профили

Подробно — док. 09. Ключ: **SoC (агент) + MCU (safety) + Secure Element (ключи)** на любом SKU.

## 3. Перцепция

### 3.1. Аудио
Wake word (локально, DSP/NPU) · VAD · beamforming (MVDR) · шумоподавление · AEC · диаризация · ASR · классификатор акустических событий (плач, сирена, разбитие стекла, лай) · TTS. Кольцевой буфер ≤ 3 с в RAM; до wake word ничего не пишется. Эмоции по голосу — **не в MVP** (каталог 123).

### 3.2. Зрение (D/H, опционально)
Детекция объектов, OCR, жесты, описание сцены (a11y), фильтр приватности (блюр лиц/номеров до сохранения). Лица — только по согласию каждого, локальные эмбеддинги. Камера физически закрывается шторкой; светодиод аппаратно связан с питанием.

### 3.3. Сенсоры
Присутствие (PIR, mmWave; ультразвук — C), среда (T/RH/lux/VOC/CO2), безопасность (внешние Matter-датчики), энергия, позиция (BT Channel Sounding, UWB — C). Выход — **события**, не сырые потоки.

## 4. Шина событий

Все сигналы → событие по `event.schema.json`: `ts_utc`, `source`, `type`, `privacy_class`, `provenance`, `required_response`, `payload`. Сырые потоки в LLM не попадают.

```json
{
  "event_id": "evt_20261011_001",
  "ts_utc": "2026-10-11T09:33:00Z",
  "source": "mmwave_bedroom",
  "type": "ambient_event",
  "subtype": "person_fell",
  "confidence": 0.94,
  "privacy_class": "health_sensitive",
  "provenance": "sensor_event",
  "required_response": "safety_protocol",
  "payload": {"room": "bedroom", "stillness_seconds": 18}
}
```
Типы: `user_command`, `ambient_event`, `device_event`, `security_event`, `health_event`, `energy_event`, `calendar_event`, `system_event`, `agent_action_result`.

## 5. Оркестратор

Компоненты: Intent Router (быстрый путь/медленный), Task Planner, State Machine (`created → planning → awaiting_confirmation → executing → completed | failed | cancelled`), Task Queue, Context Builder, Tool Selector, Verifier, Retry Manager, Escalation Manager, Cancellation Controller.

Приоритеты (исправлено): **P0** стоп/mute/отмена → **P1** безопасность жизни → **P2** явная команда владельца → **P3** критическая автоматизация → **P4** фоновая оптимизация → **P5** проактивные рекомендации → **P6** аналитика.

## 6. Модельный каскад

| Модель | Задача | SKU / где |
|---|---|---|
| Wake word | активация | все; DSP/MCU-класс |
| Intent-парсер (правила) | типовые команды | все; CPU |
| ASR (Whisper-класс int8/Parakeet-класс) | речь → текст | все; NPU |
| SLM 1–4B Q4 | маршрутизация, простые планы | P, D; NPU |
| LLM 7–14B Q4 | планы, диалог, RAG | H; NPU/GPU |
| VLM лёгкая | камера/документы | D (опц.), H |
| Эмбеддинги + реранкер | RAG | H (D лёгкая) |
| TTS (нейросетевой, локальный) | ответ | все |
| Детекторы аномалий | энергия/датчики | H, лёгкие на P/D |

Принцип: **малая модель решает всё, что может**; модель выбирается маршрутизатором, решение — в журнал. Оценка до включения по умолчанию — док. 11.

## 7. Память

| Слой | TTL | Содержимое | Правило |
|---|---|---|---|
| Working | сек–мин | диалог, план, показания | RAM |
| Session | часы–дни | недавние команды, временные предпочтения | очищается в guest |
| Long-term | месяцы | привычки, карта дома, устройства, предпочтения | запись только из доверенных источников; provenance + TTL |
| Vector RAG | постоянно | чанки документов/заметок | помечено untrusted-content |
| Graph | постоянно | user–room–device–rule | для объяснений |
| Journal | append-only | запросы, планы, решения, результаты | hash-chain |
| Health vault | по согласию | отдельный том/ключ | никогда в облако |

## 8. Инструменты и MCP

Локальные MCP-серверы: `home_core`, `lights`, `climate`, `security`, `media`, `calendar`, `files`, `health`, `energy`, `automation`, `memory`. Каждый — подписанный пакет в песочнице (WASM/rootless OCI), без сети по умолчанию; stdio-запуск только из подписанного манифеста. Ревизия протокола — 2026-07-28 (см. док. 03, 06). Манифест хоста — источник истины по рискам.

## 9. Policy engine

Правила P-001…P-012 (`reference/policy/risk_matrix.yaml`, реализация `omni_core.policy`). Свойства: детерминированность, подписанные правила, fingerprint в каждой записи журнала, «побеждает самое строгое», не изменяется агентом. Исключения заданы явно: safety-события не подавляются тихими часами; standing grant владельца понижает только `confirm` для sensor/automation.

## 10. Мультиагентный режим

Специализированные агенты (Home, Media, Energy, Health, Security, Knowledge, Personal, Developer) — **роли в одном policy-периметре**, а не независимые сущности: общий policy engine и журнал; обмен через MCP/внутренние события; агент без явного гранта не вызывает инструменты другого агента. На P/D-SKU — один процесс с ролями; на H — отдельные процессы.

## 11. Offline-first

Работает без интернета: wake word, базовые команды, свет/климат/замки, музыка из локальной библиотеки, таймеры/напоминания, локальный RAG, автоматизации, датчики/тревоги, журнал. Требует сети: веб-поиск, часть стриминга, обновления больших моделей, внешние сервисы (такси, доставка). Деградация — §12.

## 12. Режимы деградации и safety-путь

```text
 Датчики/кнопка SOS ─► SAFETY MCU ─► локальный сигнал (сирена/свет) ─► BLE/Thread/Wi-Fi уведомление
                           │  (без LLM, без облака; собственные часы и watchdog)
                           └─► SoC агент (если жив): подтверждение «Всё в порядке?», контакты
```

| Отказ | Что остаётся |
|---|---|
| Нет WAN | всё локальное; облачные функции явно недоступны |
| Нет Wi-Fi/роутера | Thread/BLE, локальное управление с телефона по BLE, сирена |
| NPU перегрев/сбой | детерминированный intent-парсер, таймеры, сцены; LLM-функции недоступны |
| Потеря питания | резервный конденсатор/АКБ (опция): «last gasp» + сирена safety MCU |
| Сбой обновления | авто-откат A/B ≤ 5 мин |
| Шторка/mute включены | функции соответствующего канала выключены; safety-путь без микрофона работает |

## 13. Обновления и обучение

Подписанные пакеты (TUF-класс метаданные), anti-rollback, A/B-слоты, health-check, откат, журнал обновлений; OTA не стартует в окно активной тревоги. Данные пользователя в обучение не уходят по умолчанию. Локальная адаптация — только на разрешённых данных, объяснимая. Federated learning/DP — tier C (исследование).

## 14. Эмерджентное свойство

```text
восприятие → понимание → память → план → политика → действие → аудит → обучение
```
Агент действует **по цели**, в границах доверия и приватности, и доказывает это журналом.
