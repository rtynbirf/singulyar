# 02 · ТЕХНИЧЕСКОЕ ЗАДАНИЕ (полное)

Версия 1.0 · статус: проектная спецификация. Нормативные слова: **ДОЛЖЕН** (обязательно), **СЛЕДУЕТ**, **МОЖЕТ**.
Нумерация функциональных требований `FN-001…FN-515` совпадает с каталогом (док. 04). Системные требования — `FR-*`, `NFR-*`, `IF-*`, `DR-*`.

## 1. Назначение и объём

Устройство и агентная ОС, которые (1) воспринимают голос, звуковые события, присутствие, среду и (опционально) видео; (2) управляют умным домом по Matter и мостам; (3) планируют и исполняют многошаговые цели через tool calling и policy engine; (4) хранят память и RAG локально; (5) эскалируют в облако только по явной политике.

Объём v1.0 — все пункты каталога с tier **M** (176 пунктов, часть — политики и доступность). Tier S — v1.x; C — исследования; X — вне объёма.

## 3. Функциональные требования агента (FR)

| ID | Требование | Приёмка |
|---|---|---|
| FR-A1 | Принимать цель на естественном языке (голос/текст/API) | интеграционный тест на 200 целей RU/EN |
| FR-A2 | Строить план: DAG, волны параллельности, условия; гибрид Plan-and-Execute + ReAct | `test_plan_*`; план ≤ 25 шагов |
| FR-A3 | Вызывать только инструменты из **подписанного манифеста хоста** | `test_unknown_tool_rejected` |
| FR-A4 | Валидировать аргументы по JSON Schema, существование устройств, идемпотентность | `test_schema_*`, `test_hallucinated_device_rejected` |
| FR-A5 | Принимать решение policy engine для каждого вызова: allow / confirm / confirm_2f / deny | `test_*` policy |
| FR-A6 | Подтверждать high (пользователь) и critical (два фактора); молчание = отказ; таймаут 20 с | UI + e2e |
| FR-A7 | **Стоп** прерывает исполнение между шагами и запускает откат | `test_cancel_*` |
| FR-A8 | Откат (сага) для обратимых шагов; невозможность отката фиксируется | `test_saga_*` |
| FR-A9 | Повторы только идемпотентных вызовов; backoff; лимит 3 | `test_retry_only_for_idempotent` |
| FR-A10 | Лимиты: шагов 25, вызовов 40, длительность 300 с, одинаковых вызовов подряд 2, без изменения состояния 3 | `test_loop_detector` |
| FR-A11 | Provenance каждого вызова; недоверенный источник не запускает действия | `test_untrusted_*` |
| FR-A12 | Append-only журнал с hash-chain; проверка целостности | `test_audit_*` |
| FR-A13 | Объяснение действия строится из журнала, не из «пересказа» модели | e2e |
| FR-A14 | Агент не может менять политику, манифест, ключи, журнал | тест прав ФС + `P-010` |
| FR-A15 | Standing grants владельца: понижают только `confirm` для sensor/automation; не понижают critical | `test_standing_grant_*` |

## 9. Режимы (профили политик)

`normal` · `guest` (без памяти) · `child` · `care` (контакты, неподвижность) · `confidential` (локальный ASR, без облака, ответы на экран) · `paranoia` · `no-voice` · `no-screen` · `no-camera` · `no-cloud`.

## 10. Критерии приёмки релиза v1.0

1. Все FR/NFR выше выполнены или имеют утверждённое отклонение.
2. Автотесты ядра зелёные; набор атак (док. 11) блокируется на 100%.
3. Хаос-тесты: отключение WAN, питания, NPU — safety-путь жив.
4. Аудит доступности и приватности (DPIA) подписан.
5. SBOM и процесс CVD опубликованы.
6. Сертификации (RED/EMC/безопасность, Matter, при необходимости Product Security) получены.
