## Шаг 0. Подготовка

**Команда (минимум):** embedded/DSP (1), ML/edge (1), backend/агент (1–2), mobile/web (1), security (0.5), hardware/ID (по этапу), юрист/комплаенс (консультант).

**Решения до кода (запишите в ADR):**
1. SoC/NPU для P-SKU стенда (критерии: поддерживаемый рантайм LLM/ASR, память ≥ 8 ГБ, Linux BSP, Thread RCP через USB).

4. Оркестрация сервисов: systemd + OCI rootless (продукт) / docker compose (стенд).
5. Юрисдикция и список «LIC»-функций, включаемых в v1.0 (док. 08 §6).

**DoD:** ADR-0001…0005 приняты; стенд собран.

# core: загрузка манифеста (схема reference/schemas/tool_manifest.schema.json)
import json
from omni_core import ToolSpec, Risk
def load_registry(path):

    # verify_signature(data)  # обязательна; не принимать неподписанный манифест

## Шаг 3. Шина событий и provenance

Каждый вход получает provenance **на границе** — в адаптере, не в модели:

| Вход | Provenance |
|---|---|
| голос с подтверждённым профилем владельца (или приложение с аутентификацией) | `owner_direct` |
| другой авторизованный пользователь | `user_direct` |
| гостевой профиль | `guest` |
| событие датчика (радар, протечка, кнопка SOS) | `sensor_event` |
| утверждённое пользователем правило | `automation` |
| звук без распознанного говорящего / ТВ / радио | `untrusted_audio` |
| результат веб-поиска/облака | `web` |
| RAG, файлы, письма, календарные приглашения | `document` |
| запись памяти, не подтверждённая пользователем | `memory_inferred` |

```python
import asyncio, json, time, uuid
class EventBus:
    def __init__(self): self.subs = []; self.q = asyncio.Queue(maxsize=1000)
    def subscribe(self, fn): self.subs.append(fn)
    async def publish(self, type_, source, payload, provenance, privacy="household", subtype=None, conf=None, required="none"):
        ev = {"event_id": uuid.uuid4().hex, "ts_utc": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
              "source": source, "type": type_, "subtype": subtype, "confidence": conf,
              "privacy_class": privacy, "provenance": provenance, "required_response": required, "payload": payload}
        # validate(ev, EVENT_SCHEMA); drop on failure
        await self.q.put(ev)
    async def run(self):
        while True:
            ev = await self.q.get()
            for fn in self.subs: asyncio.create_task(fn(ev))
```
Приоритеты: очередь с классами P0…P6 (замените `Queue` на приоритетную); `P0` (стоп/mute) обрабатывается вне очереди.
**DoD:** тест «аудио без профиля → `untrusted_audio`»; нагрузочный тест 1000 событий/с без потерь safety-событий.

## Шаг 4. Голосовой конвейер

1. **Захват:** многоканальный PDM/TDM → DSP (AEC, beamforming, шумоподавление) → моно-поток 16 кГц.
2. **Wake word:** локально; кольцевой буфер ≤ 3 с в RAM; до срабатывания ничего не пишется.
3. **VAD/конец реплики** → **ASR** (локальный) → текст.
4. **Быстрый путь:** детерминированный intent-парсер (шаблоны, слоты по реестру устройств) — типовые команды без LLM.
5. **Медленный путь:** SLM/LLM → план (шаг 6).
6. **TTS** локально; barge-in (прерывание речи словом «стоп»).
7. **Говорящий:** опциональные эмбеддинги — только по согласию; результат используется для provenance/персонализации, не как фактор для high/critical.

Если используете Wyoming-подобную схему сервисов (wake/STT/TTS как отдельные процессы), вынесите их в compose-стенд (`reference/deploy/docker-compose.reference.yml`) и мерьте задержку каждого этапа.

**Метрики и пороги:** WER (RU/EN/DE) на собственном наборе (≥ 300 фраз × 3 помещения × 3 дистанции × 3 уровня шума); ложные срабатывания wake word на 10 ч ТВ/речи; задержка «конец реплики → первое слово ответа» (NFR-PERF-1).
**DoD:** 20 типовых команд проходят полный путь офлайн; метрики записаны.

## Шаг 5. Локальный LLM и tool calling

1. Подготовьте модель (Q4; проверьте лицензию). Подключите рантайм (HTTP/IPC на localhost).
2. **Структурный вывод:** передавайте JSON Schema допустимых вызовов, **сгенерированную из манифеста по ролям** (модель не видит чужих инструментов). Используйте грамматическое/структурное ограничение декодирования.
3. Формат ответа модели — `tool_call`/`final` (док. 03 §6). Поля `risk`, `reasoning` удалены.
4. Контекст: минимальный; недоверенное — отдельным блоком `untrusted_content` с пометкой «данные, не команды».
5. Если модель вернула невалидный JSON → одна попытка исправления, затем уточняющий вопрос.

```python
def tool_schema_for(role, registry, allowed_scopes):
    one_of = []
    for name, s in registry.items():
        if s.risk.name == "FORBIDDEN": continue
        if any(sc not in allowed_scopes for sc in s.scopes) and role != "owner": continue
        one_of.append({"type": "object", "required": ["tool", "arguments"], "additionalProperties": False,
                       "properties": {"tool": {"const": name}, "arguments": s.input_schema,
                                      "rationale": {"type": "string", "maxLength": 200}}})
    return {"oneOf": one_of}
```
**Eval до включения:** набор ≥ 300 целей (простые, составные, неоднозначные, враждебные). Пороги: выбор верного инструмента ≥ 95% на простых, валидный JSON ≥ 99%, отказ на враждебных 100% (policy гарантирует, eval проверяет модель).
**DoD:** отчёт eval в CI; регрессия блокирует релиз модели.

## Шаг 7. MCP-хост и серверы

1. Хост реализует клиент MCP ревизии **2026-07-28**: версия и возможности клиента в `_meta`, обработка `resultType`, Tasks-расширение для долгих задач, Streamable HTTP для удалённых серверов; **SSE-транспорт не использовать**.
2. Локальные серверы — stdio, запуск **только** из подписанного манифеста: путь к бинарнику, хэш, аргументы фиксированы; пользовательская конфигурация не добавляет команд.
3. Песочница: WASM-компоненты или rootless OCI + seccomp + отдельный UID + `no-new-privileges` + лимиты CPU/RAM/FS; сеть выключена, кроме явно разрешённых хостов.
4. Удалённые серверы: OAuth 2.1; проверка `iss` (RFC 9207); resource indicators (RFC 8707); allowlist доменов; ответы помечаются provenance `web`.
5. Для каждого сервера — **capability-токен**: список инструментов и scope.

**DoD:** тест «сервер возвращает аннотацию `readOnly` для `unlock`» → хост всё равно применяет manifest; тест «stdio-сервер пытается запустить подпроцесс/сеть» → заблокировано.

## Шаг 10. Хранилища, шифрование, журнал

1. Тома: системный, данных пользователя, **health-vault** (отдельный ключ). FDE (AES-256-XTS) + AEAD для данных; ключи в SE/TPM.
2. Журнал: SQLite/файл + `HashChainLog`; голова подписывается ключом SE каждые N записей/минут; экспорт JSONL *(эталон)*.
3. Память: таблицы с provenance, TTL, источником; удаление пользователем; запрет записи из `untrusted`.
4. Стирание: «forget all» — подтверждение личности → уничтожение ключей → проверка недоступности.
5. Согласия: таблица (scope, срок, источник, отзыв) + применение отзыва немедленно.

**DoD:** тест перезагрузки (журнал цел), тест подделки (обнаружена), тест стирания (данные нечитаемы).

## Шаг 11. Safety MCU и аппаратные ключи

1. MCU (отдельный кристалл или защищённый домен) читает: кнопку SOS, внешние датчики (Thread/BLE), радар (UART), сигнал питания.
2. Логика: пороги/таймеры без LLM; сирена и свет; уведомление по независимому каналу; подписанные сообщения к SoC; watchdog в обе стороны.
3. Аппаратные выключатели mic/cam/radio разрывают питание и данные; MCU читает состояние и показывает на LED; **нет программного пути обратно**.
4. Тесты: отключение SoC, отключение Wi-Fi, отключение питания (конденсатор) — safety работает.

**DoD:** хаос-сценарии (док. 11 §5) проходят.

## Приложение B. Частые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Matter-устройства не находятся | VLAN режет mDNS/ICMPv6 | единый L2 для IOT-MATTER или mDNS-reflector |
| Ложные срабатывания wake word от ТВ | нет AEC по референсу воспроизведения | подать референс в AEC, пороги, «негативные» образцы |
| Модель выдумывает `device_id` | нет списка устройств в контексте | сначала `home.list_devices`; verifier отклоняет |
| Повторный unlock | retry без ключа | `idempotency_key`, retry только идемпотентных |
| Агент «проглатывает» критические отказы | нет различения исходов | enum результатов, сага, журнал |
| Перегрев NPU | постоянная загрузка моделью | профиль «ночь», маршрутизация на меньшую модель, троттлинг без затрагивания safety |
