# 02 · Полное техническое задание (ТЗ)

**Версия ТЗ:** 1.0  
**Дата:** 2026-10-12  
**Статус:** проектная спецификация на основе исходных артефактов A–G и ориентиров 2025–2026  
**Область:** SINGULYAR SEARCH — эмерджентный поисковый двигатель с проверкой доказательств

---

## 1. Цель продукта

Дать человеку инструмент исследования, который:

1. принимает цель и ограничения;
2. планирует и выполняет разнообразный поиск (лексический, семантический, контрдоказательства, первоисточники);
3. строит граф доказательств с происхождением;
4. проверяет и пытается опровергнуть выводы;
5. возвращает ответ **только** при достаточных независимых доказательствах, иначе — `UNKNOWN` с явными gaps;
6. не отнимает контроль и не скрывает неопределённость.

Продукт **не** является универсальным оракулом, медицинским изделием или юридическим советником.

## 3. Функциональные требования (FR)

### FR-01 · Приём цели
Система принимает: текст запроса, опциональные ограничения (домен, период, формат ответа, бюджет шагов/стоимости), критерии успеха.

### FR-02 · Планирование исследования
Система строит план: минимум запросы «как есть», «+ source», «+ contradiction», «+ primary source». План расширяем координатором.

### FR-03 · Разнообразный поиск
Параллельные каналы: BM25/FTS, dense/vector (где доступно), phrase, coverage, provenance, challenge. Дедупликация по doc_id / source hash.

### FR-04 · Гибридное объединение
Fusion через RRF (k=60 по умолчанию) или настраиваемые веса. Rerank (cross-encoder) — опциональный этап после fusion.

### FR-05 · Граф доказательств
Сущности: Document, Claim, Evidence (kind: support|oppose), Verdict. Связи: claim←evidence←source, version, timestamp.

### FR-06 · Проверка и опровержение
Verifier сравнивает support vs conflict; требует min_unique_sources (политика); выставляет status: VERIFIED | CONTRADICTORY | UNVERIFIED | UNKNOWN.

### FR-07 · Utility следующего шага
Выбор действия a по \( U(a) = \mathbb{E}[\Delta Q|a]/\mathrm{Cost}(a) \). Остановка при низком U или исчерпании бюджета.

### FR-08 · UNKNOWN
При недостатке evidence или unique sources → ответ `UNKNOWN`, confidence 0 (или калиброванный низкий), список gaps и limitations.

### FR-09 · Журнал gate
Каждый проход: CLAIM → SOURCE → EVIDENCE → TEST → VERDICT логируется. Прототип: hash-chain style.

### FR-10 · API / CLI
Минимум: ingest документа, search, ask (research). CLI для локальных MVP.

### FR-11 · Ingest
Приём текста/файлов; индексация BM25; embeddings при наличии модели; metadata (source_url, date, version).

### FR-12 · Ограничения агентов
Каждая роль: лимит шагов, времени, доступа. Verifier может veto координатора.

### FR-13 · Явные limitations
В каждом ответе — блок limitations (локальный корпус / нет веба / роли программные / …).

### FR-14 · Оценка
Harness: Recall@k, nDCG@k; ориентир BEIR; регрессионные тесты на контрольном наборе.

## 4. Нефункциональные требования (NFR)

| ID | Требование | Целевой ориентир |
|---|---|---|
| NFR-01 | Задержка локального MVP search | < 200 ms на малом корпусе |
| NFR-02 | Задержка hybrid + rerank (сервис) | p50 < 300 ms при top_k≤50 (без учёта LLM) |
| NFR-03 | Воспроизводимость | Детерминированный verifier при фиксированном корпусе |
| NFR-04 | Аудит | Полный лог gate на каждый /ask |
| NFR-05 | Расширяемость | Новый канал поиска = новый agent + регистрация в executor |
| NFR-06 | Изоляция | Retrieved content не исполняется |
| NFR-07 | Стоимость | Бюджет шагов и токенов задаётся пользователем |
| NFR-08 | Отказоустойчивость | Падение одного канала не роняет весь research |

## 7. Критерии приёмки (Acceptance)

**A1.** При пустом индексе /ask возвращает UNKNOWN и не генерирует утверждений.  
**A2.** При одном источнике и политике min_unique_sources=2 → UNKNOWN или UNVERIFIED с указанием echo-chamber risk.  
**A3.** При support и conflict → status CONTRADICTORY / contradicted, alert в ответе.  
**A4.** Gate-лог содержит все пять этапов.  
**A5.** Hybrid search на контрольном наборе не хуже max(BM25, dense) по Recall@10 (ориентир; требует eval harness).  
**A6.** Юнит-тесты ядра (models, agents, utility, metrics) зелёные.  
**A7.** Прототип демонстрирует сценарии: достаточные evidence, contradiction, empty corpus, single-source.

## 8. Вне объёма (Out of scope) v1.0

- Полноценный краулер всего веба.
- Обучение собственной большой языковой модели.
- Медицинские / юридические заключения.
- Гарантия истинности утверждений вне доступного корпуса.
- Автоматическое исполнение действий на основе найденного контента.

---

## 9. Зависимости и допущения

- Для сервисного каркаса: Docker, OpenSearch, PostgreSQL (или эквивалент).
- Для dense: embedding-модель (например sentence-transformers / актуальные MTEB-лидеры — выбор за реализатором).
- Корпус и qrels для BEIR-style eval предоставляются отдельно.
- Политика AH-* и min_unique_sources настраиваемы.
