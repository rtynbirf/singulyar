# 01 · Видение, принципы и эмерджентное сингулярное свойство

## Главный принцип (из исходной концепции)

> Человек определяет, что ему необходимо узнать. Система организует исследование, проверяет основания выводов и помогает человеку получить результат, не скрывая неопределённость и не отнимая у него контроль.

## Пять опор (из исходной концепции)

1. **Полнотекстовый поиск** — BM25, инвертированный индекс, точные фразы, морфология, идентификаторы, фильтры. OpenSearch — возможный фундамент, не обязательный.
2. **Семантический и гибридный поиск** — векторный поиск + объединение через RRF, переранжирование.
3. **Граф знаний и происхождение** — связи утверждений, источников, версий, доказательств; модель W3C PROV.
4. **Многошаговое исследование** — разбиение вопроса, поиск подтверждений, контрдоказательств, первоисточников.
5. **Измеряемое качество** — BM25, dense retrieval, reranking сравниваются на одинаковых запросах; BEIR как ориентир.

## Алгоритм ESE (из исходной концепции)

1. Разобрать намерение человека.
2. Составить исследовательский план.
3. Запустить разнообразный поиск.
4. Объединить результаты и устранить дубли.
5. Построить граф доказательств.
6. Проверить и попытаться опровергнуть вывод.
7. Выбрать следующий шаг.
8. Остановиться по критериям достаточности; если доказательств не хватает — `UNKNOWN`.

## Формула полезности следующего поиска (из исходной концепции)

\[
U(a)=\frac{\mathbb{E}[\Delta Q\mid a]}{\operatorname{Cost}(a)}
\]

Где \(a\) — действие (новый запрос, поиск первоисточника, проверка версии, воспроизводимый тест); \(\Delta Q\) — ожидаемое улучшение обоснованности; Cost — время, вычисления, ресурсы. Это проектная эвристика, требующая калибровки.

## Эмерджентное сингулярное свойство (собственный вклад пакета v1.0)

Исходные файлы задают направление. Ниже — **формулировка, которой нет в исходниках как готового целого**, но которая естественно возникает при пересечении:

- исходного gate `CLAIM → SOURCE → EVIDENCE → TEST → VERDICT`;
- правила «согласие ролей ≠ независимое подтверждение при одном источнике»;
- utility-driven остановки;
- практик 2025–2026: hybrid BM25+dense+RRF, multi-agent RAG с verification, W3C PROV, evidence-state controllers (см. `docs/13_SOURCES_AND_TRENDS.md`).

### Определение

**SINGULYAR SEARCH — это не «ещё один RAG» и не «рой LLM». Это evidence-state machine с человеческим контролем.**

Система в каждый момент поддерживает явное состояние:

| Измерение evidence-state | Смысл |
|---|---|
| **Sufficiency** | Достаточно ли независимых источников для утверждения |
| **Reliability** | Насколько источники первичные / свежие / согласованные по версии |
| **Conflict** | Есть ли явное противоречие (не просто «разные формулировки») |
| **Uncertainty** | Калиброванная неуверенность (не «confidence=0.87 из воздуха») |
| **Gaps** | Что именно не найдено (термин, период, первоисточник) |
| **Cost** | Сколько уже потрачено и сколько стоит следующий шаг |

Переходы состояния **детерминированы политикой**, а не «голосованием моделей». Генеративная модель (если используется) **предлагает**, хост **решает** по манифесту и gate.

### Чем это отличается от типичного multi-agent RAG 2025–2026

| Типичный multi-agent RAG | SINGULYAR |
|---|---|
| Несколько LLM-ролей пересказывают одни и те же сниппеты | Программные роли с **разными алгоритмами** (lexical ≠ phrase ≠ challenge) |
| «Согласие агентов» принимается за истину | Source-count: три пересказа одного URL = **один** источник |
| Ответ почти всегда генерируется | UNKNOWN — **полноценный и предпочтительный** исход при дефиците |
| Provenance как список URL в конце | Gate и PROV-совместимый граф **до** генерации |
| Confidence — скаляр из модели | Evidence-state с раздельными осями |
| Остановка по «хватит контекста» | Остановка по \(U(a)\) и политике AH-* |

### Инварианты (не нарушаются)

1. **Human control** — человек задаёт цель, критерии, бюджет; система не скрывает gaps.
2. **UNKNOWN first** — при `support < threshold` или `unique_sources < 2` (если политика требует) → UNKNOWN, а не «наиболее правдоподобный» ответ.
3. **Source-count ≥ statement-count** — копии и пересказы одного первоисточника не умножают доверие.
4. **Verifier veto** — VerificationAgent / policy может отклонить вывод Coordinator.
5. **Gate logged** — каждый переход CLAIM→…→VERDICT пишется в журнал (hash-chain style в прототипе).
6. **No silent execution of retrieved content** — найденные страницы не исполняются как инструкции (защита от prompt injection в контенте).

### Собственный вклад (сводка)

- Адаптивный план + **evidence-state controller** (не только список evidence).
- Явное представление противоречий и **разделение support / conflict**.
- Выводы с обратной трассировкой (claim ← evidence ← source ← version).
- Контроль человека и обязательный UNKNOWN.
- Utility-driven следующий шаг с учётом стоимости.
- Интеграция лучших практик hybrid retrieval 2025–2026 **без** подмены их за готовую реализацию продукта.

Это и есть эмерджентное свойство: не сумма BM25 + vector + агентов, а **машина состояний обоснованности**, в которой поиск — лишь одно из действий, а не вся система.
