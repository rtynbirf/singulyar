# ОТЧЁТ_P4.1 — локальный open-model адаптер (такт v10.88 «АДАПТЕР», С63, PAT №24)

Строка карты: Л5 — остаток **P4.1 «Local open-model adapter (layout-conditioned baseline)»** (ТЗ трека, строка 182). Дорога из ОТЧЁТ_P4: «адаптеру остаётся честная обвязка статуса EXPERIMENTAL и контракт на шине». Сделано в этой редакции.

## Что сделано

1. **Канон адаптера** `src/open-model-adapter.mjs` (`open-model-adapter/0.1`):
   - **Разделение труда**: модель решает ГДЕ (маска id'ов регионов), дом решает КАК (позиции — их `baselineDerive` v10.81), применение — только их `applyMaskedRepair` через их `batchRepair` (агент v10.85). Модель не изобретает bbox'ов; гарантия нетронутости удержанных остаётся ихней и проверяется через модельный путь — и ссылками (регион «a» — тот же объект в результате), и байт-в-байт.
   - **Контракт runner**: синхронный, чистый, 0 сети — `runner(промпт) → {ответ: string}|{отказ: причина}`. Асинхронные рантаймы (WebLLM, transformers.js, локальный сервер вывода) гоняются ЗА пределами агентного цикла и приносят «замороженный ответ» (`runner = () => ({ответ: '<текст модели>'})`) — детерминизм по построению. Нет runner'а — нет proposer'а: адаптер не выдумывает ответы за модель.
   - **Промпт** (`собратьПромпт`): layout-conditioned, детерминированный байт-в-байт — фиксированный порядок полей, регионы сортированы по id, замки помечены, инструкция формата одна, ни часов, ни случайности.
   - **Парсер** (`разобратьОтвет`): строго один формат (`["id", …]` или `{"маска": […]}`); сортировка + съедание дублей; замки фильтруются молча (их закон «замки не чинятся никогда») — одни замки → валидное «нечего чинить»; незнакомый id / не-строка / проза / рваный JSON — честный TypeError, адаптер конвертирует его в `{отказ}` и никогда не выбрасывает наружу (агент пишет причину в память раунда).
   - **Регистрация** (`registerOpenModel`): честный true/false без бросков (как их `registerProposer`); имя в их реестре — `open-model/<id>`; коллизия имени — false, полузаписи в ledger нет (их дверь — единственная точка истины). id — буквы/цифры Unicode + `._-` (дом говорит и по-русски).
   - **Ledger** (`списокМоделей`, схема `ladom.open-model.v1`): на импорте пуст — моделей в доме нет, и это честно. Статус модели: `pinned sha256:<хэш>` или `EXPERIMENTAL: без pinned-хэша — модель владельца, дом не проверял веса` (родня А3: без пиннинга статус не завышается).
2. **Минимальный честный патч канона** `src/repair-agent.mjs` (repair-agent/0.1 → пометка listProposers): свежее состояние (одни стоковые) — **дословно прежний** текст и `модели: []`; после регистрации адаптера пометка называет его поимённо («адаптеры: open-model/… — статусы и ledger моделей у их модулей»). Экспорты и импорты канона не менялись — тесты v10.85 не правились и остались зелёными.

## Честные границы

- Веса модели в доме не живут (правда платформы: файл ≤100 МБ, Pages ≤1 ГБ) и не будут: модель приходит готовой через runner от владельца. Адаптер — контракт и обвязка, не мозг.
- Модель без pinned-хэша работает со статусом EXPERIMENTAL — это осознанный постур (владельцево железо — владельцев риск), а не сертификат качества.
- Пиннинг здесь — hex-хэш в ledger; сверка хэша с байтами весов — за рантаймом владельца (адаптер весов не видит).
- Живой прогон с реальной локальной моделью — 👤 владельца (запуск рантайма и подача «замороженного ответа»); машинная часть закрыта тестами с фикстурными runner'ами.
- Парсер НЕ угадывает: ни частичных масок из прозы, ни «похожих» id, ни альтернативных форматов — один формат, остальное честный отказ.
