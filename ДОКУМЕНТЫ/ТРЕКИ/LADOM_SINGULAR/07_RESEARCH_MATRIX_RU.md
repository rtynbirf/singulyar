# Матрица смежных областей и переносимых решений

| Область | Что даёт | Как использовать в нашей системе | Ограничение / тест |
|---|---|---|---|
| LLM spatial planning | Превращение запроса в список сущностей и отношений | Выделять объекты, количества, атрибуты, left/right/behind/inside, запреты | LLM может пропустить объект; проверять полноту по исходному запросу |
| Scene graphs / graph constraints | Явные отношения между сущностями | Узлы=элементы, рёбра=отношения; валидировать циклы/невозможные отношения | Не все отношения можно свести к bbox |
| Layout-to-image | Пространственное управление генерацией | Сцена как редактируемый IR перед рендером | Bbox не описывает все формы и перспективу |
| GLIGEN | Текст + grounding bbox | Вариант архитектуры условного рендерера | Требует соответствующей модели/адаптации; не включается в любую API-модель |
| ControlNet | Дополнительные карты условий: края, глубина, поза, сегментация | Дополнительные управляющие каналы при локальном renderer | Условия могут конфликтовать; тестировать порядок приоритетов |
| BoxDiff | Ограничения положения без переобучения базовой модели | Исследовательский baseline для bbox adherence | Не переносится автоматически на закрытый API Reve |
| DiT / latent diffusion | Масштабируемая генерация пикселей/латентов | Базовые открытые кандидаты renderer | Не доказывает, что Reve использует DiT или конкретный VAE |
| Flow matching | Альтернативный генеративный процесс | Отдельный baseline при выборе open model | Нельзя смешивать терминологию diffusion/flow без изучения checkpoint |
| OCR + text rendering | Точная проверка текста | Сверять требуемую надпись с результатом; для критичного текста — пост-композитинг | OCR сам ошибается, особенно на декоративных шрифтах |
| Object detection / segmentation | Проверка наличия объектов и локальных масок | QA: recall объектов, bbox error, overlap | Детектор может не распознавать редкие/стилизованные объекты |
| Image editing / inpainting | Локальная перегенерация | Исправлять регион, сохраняя остальной кадр маской/композитингом | Контекстные границы могут дать швы; нужна оценка вокруг маски |
| Retrieval/reference conditioning | Сохранение стиля/персонажа/материала | Хранить референсы, их порядок и роли как часть входа | Порядок и вес референсов могут менять результат; протоколировать |
| Human-in-the-loop | Исправление неоднозначностей | Разрешать человеку двигать/удалять/закреплять элементы до рендера | UI должен быть доступен и иметь undo/redo |
| Evaluation science | Отделяет качество от красивой демонстрации | Фиксированный набор сцен, seeds, повторения, слепое сравнение | Одна метрика не измеряет всю полезность |
| Data engineering / data governance | Масштабируемый набор обучающих пар | Версионирование, дедупликация, лицензии, качество аннотаций | «Миллиарды изображений» не гарантируют качественные метки |

## Рекомендуемые измерения

1. **Entity recall:** сколько требуемых объектов реально присутствует.
2. **Count accuracy:** совпадает ли количество экземпляров.
3. **Spatial adherence:** IoU/центр/размер объектов относительно заданных bbox; отдельно тестировать отношения.
4. **Attribute fidelity:** правильны ли цвет, материал, поза, текстура, тип объекта.
5. **Text exact match:** OCR-результат совпадает с заданной строкой; учитывать Unicode и языки.
6. **Reference consistency:** сходство идентичности/стиля с референсом, оценённое отдельно от общего качества.
7. **Edit locality:** изменение внутри целевого региона и побочные изменения вне него.
8. **Human preference:** слепая парная оценка, не подменять её только CLIP/FID.
9. **Cost/latency:** цена за успешный результат, а не только за вызов; учитывать неудачные генерации.
10. **Repeatability:** вариация качества при разных seeds/повторных запросах.
