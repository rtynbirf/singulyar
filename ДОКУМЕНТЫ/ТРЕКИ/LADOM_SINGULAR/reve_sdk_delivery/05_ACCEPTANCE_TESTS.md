# Тесты приёмки

## A. Автономный редактор (без сети)
1. Открыть `ladom-composition-studio.html` локально. Ожидание: UI загружается без ошибок сети.
2. Создать регион. Ожидание: появляется прямоугольник и запись в списке.
3. Выбрать регион и изменить label/prompt. Ожидание: свойства обновляются и экспортируются.
4. Перетащить регион. Ожидание: bbox меняется, остаётся внутри холста.
5. Изменить размер через маркер. Ожидание: ширина/высота не становятся отрицательными или нулевыми.
6. Удалить регион. Ожидание: удаляется и с холста, и из JSON.
7. Экспортировать JSON, импортировать его обратно. Ожидание: число регионов, поля и bbox сохраняются.
8. Импортировать повреждённый JSON. Ожидание: понятная ошибка; текущий проект не затирается.
9. Импортировать bbox за пределами 0..1. Ожидание: отказ или нормализация по заранее документированной политике; не молчаливое принятие.
10. Проверить keyboard-only: фокус видим, поля доступны, кнопки работают. Ограничение: drag мышью в MVP не заменяет альтернативное числовое редактирование; если оно отсутствует, тест фиксирует дефект.

## B. Адаптер API (после подключения реального токена; сейчас НЕ запускался)
11. Проверить минимальный `create_layout` на небольшом prompt.
12. Сохранить реальный response schema и request ID; токен не писать в артефакты.
13. Отредактировать layout и проверить `reconcile_layout` согласно текущей сигнатуре SDK.
14. Выполнить `render_layout`; проверить image bytes/URL и метаданные ответа.
15. Проверить content violation при корректном HTTP статусе, если сервис предоставляет такой тестовый сценарий.
16. Проверить неверный bbox/пустой prompt и убедиться, что клиент валидирует запрос до отправки.
17. Смоделировать timeout, 429, 4xx, 5xx и неизвестное тело ответа.
18. Проверить, что повтор запроса не создаёт непреднамеренных платных дубликатов.
19. Проверить, что токен отсутствует в client bundle, devtools-visible JS constants, логах и сообщениях об ошибке.
20. Провести round-trip `API Layout → local Project → API Layout` и документировать потери полей.
