## Что сделано

**`src/krug-profiles.js`** (`krug-profiles/0.1`) — канон локального круга: один файл, который зал ·17 грузит классическим script-тегом (https и file://), а тесты зовут через node:vm. Чистота как у `sync-crdt.js`: 0 сети · 0 document · 0 eval; хранилище передаётся снаружи адаптером `{load(), save(json)}` — модуль не знает ни DOM, ни localStorage.

1. **Постоянная личность устройства**: `устройство(адаптер)` — ключ 32 hex, переживает перезагрузку (адаптер-память); без памяти адаптера ключ честно живёт сессию (имитаций нет). Случайность подмешивается снаружи (зал подаёт crypto.getRandomValues-путь; без crypto — честный Math.random).
2. **Профиль отношений**: `{ key, имя (≤40), роль (≤12), первая, последняя, встреч, согласие }`. `встреча()` — первая встреча создаёт профиль с согласием «спрошено», повторная обновляет счётчик и «последнюю», «первая» неизменна. Потолок — 64 профиля, переполнение честное: «круг полон — забудь кого-нибудь». Повреждённый став не роняет круг — пересборка снимает мусор и дубли, «невесть-что»-согласие становится честным «спрошено».
3. **Закон согласия** (`повторныйКонтакт()`): незнакомец и «спрошено» → `{ok:false, вопрос:true}` (решает человек); «разрешено» → `{ok:true, рендеву}` — контакт идёт без вопроса; «запрещено» → честный отказ `{ok:false, причина:'запрещено', вопрос:false}` — не молчание; `забыть()` удаляет по-настоящему. Первый контакт — сам явный шаг человека (QR/код/рукопожатие), поэтому запись профиля не спрашивает; спрашивает только ПОВТОРНЫЙ. `согласие()` о незнакомце не выдумывается — сначала встреча.
4. **Рендеву детерминирован**: `рендеву(ключ) = 'krug-' + ключ` — одно имя встречи на ключ хозяина; на нём стоят мост вкладок BroadcastChannel того же браузера (чистый офлайн) и комната trystero-nostr между устройствами (как звонки ·23). Часы в решениях не участвуют: список сортируется по ключу, ts — только данные.

**Зал ·17** — блок «Круг своих» под панелью «Синхрон»:

- **Первый контакт — как было**: QR/код (физика air-gapped WebRTC: SDP свеж при каждой встрече). По открытому P2P-каналу обе стороны обмениваются HELLO (`krugЗдравствуйте`/`krugВстретил`) — профиль записывается обеим сторонам после каждой встречи (встреч++).
- **Повторный контакт — без повторного QR**: «◉ слушать круг» на зале держит рендеву открытым; гость со remembered-профилем жмёт «↩ вернуться в зал» → зов по рендеву → зал по закону согласия: «разрешено» — сразу выносит **свежий оффер WebRTC** через рендеву; «спрошено»/незнакомец — зов встаёт в очередь решения («принять/нет»; «нет» не запрещает навсегда); «запрещено» — честный отказ гостю. Ответ тем же рендеву → канал встаёт как при QR. Двойная доставка (мост+релеи) гасится тихим окном 30 с на ключ; у гостя тайм-аут 20 с с честным текстом («зал молчит — он должен держать „слушать круг“»).
- **Честные пометки**: статус слушания различает «мост вкладок + релеи (сигналинг через интернет, контакт P2P)» и «мост вкладок (релеи не встали)»; при отказе релеев круг продолжает жить в том же браузере.
- STATE/CMD/WebRTC-ручной путь (4b), режим телефона (4c) и Синхрон (4d) не тронуты.

## Честные границы

- **Кросс-устройственный рендеву сигналит через публичные Nostr-релеи** — как звонки ·23 (дом уже принял этот транспорт): сигналинг в релеях виден, но несёт только имена-ключи и свежий SDP; медиа и данные идут P2P. Полный воздух-гэп (ни сети, ни моста) физически оставляет QR — это записано в подсказке зала, не спрятано.
- Профили — локальные по устройству (закон дома: данные живут на устройстве владельца); экспорт/перенос круга между устройствами — не заявлено.
- Имя/роль с другого устройства — самообъявленные (как в ·23); ключ — форма-гард 32 hex, лимиты длины.
- Релеи-путь зал живой поверкой прогнан в двух окнах одного браузера (мост) + отдельно комната релеев поднималась честно; двойной прогон двух ФИЗИЧЕСКИХ устройств — 👤 владельца (нет второго устройства в песочнице).
- Эксперименты согласия на людях, доверие и атаки «много знакомых» — вне такта; потолок 64 — первая честная рейка.

## Проверено боем (живой стенд, два окна)

Живая поверка поймала настоящий баг **до пуша** — он исправлен и закрыт регресс-тестом:

- **Баг**: `устройство()` и профили делили один адаптер как ОДИН слот — запись личности устройства стирала профили (и наоборот); на второй перезагрузке ключ устройства рождался заново, а согласие «разрешено» терялось — повторный контакт ложно спрашивал.
- **Починка**: хранилище — один став `{v:1, профили:[…], устройство:{key,…}}`; `устройство()` читает/пишет своё поле внутри стора, мусор в профилях не роняет устройство (и наоборот).
- **Прогон** (эмуляция второго устройства честной подменой личности через `window.__HALL` — в песочнице нет второго физического устройства):
  - Фаза 1 (первый контакт через рендеву): зов гостя → очередь согласия зала («спрошено» — решает человек) → «принять» → свежий оффер через рендеву → ответ → **dc.readyState=open**, «канал: ● телефон подключён» → рукопожатие HELLO записало профиль (встреч растёт).
  - Фаза 2 (**повторный контакт — критерий P3.1**): согласие обеих сторон «разрешено» → очередь согласия НЕ появлялась — оффер ушёл автоматически → **dc.readyState=open** без QR и без единого клика.
  - Регресс 4d: Синхрон жив рядом (👏 1, сходится) — STATE/CMD не тронуты. Скриншоты: diag/v1084_krug_host.png, diag/v1084_krug_guest.png.
