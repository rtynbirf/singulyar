# Техническое задание SINGULYAR / HIR v0.1.0

## 1. Назначение
Общий runtime связывает намерение, участников, смысловое событие, представление и транспорт. Цель — единая среда совместного действия с контролем человека, локальной работой и доступностью в ядре.

## 2. Обязательные принципы
- Человек управляет намерением, предпочтениями и разрешениями.
- Не назначать человеку диагноз/категорию автоматически.
- Смысл отделён от интерфейса и транспорта.
- Локальные функции работают без сервера там, где это возможно.
- Автономность и сетевые возможности описаны отдельно и тестируются.
- Нет телеметрии и внешних скриптов по умолчанию.
- Все действия доступны клавиатурой; состояния и ошибки доступны вспомогательным технологиям.
- Не заявлять успех без фактического подтверждения.
- Все существенные обещания проходят CLAIM → CODE → SPEC → TEST → RESULT → VERDICT.

## 3. Объём
### MUST
1. Схемы PersonRef, Relationship, Intent, MeaningEnvelope, RepresentationPreference.
2. Manifest модулей: версия, API, capabilities, permissions, storage/network use, a11y modes, tests.
3. Локальный контакт: создать/удалить.
4. Текстовое событие и минимум два представления (текст и TTS при наличии).
5. Крупный текст, контраст, reduced motion, клавиатурная навигация.
6. IndexedDB persistence и миграции схем.
7. Экспорт/импорт с валидацией.
8. Матрица автономности для каждого сценария.
9. Контрактные тесты и базовый accessibility smoke test.
10. Threat model, политика хранения/удаления.

### SHOULD
- Очередь исходящих событий с состояниями local/queued/sent/delivered/failed/unknown.
- Идемпотентная повторная доставка.
- Резервное копирование по выбору пользователя.
- Совместимость с текущими модулями ·19 ЧЕЛОВЕК, ·21 ОБЩЕНИЕ, ·22 СВЯЗЬ, ·30 ТКАНЬ и ядром.

### MAY после MVP
- WebRTC DataChannel, аудио/видеозвонки, собственная relay-инфраструктура.
- CRDT для подтверждённых сценариев конкурирующего редактирования.
- Брайль/тактильный вывод при наличии оборудования.
- Офлайн ASR/OCR/TTS как сменные адаптеры после оценки ресурсов и лицензий.

### Не входит в MVP
Автоматическое распознавание жестового языка камерой, собственная криптография, обязательные аккаунты/SMS/CAPTCHA для локального использования, автоматические необратимые действия ИИ, обещание удалённого общения без канала связи.

## 4. Функциональные требования
FR-01 Пользователь вводит намерение свободным текстом.
FR-02 Исходный текст отделён от предложенной интерпретации.
FR-03 Внешнее действие не выполняется без подтверждения.
FR-04 Контакт можно создать и удалить.
FR-05 Удалённая связь требует явного согласия участников.
FR-06 Сообщение хранится как MeaningEnvelope, не как HTML.
FR-07 Представление можно менять без изменения исходного события.
FR-08 Недоступность представления вызывает понятный fallback.
FR-09 Данные можно экспортировать и удалить.
FR-10 Импорт проверяет схему, размер и типы.
FR-11 Транспорт сообщает реальное состояние.
FR-12 Отзыв отношения прекращает доступ по определённым правилам.
FR-13 «Сохранено локально» не равно «доставлено».
FR-14 Ошибки доступны через семантические роли и live regions.
FR-15 Настройки согласованно применяются к поддерживаемым модулям.

## 5. Нефункциональные требования
- NFR-01 Нет сторонних скриптов в базовом ядре.
- NFR-02 Все сетевые запросы документированы.
- NFR-03 Цель — WCAG 2.2 AA, подтверждаемая ручными и автоматизированными тестами.
- NFR-04 Полная клавиатурная навигация и видимый фокус.
- NFR-05 Масштаб 200% без потери функций.
- NFR-06 Ошибки хранения/миграции не приводят к молчаливой потере данных.
- NFR-07 Сообщения не попадают в диагностические логи по умолчанию.
- NFR-08 База security verification: OWASP ASVS 5.0.0 с применением релевантных требований.
- NFR-09 Каждая сборка имеет версию, commit ID и тестовый отчёт.

## 7. Приёмка
- Все MUST требования покрыты автоматическими или документированными ручными тестами.
- Сценарии создания, чтения, экспорта и удаления проходят без критических ошибок.
- Ни одна операция не объявляется доставленной без подтверждения транспорта.
- Переключение представления сохраняет исходное событие.
- Проверены клавиатура, экранный диктор, контраст, масштабирование, reduced motion.
- Сетевые запросы инструментально проверены.
- Известные ограничения опубликованы в отчёте.
