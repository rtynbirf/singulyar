# ПОЛНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) НА РАЗРАБОТКУ «SINGULYAR OS v2.0»

## 1. ЦЕЛЬ И НАЗНАЧЕНИЕ СИСТЕМЫ
**«СИНГУЛЯР»** — это суверенный автономный мультимедийный веб-организм (**Single-File Ambient Intent Organism**), функционирующий в формате **одного физического HTML-файла**, не требующий наличия сети Интернет, внешних серверов, облачных баз данных или сторонних API.

---

## 2. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ ТРЕБОВАНИЯ

### 2.1. PWA & Offline Storage Architecture
* **Единый файловый бандл:** Весь исполняемый код (HTML, CSS, JS, Wasm-модули, SVG-векторы) запекается в монолитный файл без внешних сетевых зависимостей.
* **Self-Healing Service Worker:** Наличие встроенного инлайн-Service Worker с стратегией **Cache-First** и регулярной проверкой контрольных сумм по хэш-цепи SHA-256.
* **Persistent Quota Storage:** Хранение минусовок (62 фонограммы) и слоговых матриц (200+ языков) в **Origin Private File System (OPFS)** и `IndexedDB` с запросом прав `navigator.storage.persist()`.

### 2.2. Audio-DSP & Real-Time Pitch Processing
* **Изоляция AudioWorklet:** Вынос всего FFT-анализа, отслеживания фундаментальной частоты ($F_0$) вокалиста и алгоритмов автокорреляции YIN/KissFFT из главного потока (Main Thread) в отдельный `AudioWorkletGlobalScope`.
* **Субкадровый Вайп Субтитров:** Рендеринг запекания текста песен (UltraStar-стиль) через `performance.now()` и `requestAnimationFrame` с интерполяцией при частоте обновления экрана 60–120 Гц.

### 2.3. P2P Mesh & Air-Gapped Communication
* **Zero-Server WebRTC Handshake:** Установка бессерверного соединения между ТВ-экраном (дверь `·17`) и мобильным пультом (дверь `·44`) посредством считывания анимированного QR-кода со сжатым SDP-Offer/Answer.
* **CRDT Data Consistency:** Использование конфликно-устойчивых типов данных (**LWW-Element-Set CRDT**) с часами Лампорта для локального автономного кошелька (`·25`), чатов (`·23`) и журнала событий.

### 2.4. Intent-Driven UX (HIR Runtime)
* **Интерпретатор Намерений (Нить Ариадны):** Замена классической навигации на гибридный рантайм `HIR` (`·41`), разбирающий естественные текстовые/головые фразы человека в цепочки активации дверей с использованием локального TF-IDF / N-gram векторизатора.

## 3. ПОДВЕРНЫЙ РЕЕСТР И ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ ВСЕХ 41 ДВЕРЕЙ

### КЛАСТЕР 1: FLOW & ATHLETE (Вокально-Сценическое Ядро)
1. **·01 КОГДА ТЕРЯЕМ** — Флагманский модуль. Подключение Lazy-Hydration Canvas и Lazy AudioContext.
2. **·02 РЕЗОНАНС** — Колесо 157 голосов. Маскирование слов на WebGL Fragment Shader / CSS `mask-image`.
3. **·02б ФАБРИКА** — Эмерджентный конвейер. Отрисовка DAG-графа сборки аранжировки в реальном времени.
4. **·15 ОРКЕСТРАТОР** — Реестр 62×13. Алгоритм WSOLA SoundTouch для изменения питча без формантных искажений.
5. **·16 СУФЛЁР** — Вокальный оцениватель. C/WASM YIN Pitch Detector в `AudioWorklet` с `SharedArrayBuffer`.
6. **·31 ЛАДОМ** — Консоль вечера. Разделение Core Model Store и View Layer.
7. **·32 СЦЕНА** — Вайп субтитров. Привязка к `AudioContext.currentTime` с отрисовкой через `requestAnimationFrame`.

### КЛАСТЕР 2: AURA & ATLAS (Языки & Фонетика)

9. **·21 ОБЩЕНИЕ** — Мультисенсорность. Каскадный fallback: Haptics для Android, Screen Flash Pulse для iOS.
10. **·36 СЛОВАРЬ** — Префиксный поиск. Структура данных Trie для мгновенного поиска за $O(L)$.
11. **·37 О ДОМЕ** — Интерактивный онбординг. 3-шаговый симулятор суверенного пения.
