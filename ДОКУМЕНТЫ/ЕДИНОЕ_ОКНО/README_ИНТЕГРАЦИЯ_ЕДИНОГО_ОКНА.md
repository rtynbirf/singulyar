# Интеграция «Единого окна коммуникации» в Singulyar

## Что добавлено
- `СИНГУЛЯР_43_ЕДИНОЕ_ОКНО_КОММУНИКАЦИИ.html` — автономная mobile-first страница, 13 категорий, поиск, фильтры, выбор намерения и ссылки на существующие двери проекта.
- Существующие возможности не заменяются и не копируются внутрь нового модуля: страница служит навигационным слоем поверх `·19 ЧЕЛОВЕК`, `·20 ФОНЕТИКА`, `·21 ОБЩЕНИЕ`, `·22 СВЯЗЬ`, `·23 КРУГ`, `·24 ПОЧТА`, `·25 КОШЕЛЁК`, `·26 ЛИНИЯ`, а также `·18 СОБЫТИЕ`.

## Важно: статус
Это **аддитивный интеграционный deliverable**, не утверждение, что файл уже опубликован в GitHub Pages. В этой сессии не было доступа на запись в репозиторий, поэтому исходные файлы и live-сайт не изменялись.

## Установка в репозиторий
1. Скопировать HTML в корень репозитория без переименования.
2. В `index.html` добавить одну карточку/ссылку «ЕДИНОЕ ОКНО КОММУНИКАЦИИ ·43» на `СИНГУЛЯР_43_ЕДИНОЕ_ОКНО_КОММУНИКАЦИИ.html`.
3. Если двери регистрируются в `singulyar-modules.js` или в реестре версий, добавить запись только после проверки схемы актуального манифеста; не выдумывать поля и не менять существующие идентификаторы.
4. Проверить правила кэширования `sw15.js`. Если HTML включается в precache, обновить список и поколение кэша согласно действующему протоколу проекта.
5. Пройти проверки ниже, затем опубликовать обычным workflow проекта.

## Принцип маршрутизации
- Смысл/намерение не зависит от канала.
- Класс средства не смешивается с брендом приложения: WhatsApp, Telegram, Signal и т. п. перечислены как примеры мессенджеров.
- Получатель выбирает представление; для этого используются существующие `·19 → ·21 → ·22`.
- Деньги — отдельный класс передачи ценности, привязанный к `·25 КОШЕЛЁК`. Карточные/банковские рельсы не помечаются подключёнными, пока это не подтверждено кодом и тестом.
- Внешние сервисы обозначены как внешние; карточка не создаёт впечатление, что интеграция уже существует.
- Физические сигналы, бумага, наличные, бартер и массовое вещание остаются в общей карте, хотя не являются функциями веб-приложения сами по себе.

## Приёмочные проверки
1. Страница открывается локально как одиночный HTML; сетевые запросы не требуются для основной навигации.
2. Поиск находит категории и термины, включая «наличные», «бартер», «жестовый язык», «SMS», «Telegram».
3. Фильтры «Лично», «Цифровые», «Деньги и ценность», «Доступность», «Публичные» не удаляют данные — только фильтруют видимость.
4. Сервисы одного класса показаны внутри одной категории, а не как самостоятельные классы коммуникации.
5. Ссылки `·18–·26` открывают правильные файлы из корня сайта.
6. На экране 360×800 px видны заголовок, поиск, фильтры, выбор намерения и начало сетки; категории раскрываются внутри той же страницы.
7. Проверить клавиатурную доступность, видимый фокус, масштабирование текста и `prefers-reduced-motion`.
8. Проверить PWA/service worker: новая дверь не должна ломать офлайн-кэш или существующие маршруты.
9. Не заявлять работу внешних платежей, социальных сетей или обычной телефонной сети без интеграции и доказательства тестом.

## Ограничение
Это карта и маршрутизатор по имеющимся дверям, а не автоматический универсальный шлюз в сторонние платформы. Реальные интеграции добавляются адаптерами с явным статусом, разрешениями пользователя, тестами доставки и понятным fallback.
