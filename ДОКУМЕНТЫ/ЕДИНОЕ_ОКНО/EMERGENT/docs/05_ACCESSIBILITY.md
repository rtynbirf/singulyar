# 05 — Доступность как системный контракт

Цель разработки — ориентир WCAG 2.2 AA и WAI-ARIA APG, но соответствие не сертифицировано. Проверять фактические пользовательские пути.

- Семантические HTML controls прежде чем ARIA; каждый input имеет label.
- Полный клавиатурный доступ, логичный порядок фокуса, видимый focus indicator, skip link.
- Статусы и динамические результаты объявляются через подходящие live regions; не перемещать фокус неожиданно.
- Не использовать цвет как единственный носитель смысла; контраст и масштабирование 200%+.
- Для видео предусматривать субтитры/текст; для изображений — текстовые описания; для аудио — транскрипт, где возможен.
- Слепому пользователю не предлагать «прочитайте справку» как единственную помощь; ключевые действия и состояния должны озвучиваться и быть доступны с клавиатуры.
- Глухому пользователю — текстовый путь, визуальный статус, субтитры/транскрипт; жестовый перевод в MVP может быть человеческим, не заявлять AI распознавание.
- Неговорящему пользователю — текст/AAC и необязательный TTS с выбором голоса; TTS — не подмена права говорить своим способом.
- Для тактильного вывода/Брайля — только через реальную поддержку устройства и адаптер, с тестом; нельзя изображать поддержку без оборудования.
- Уважать предпочитаемую модальность, но не хранить диагноз как необходимое поле. Способность и предпочтение — изменяемая настройка.
- Протестировать сценарий: глухая бабушка + слепой дедушка, который может говорить/использовать согласованные тактильные сигналы + неговорящая внучка. Не предполагать, что все трое владеют одинаковыми каналами.

## Ручная проверка перед релизом

Клавиатура без мыши; NVDA + Firefox/Chrome; VoiceOver + Safari; TalkBack + Android; увеличение/перенос текста; reduced motion; контраст; диктовка/TTS по разрешению; пользовательское тестирование с людьми с инвалидностью. Автоматический сканер — только один из источников.
