# 08 — Карта интеграции и сохранение предложенных направлений

## Инвариант

Не выбрасывать каталог коммуникации, единое окно, деньги/ценность, доступность, поиск и композицию преобразований. Но размещать их на правильных слоях: каталог ≠ транспорт, бренд ≠ класс, intent ≠ сообщение, сообщение ≠ платёж.

## Полный каталог классов

1. Личное присутствие: речь, жесты, мимика, письмо, рисунок, тактильные сигналы.
2. Телефонная сеть: вызовы, SMS, MMS, USSD.
3. Мессенджеры: конкретные приложения относятся к этому классу, не являются отдельными типами коммуникации.
4. Видеосвязь.
5. Электронная почта.
6. Социальные сети.
7. Фото, видео, аудио, документы, ссылки, физические носители.
8. Форумы и сообщества.
9. Публичное вещание и стримы.
10. Совместная работа: документы, доски, задачи, календари, игровые среды.
11. Доступность/преобразование: субтитры, STT/TTS, OCR, Брайль, AAC, экранный диктор, тактильный вывод.
12. Передача ценности: наличные, банковские/мобильные переводы, карты, QR, счета, чаевые, подарки, пожертвования, долг, заём, бартер.
13. Человек—машина: голосовые интерфейсы, устройства и ассистивные технологии.

## Конфликт нумерации и навигация

В текущем доме уже заявлено 43 двери. Поэтому предыдущий файл `СИНГУЛЯР_43_ЕДИНОЕ_ОКНО_КОММУНИКАЦИИ.html` нельзя регистрировать как новую дверь. Использовать его можно только как reference mockup. Правильная точка входа — существующее поле намерения в hub / ·41 НАМЕРЕНИЕ, а реализация должна быть композицией существующих ·29 СВОБОДА, ·30 ТКАНЬ, ·21 ОБЩЕНИЕ, ·22 СВЯЗЬ и подтверждённых адаптеров.

## Поиск

«Поиск по всему Singulyar» делается через индекс собственных сущностей/событий и connector-specific search API там, где он разрешён. Не обещать глобальный поиск внутри закрытых сервисов без их API и разрешения. Результат должен показывать источник, дату, права доступа и доступность офлайн.
