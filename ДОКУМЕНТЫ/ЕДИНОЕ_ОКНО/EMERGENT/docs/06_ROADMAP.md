# 06 — Дорожная карта с воротами готовности

Оценки — порядок работ, не обещание сроков. Один этап не считается завершённым без тестов и проверяемого артефакта.

## Этап 0 — Разведка текущего проекта

- Получить точную копию актуальной ветки/commit и список всех HTML/JS/CSS/Service Worker.
- Построить инвентарь страниц, глобальных переменных, событий, storage keys, навигации и API каждого нужного модуля.
- Выполнить smoke tests опубликованной страницы и зафиксировать baseline.
- Результат: `CURRENT_STATE.md`, file/function map, список рисков и точек интеграции.
- Gate: ни одна интеграция не заявляется без доказанного entrypoint/контракта.

## Этап 1 — Семантическое ядро

- Версионируемая схема intent/event, capability manifest, delivery states, provenance.
- Контрактные тесты и обратная совместимость.
- Gate: schema validation + тесты отказа/неизвестного статуса.

## Этап 2 — Реальная интеграция интерфейса

- Встроить UI в существующую навигацию, переиспользовать дизайн-токены и события.
- Изолировать CSS/JS от глобальных имён; не переписывать существующие модули.
- Интегрировать `·19 ЧЕЛОВЕК`, `·21 ОБЩЕНИЕ`, `·22 СВЯЗЬ`, `·18 СОБЫТИЕ`, `·23 КРУГ` по подтверждённым API; остальные подключать по контрактам.
- Gate: regressions baseline, доступность, работоспособность старых функций.

## Этап 3 — Offline-first и память

- IndexedDB repository, export/import, схема миграции, retention/delete.
- Queue только для действий, безопасных к повтору; никаких «платёжных retry» без provider idempotency.
- Gate: offline, quota error, corruption recovery, delete test.

## Этап 4 — Первый настоящий транспорт

- Выбрать один адаптер по пользе и доступности API: вероятный кандидат Matrix для федеративного общения либо email; принять решение через ADR.
- Вынести connection/auth в adapter; показывать сервер, privacy, capabilities и реальный delivery status.
- Gate: integration tests на тестовом сервере; credential lifecycle; ошибки и повтор.

## Этап 5 — Преобразования доступности

- TTS/STT capability detection; ручной текстовый путь обязателен.
- Подключать OCR/офлайн-распознавание только как opt-in; показывать неопределённость и не отправлять результат без подтверждения.
- Gate: тесты со вспомогательными технологиями и пользовательские проверки.

## Этап 6 — Социальная федерация, звонки, ценность

- ActivityPub для публикаций, WebRTC только после signalling/security design.
- Денежные операции — внешний провайдер и отдельный юридико-безопасностный review; прототип не обрабатывает деньги.
- Gate: threat model, независимый security review, provider sandbox, повтор/двойная операция.

## Этап 7 — Релиз

- SBOM, лицензии, версия, миграции, release notes, rollback, backup/restore, доступность, threat model, нагрузочные/совместимость тесты.
- Gate: нулевые P0/P1 дефекты; результаты проверок опубликованы; известные ограничения доступны пользователю.
