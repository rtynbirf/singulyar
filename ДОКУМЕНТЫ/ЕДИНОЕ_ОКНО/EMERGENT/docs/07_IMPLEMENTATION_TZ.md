# 07 — Техническое задание исполнителю

## Deliverable

Pull request в исходный репозиторий Singulyar, не отдельный сайт; архив документации и воспроизводимые тесты. До получения/проверки исходников не выдумывать имена файлов и не вставлять модуль вслепую.

## Обязательная последовательность

1. Зафиксировать commit, дерево репозитория, окружение и команды запуска.
2. Составить `CLAIM → CODE → OFFICIAL SPEC → TEST → VERDICT` для каждого существенного утверждения.
3. Найти реальные entrypoints и API модулей `·15`, `·17–·26`, КРИСТАЛЛ, ФАБРИКА, ПАМЯТЬ; неизвестное маркировать UNKNOWN.
4. Реализовать адаптер интеграции с существующим роутером/навигацией, без дублирования существующих функций.
5. Добавить feature flag и rollback; не ломать offline/PWA и текущие service worker caches.
6. Внедрить schema, capability manifest, explicit consent gate, delivery state, event log.
7. Добавить тесты на old routes, current functions, local draft, export, no-consent, adapter unavailable, network offline, duplicate action, invalid schema.
8. Выполнить keyboard/screen reader checks и security review.
9. Предоставить список файлов/строк, команды, выводы тестов, скриншоты при необходимости, hash commit и known gaps.

## Критерии приёмки

- Существующие функции не удалены и regression suite проходит.
- При отсутствии API/сети система честно сообщает, что транспорт недоступен.
- Любая отправка требует явного подтверждения.
- События не смешивают намерение, факт попытки, принятие провайдером и доставку адресату.
- Пользователь может отменить/удалить черновик, экспортировать данные и понять, где они хранятся.
- Нет неподтверждённых обещаний E2EE, федерации, оплаты или доступности.
- Протокол и тесты документированы, есть миграционный план и rollback.
