# Интеграция в исходный Singulyar

Этот архив подготовлен как воспроизводимый пакет прототипа и проектной документации. Публичный hub, README и страницы ·21/·22 проверены 14.10.2026; актуальный проект уже имеет intent route, ·29 СВОБОДА, ·30 ТКАНЬ, ·41 НАМЕРЕНИЕ, ·53 СВЯЗЬ ЧЕЛОВЕКА и ·54 ПИР. **Архив не изменяет live-сайт и не включает полный pinned checkout.** Чтобы безопасно сделать интеграционный PR:

1. Синхронизировать точный актуальный commit репозитория; сверить `data/versions.json`, `singulyar-modules.js`, service worker cache version и фактическую версию hub. Устранить обнаруженное расхождение между hub v11.32, README v11.33 и `docs/СИНТЕЗ.md` v10.61.
2. Сохранить baseline тестов и снимки текущего поведения. Не назначать `·43`: в текущем проекте 43 двери уже есть.
3. Reuse existing hub intent field and ·41 НАМЕРЕНИЕ as the entrypoint; reuse ·29 СВОБОДА for composition and ·30 ТКАНЬ for transport/fabric after code review. Найти фактические контракты `·15 ОРКЕСТРАТОР`, `·18 СОБЫТИЕ`, `·19 ЧЕЛОВЕК`, `·21 ОБЩЕНИЕ`, `·22 СВЯЗЬ`, `·23 КРУГ`, `·24 ПОЧТА`, `·25 КОШЕЛЁК`, `·26 ЛИНИЯ`, а также КРИСТАЛЛ/ФАБРИКА/ПАМЯТЬ.
4. Не копировать прототип поверх существующей страницы. Перенести его UI в существующую навигацию, использовать текущие CSS tokens и event APIs.
5. Инкапсулировать CSS/JS; избежать глобальных имён; сохранить service worker cache/update strategy.
6. Подключать adapters по одному, сначала local draft, затем выбранный транспорт. Для каждого указать capabilities/status/privacy/permissions.
7. Выполнить `node tests/core.test.js`, затем проектные tests, ручные accessibility и security tests.
8. В PR включить diff, test logs, список проверенных/непроверенных claims и план rollback.

До шага 3 любой точный файловый путь интеграции будет догадкой, поэтому в этом пакете его намеренно нет.
