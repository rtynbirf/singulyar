# Singulyar Emergent — прототип, ТЗ и план интеграции

**Срез подготовки:** 14 октября 2026. **Статус:** инженерный пакет и локально запускаемый прототип; не production-мессенджер. Архив не изменяет опубликованный GitHub Pages сайт автоматически.

## Быстрый запуск

1. Распакуйте архив.
2. Откройте `prototype/index.html` в актуальном браузере. Для локального прототипа сервер не обязателен; если браузер ограничивает локальные функции, запустите `python -m http.server 8080` из корня пакета и откройте `http://localhost:8080/prototype/`.
3. Для проверки ядра установите Node.js 20+ и выполните `./verify.sh`. Полная проверка JSON Schema дополнительно использует Python `jsonschema` (если пакет установлен). Если Chromium доступен, `./verify.sh` автоматически запускает 7 браузерных сценариев; детали ограничения storage shim — в `docs/14_BROWSER_E2E_RESULTS.md`.

## Что реально работает в этом пакете

- Интерактивный сценарий выбора намерения, адресата, срочности и модальностей.
- Каталог 13 классов коммуникации, где класс не смешан с брендом приложения.
- Объяснимые предложения способов связи, ранжирование по модальностям/срочности, ручной выбор, локальный черновик и экспорт JSON.
- Единый runtime-контракт события, встроенная проверка перед сохранением/экспортом, JSON Schema и capability ID/status в предложении.
- Исправлена ошибка устаревшего снимка: экспорт и сохранение всегда берут текущие поля формы; локальный черновик можно явно восстановить.
- Явный статус «не отправлено»; никаких скрытых сетевых вызовов или реальных платежей.
- Реестр адаптеров со статусами и явной границей между локальной возможностью, требующей проверки возможностью устройства и неподключённым транспортом. Тесты контракта и документация интеграции.
- Добавлен integration candidate `integrations/intent-composition-panel.js` под реальные селекторы существующего hub и инструкция подключения `integrations/INTEGRATION_PATCH_GUIDE.md`.
- Сохранены предыдущие HTML-артефакты в `integrations/` как материалы, а не как доказательство интеграции.

## Основная идея

Singulyar — не новый универсальный чат, который пытается заменить все приложения. Это **среда выбора и композиции коммуникации**: человек формулирует намерение; система предлагает способы на основании доступности, отношений, контекста и возможностей устройств; человек подтверждает; адаптер исполняет; журнал показывает результат и происхождение данных.

`Человек → Отношение/Круг → Намерение → Контекст и доступность → Выбор человека → Адаптер/транспорт → Подтверждённый результат → Память по разрешению`.

## Важное по реальному проекту

Публичный hub и GitHub README были просмотрены 14.10.2026; текущий проект уже содержит поле намерения, ·29 СВОБОДА (Composition Engine), ·30 ТКАНЬ, ·41 НАМЕРЕНИЕ, ·53 СВЯЗЬ ЧЕЛОВЕКА и ·54 ПИР. Модуль ·21 уже преобразует смысл в доступные представления, а ·22 объявляет девять каналов и fallback к тексту. Поэтому этот прототип не должен становиться ещё одной дверью или заменять эти модули: его роль — тестовый composer/реестр возможностей, который необходимо встроить за существующим полем намерения и связать с существующими контрактами. Детали с источниками и границами проверки — `integrations/CURRENT_REPO_AUDIT.md`.

**Номер ·43 не назначать:** он конфликтует с текущим счётчиком дверей. Сохранённый `legacy-proposal-43.html` — только исторический артефакт. Полная интеграция в live-сайт не произведена, потому что для безопасного изменения нужен pinned checkout, тестирование и commit/PR; архив содержит исполняемый прототип и реализационный пакет, а не притворяется уже опубликованным изменением.

Смотрите `docs/00_STATUS_AND_EVIDENCE.md` первым, затем `docs/12_REPAIR_REPORT.md` — отчёт об исправлениях и границах тестирования. Текущий результат: unit/contract — 14/14; Chromium browser-flow — 7/7. Это не означает тестирования опубликованного сайта: тест использует in-memory storage shim, а исполняемый regression на pinned commit исходного репозитория ещё не подтверждён. Подробности — `TEST_RESULTS.txt` и `docs/14_BROWSER_E2E_RESULTS.md`.
