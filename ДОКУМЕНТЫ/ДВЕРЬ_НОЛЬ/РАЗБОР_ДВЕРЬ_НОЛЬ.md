## 2. Честные столкновения с законами дома (решает владелец)

1. **Нумерация.** Коллегиальный шифр «Дверь 53» занят: в доме живёт **·53 СВЯЗЬ ЧЕЛОВЕКА** (реестр: дверей 52, дверей_человек «хаб + 52», есть ещё ·54 ПИР и ·55 ЕДИНОЕ ОКНО). Door Zero по своей сути — дверь ВНЕ реестра контента, поэтому счётчики дома она не трогает, если её в реестр не вносить. Честное имя — не «53», а место за нумерацией (например «дверь ∅ / PID 0»); номер — слово владельца.
2. **Статусы 204/403 Void — это сервер.** Дом стоит на GitHub Pages: статика без сервера, `curl -X POST → 403` и `204 No Content` там не родить. В доме контракт переводится в статику честно: страница-пустота (0 веса, CSP постур А, noindex, не в навигации, не в поиске) + boot-страж в CI; полный контракт 204/403 требует отдельного серверного репо (`rtynbirf/door-zero` по эскизу коллеги) — решение владельца.
3. **C-03 «не имеет владельца».** В доме Хозяин один — Человек; и ни одна дверь не «принадлежит» агенту. Формулировка коллеги в доме уточняется: у Door Zero нет агента-ответственного, но хозяин у дома есть — всегда.
4. **«Назначить ни одного ответственного» vs Директива 1 роя.** Совместимо: шаг появления Door Zero вписывается в карту (факт), сама дверь в обслуживании роя не состоит — «один факт — одно место».
5. **Фаза 5 «заморозка: любой PR → 403 Void».** В доме заморозка живёт строкой «что НЕ делается» в карте агентов (образец: запрет агрессивного skipWaiting) + стражем, не серверным кодом.
6. **Эскиз `door-zero.yml`** коллеги использует голый `actions/checkout@v4` — в доме действует закон С128 (пины экшенов по SHA, v7.0.1). Если дом возьмёт эскиз — пины по С128 обязательны.
