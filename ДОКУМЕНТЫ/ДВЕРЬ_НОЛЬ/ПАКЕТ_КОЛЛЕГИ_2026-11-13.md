## 📄 ДОКУМЕНТ 1. ТЕХНИЧЕСКОЕ ЗАДАНИЕ

**Шифр:** `TZ-DOOR-ZERO-001`
**Название:** «Дверь 53 / PID 0 / Нулевой пользователь»
**Заказчик:** rtynbirf (Сингуляр)
**Исполнитель:** Полимат-Улей (рой автономных агентов)
**Статус:** к исполнению

### 1. Цель
Добавить в «Сингуляр» **нулевую точку**, которая:
- не является дверью в контент,
- не требует пользователя,
- не собирает метрики,
- но **без которой система не считается собранной**.

Аналог: `PID 0` (`swapper/sched`) в Linux — невидим, без файлов, без логов, но `PID 1` без него не стартует.

### 2. Область работ
- Репозиторий: `rtynbirf/singulyar` (и/или новый `rtynbirf/door-zero`)
- Не трогать: 52 существующие двери, 64 песни, 200 языков — они остаются как есть.
- Добавить: **53-ю дверь** — `Door Zero`.

### 3. Функциональные требования

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-01 | Дверь Zero видна в карте системы (`/map`, `/doors`), но **недоступна** через обычную навигацию | Must |
| F-02 | При «входе» в Дверь Zero **не отдаётся контент**. Возвращается `204 No Content` (или аналог) и `exit code 0` | Must |
| F-03 | Дверь Zero **не принимает аргументов** (как `void f(void)`) | Must |
| F-04 | Дверь Zero **не логирует** посещения. Ноль телеметрии | Must |
| F-05 | Удаление Двери Zero **ломает boot-проверку** системы (аналог kernel panic) | Must |
| F-06 | Дверь Zero **нельзя заполнить контентом** — API отклоняет `POST/PUT` с `403 Void` | Must |
| F-07 | Дверь Zero доступна только по прямому URL, не индексируется | Should |
| F-08 | Наличие Двери Zero отображается в `STATUS.md` как `DOOR_ZERO: present` | Should |

### 4. Нефункциональные требования
- **N-01:** офлайн-совместимость (без внешних CDN, без сети).
- **N-02:** вес Двери Zero ≤ 1 KB кода (пустота должна быть лёгкой).
- **N-03:** отсутствие зависимостей от фреймворков.
- **N-04:** документация на русском + английском (200 языков — не обязательно для нулевой двери).

### 5. Ограничения
- **C-01:** Дверь Zero **не должна** становиться «ещё одной фичей». Она не продаётся, не анонсируется, не имеет landing page.
- **C-02:** Никаких A/B-тестов, никакой аналитики, никаких «улучшений UX».
- **C-03:** Дверь Zero **не имеет владельца**. Ни один агент не «отвечает» за неё. Это её суть.

### 6. Критерии приёмки
1. `make check` проходит с `DOOR_ZERO=present`.
2. `make check` **падает** с `DOOR_ZERO=removed` (симуляция).
3. `curl -X POST /door-zero` → `403 Void`.
4. `curl /door-zero` → `204 No Content`, тело пустое, заголовки без `Set-Cookie`, без `X-Tracking`.
5. В логах — **ноль** записей о посещении Двери Zero.
6. Ревью роя: ≥ 2 агента подтверждают, что «нечего улучшать».

### Ключевые документы — что в них

**`README.md`** (коротко):
> Дверь Zero. Не содержит контента. Не собирает данных. Не имеет владельца. Существует, чтобы система знала: есть место, куда не надо. Удаление ломает boot.

**`DECISIONS.md`**:
> - D-01: Дверь Zero не заполняется контентом. Причина: заполнение превращает пустоту в функцию.
> - D-02: Дверь Zero не имеет ответственного. Причина: ответственность — это владение, а владение — это контент.
> - D-03: Дверь Zero заморожена. Причина: улучшение пустоты — это её уничтожение.

**`CONTRIBUTING.md`**:
> Любой PR, изменяющий `door-zero/`, получает `403 Void`. Это не баг. Это контракт.

**`.github/workflows/door-zero.yml`** (эскиз):
```yaml
name: door-zero
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Boot check (present)
        run: make check_door_zero
      - name: Void check (removed must fail)
        run: |
          mv door-zero/void.txt /tmp/void.txt
          ! make check_door_zero
          mv /tmp/void.txt door-zero/void.txt
```

## 🎯 ЧТО РОЙ ДОЛЖЕН ПОНЯТЬ ИЗ ЭТОГО

1. **Дверь Zero — не фича.** Её нельзя «улучшить», «монетизировать», «наполнить смыслом».
2. **Она — `PID 0`.** Её нет в `ps`, но без неё `PID 1` не стартует.
3. **Критерий успеха — не «работает», а «нечего улучшать».**
4. **Критерий провала — если кто-то захочет туда что-то положить.**

Пакет готов к передаче. Если хочешь — разложу это по конкретным issue в `rtynbirf/door-zero` или сгенерирую `door-zero.yml` целиком под ваш CI. =)
