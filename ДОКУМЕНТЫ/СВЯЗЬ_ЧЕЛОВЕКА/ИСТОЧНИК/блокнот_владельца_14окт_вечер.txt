Схема работы и машина состоянийПри передаче объекта через WebRTC-адаптер проходит следующая цепочка переходов:draft — Пользователь создает объект (text, file, call_invite, value_intent).locally_saved — Объект фиксируется в локальном хранилище, рассчитывается 64-символьный SHA-256 манифест.queued — Адаптер проверяет готовность P2P-канала (WebRTCAdapter.probe()).attempting — Выполняется установка SDP-сессии и ICE-кандидатов (RTCPeerConnection).accepted_by_transport — Объект передан в бинарный или текстовый поток RTCDataChannel.acknowledged_by_recipient — Удаленный узел получает пакет, проверяет SHA-256 хеш манифеста и отправляет обратно системное квитирование (ACK).3. Локальный нейро-адаптер представлений (On-Device AI Representation Transformer)Проблема: Сенсорные и коммуникационные ограничения человека (зрение, слух, моторные навыки, когнитивная нагрузка) требуют непрерывной адаптации формата.Сингулярное решение: Интеграция компактных локальных нейросетей (WebNeuralNetwork API / ONNX Runtime WASM) непосредственно в слой Representation Selector.Как это работает: Без отправки данных в облако локальный модуль автоматически транслирует намерение:Текст $\rightarrow$ Глубокая выжимка / Пиктограммы (для снижения когнитивной нагрузки);Голос $\rightarrow$ Субтитры в реальном времени;Текст $\rightarrow$ Жестовый язык (3D-аватар) или вибро-тактильный паттерн (Haptic Feedback API) для слабослышащих и слабовидящих.3. Нулевое разглашение в отношениях (Zero-Knowledge Relationship Policy)Проблема: Список контактов и история общения раскрывают социальный граф человека третьим лицам.Сингулярное решение: Внедрение криптографии с нулевым разглашением (ZKP) в Relationship Store.Как это работает: Собеседники доказывают друг другу наличие права на связь (например, «я вхожу в твой круг доверия» или «у меня есть одноразовый токен»), не раскрывая свой реальный публичный ключ, имя или социальные связи промежуточным узлам. Контракт общения (например: "принимать только текстовые выжимки до 300 символов в рабочее время") исполняется локальной политикой Policy Engine до отображения пользователю.4. Самовосстанавливаемый отчуждаемый бандл (Signed Web Bundle & IPFS/DAT Mesh)Проблема: Зависимость от единой точки хостинга (например, GitHub Pages) создаёт уязвимость перед блокировками.Сингулярное решение: Упаковка всего «Дома Дверей» и всех модулей в криптографически подписанный W3C Signed Web Bundle (.wbundle).Как это работает: Каждое устройство с установленным СИНГУЛЯР становится автономной точкой раздачи. Если центральный сайт недоступен, соседние браузеры скачивают и проверяют целостность новой версии ядра напрямую друг у друга по P2P.5. ДАЙ СКРИПТ И ПОЛНОЕ РУКОВОДСТВО Thoughts expand_moreВот готовое полное руководство и универсальный Python-скрипт serve_p2p.py для запуска локального HTTPS-сервера в вашей домашней или офисной Wi-Fi/LAN сети.⚠️ Важное техническое примечание (Secure Contexts)Современные браузеры (Chrome, Safari, Firefox) разрешают доступ к WebRTC, Web Crypto API (шифрование E2EE) и IndexedDB только в защищенном контексте (Secure Context):На localhost / 127.0.0.1.По протоколу HTTPS при доступе с других физических устройств по локальному IP-адресу (например, 192.168.1.X).Предоставляемый ниже скрипт автоматически генерирует временный SSL-сертификат и поднимает защищенный HTTPS-сервер на всех сетевых интерфейсах (0.0.0.0).📜 1. Скрипт локального HTTPS-сервера (serve_p2p.py)Создайте файл serve_p2p.py в папке с распакованными файлами проекта (из архива singulyar-meta-year-prototype.zip) и вставьте следующий код:#!/usr/bin/env python3
"""
СИНГУЛЯР · Автономный локальный HTTPS-сервер для P2P-тестирования
Поддерживает работу WebRTC, Web Crypto API и IndexedDB между физическими устройствами в LAN/Wi-Fi.
"""

import http.server
import ipaddress
import os
import socket
import ssl
import subprocess
import sys

PORT = 8443


def get_lan_ip():
    """Определение локального IP-адреса устройства в Wi-Fi/LAN сети."""
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    try:
        # Не выполняет реального подключения, используется для определения маршрута
        s.connect(("10.255.255.255", 1))
        ip = s.getsockname()[0]
    except Exception:
        ip = "127.0.0.1"
    finally:
        s.close()
    return ip


def generate_self_signed_cert(cert_file="cert.pem", key_file="key.pem"):
    """Автоматическая генерация самоподписанного SSL-сертификата через OpenSSL."""
    if os.path.exists(cert_file) and os.path.exists(key_file):
        print(f"[OK] Используются существующие SSL-сертификаты: {cert_file}, {key_file}")
        return True

    print("[INFO] Генерация временного SSL-сертификата для локальной сети...")
    cmd = [
        "openssl",
        "req",
        "-x509",
        "-newkey",
        "rsa:2048",
        "-keyout",
        key_file,
        "-out",
        cert_file,
        "-days",
        "365",
        "-nodes",
        "-subj",
        "/CN=SingulyarLocalP2P",
    ]
    try:
        subprocess.run(cmd, check=True, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
        print("[OK] SSL-сертификат успешно сформирован.")
        return True
    except (subprocess.CalledProcessError, FileNotFoundError):
        print("[WARN] OpenSSL не найден в системе.")
        return False


def run_server():
    lan_ip = get_lan_ip()
    cert_file, key_file = "cert.pem", "key.pem"

    has_ssl = generate_self_signed_cert(cert_file, key_file)

    handler = http.server.SimpleHTTPRequestHandler
    # Добавляем необходимые заголовки для изоляции и доступа к Web API
    handler.extensions_map.update(
        {
            ".html": "text/html; charset=utf-8",
            ".js": "application/javascript",
            ".json": "application/json",
            ".css": "text/css",
        }
    )

    httpd = http.server.HTTPServer(("0.0.0.0", PORT), handler)

    if has_ssl:
        context = ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER)
        context.load_cert_chain(certfile=cert_file, keyfile=key_file)
        httpd.socket = context.wrap_socket(httpd.socket, server_side=True)
        protocol = "https"
    else:
        protocol = "http"
        print("\n⚠️ ВНИМАНИЕ: Сервер запущен по HTTP. Для работы Web Crypto на мобильных смартфонах")
        print("потребуется включить флаг chrome://flags/#unsafely-treat-insecure-origin-as-secure\n")

    print("\n" + "=" * 65)
    print("🚀 СИНГУЛЯР · ЛОКАЛЬНЫЙ P2P-СЕРВЕР УСПЕШНО ЗАПУЩЕН")
    print("=" * 65)
    print(f"📱 Для подключения с ПК/смартфонов в одной Wi-Fi сети перейдите по адресу:\n")
    print(f"👉 {protocol}://{lan_ip}:{PORT}/СИНГУЛЯР_53_СВЯЗЬ_ЧЕЛОВЕКА.html")
    print(f"👉 {protocol}://{lan_ip}:{PORT}/index.html")
    print("\n💡 Для локального тестирования на этом ПК:")
    print(f"👉 {protocol}://localhost:{PORT}/СИНГУЛЯР_53_СВЯЗЬ_ЧЕЛОВЕКА.html")
    print("=" * 65)
    print("Для остановки сервера нажмите Ctrl+C\n")

    try:
        httpd.serve_forever()
    except KeyboardInterrupt:
        print("\n[INFO] Сервер остановлен пользователем.")
        sys.exit(0)


if __name__ == "__main__":
    run_server()
📖 2. Пошаговое руководство по запуску и проведению P2P-тестаШаг 1. Распаковка архива и запуск сервераРаспакуйте архив singulyar-meta-year-prototype.zip в отдельную папку.Сохраните код выше в файл serve_p2p.py внутри этой папки.Откройте терминал/командную строку в этой папке и выполните:python3 serve_p2p.py
Скрипт выведет ваш локальный IP-адрес (например: https://192.168.1.50:8443/...).Шаг 2. Подключение физических устройствУстройство 1 (Ноутбук / ПК):Откройте браузер и перейдите по адресу https://localhost:8443/СИНГУЛЯР_53_СВЯЗЬ_ЧЕЛОВЕКА.html.Устройство 2 (Смартфон / Планшет на iOS или Android):Убедитесь, что телефон подключен к той же Wi-Fi сети.В браузере телефона введите адрес с локальным IP ПК, например: https://192.168.1.50:8443/СИНГУЛЯР_53_СВЯЗЬ_ЧЕЛОВЕКА.html.Примечание по самоподписанному сертификату: При первом входе браузер покажет предупреждение безопасности («Подключение не защищено»). Нажмите «Дополнительно» $\rightarrow$ «Перейти на сайт (небезопасно)» — это стандартная процедура для локальных разработок.Шаг 3. Проведение P2P-сеанса связи между ПК и СмартфономГенерация E2EE-ключей идентичности:На ПК и на Смартфоне нажмите «Сгенерировать пару ключей ECDH P-256».В обоих интерфейсах отобразятся 32-символьные отпечатки SHA-256 (например: A1:B2:C3:...).Установление прямого P2P-канала (Zero-Server Handshake):На ПК: в блоке «3. WebRTC P2P DataChannel» нажмите «Создать P2P Offer». Скопируйте сформированный токен.Передайте токен на Смартфон (через QR-код, мессенджер или локальный буфер).На Смартфоне: вставьте токен в поле «SDP Offer / Answer» и нажмите «Принять Offer и создать Answer». Скопируйте сформированный ответный токен.На ПК: вставьте ответный токен и нажмите «Завершить Handshake».Проверка передачи сообщений и статусов:Индикатор на обоих устройствах сменится на 🟢 Status P2P: Channel OPEN.Отправьте сообщение со смартфона. ПК моментально получит зашифрованный пакет, проверит SHA-256 хеш манифеста и автоматически вернет системное подтверждение ACK.На смартфоне статус отправленного объекта изменится с attempting на recipient_acknowledged.🛠️ Устранение возможных проблем сетиСервер недоступен с телефона: проверьте, что брандмауэр/файрвол на ПК разрешает входящие соединения на порт 8443 (sudo ufw allow 8443/tcp на Linux или разрешение в Брандмауэре Windows).Сбой подключения WebRTC: если устройства находятся в разных подсетях изолированного роутера (например, Guest Wi-Fi), включите функцию AP Isolation Disabled в настройках роутера.
