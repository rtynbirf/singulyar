# Модель угроз и приватности

## Активы

Контакты, содержимое сообщений и файлов, ключи, адреса маршрутизации, история отношений, настройки доступности, финансовые намерения, метаданные времени/частоты связи.

## Противники и ошибки

1. Сетевой наблюдатель видит IP, время и объём трафика.
2. Relay/TURN/почтовый/телеком-провайдер видит часть метаданных и может иметь доступ к незашифрованному содержимому, если протокол не защищён E2EE.
3. Злоумышленный контакт присылает HTML, SVG, JSON или файл с вредоносным содержимым.
4. Потерянное/общедоступное устройство раскрывает локальные записи.
5. Подмена контакта/ключа приводит к отправке не тому человеку.
6. Компрометация устройства/браузерного расширения обходит защиту интерфейса.
7. Повтор, подмена или двойная трата опасны для будущего офлайн-обмена ценностью.
8. Доступностная настройка может раскрыть чувствительные данные, если автоматически отправлять её контактам.
9. Неправильный UI сообщает «доставлено», хотя транспорт только принял пакет.
10. Оператор номера/email/платежей может заблокировать аккаунт или изменить условия.

## Защиты и честные ограничения

- v0.1 не содержит E2EE; локальные данные не зашифрованы. Не хранить здесь секреты и финансовые данные.
- Импортировать только JSON-данные, никогда не исполнять импортированный код.
- Не помещать токены провайдеров в HTML, JS или репозиторий. Секреты хранить на серверной стороне выбранного адаптера.
- Для будущего E2EE использовать проверенную библиотеку и опубликованный протокол; не писать криптографию самостоятельно. Нужны анализ управления ключами, multi-device, ротации, резервных копий, удаления и восстановления.
- Ключи контактов сверять по отпечатку/QR/фразе через независимый канал; телефон/email сами по себе не аутентифицируют человека.
- Ограничивать размер, MIME и частоту входящих объектов; экранировать текст; CSP; безопасные заголовки.
- Приватность по умолчанию: никакой автоматической передачи сенсорного профиля, контактов или телеметрии.
- Для денежных адаптеров: отдельное согласие, подтверждение получателя/суммы/комиссии, idempotency key, журнал состояния и независимая юридическая проверка.

## Нельзя обещать

«Полная анонимность», «неотслеживаемость», «невзламываемость», «гарантированное удаление у всех участников», «деньги без посредников и риска», «реальный глобальный номер без оператора» или «E2EE» без проверяемых доказательств.

## До production

Threat modeling workshop; независимый review; SAST/DAST; тесты XSS/CSRF/IDOR/replay; аудит зависимостей/SBOM; проверяемая сборка; план реагирования на уязвимости; процедура отзыва ключей; тест восстановления; минимизация логов; проверка законов целевых стран.
