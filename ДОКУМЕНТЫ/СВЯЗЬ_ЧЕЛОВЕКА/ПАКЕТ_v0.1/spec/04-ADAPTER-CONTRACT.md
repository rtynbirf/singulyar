# Контракт адаптера

Каждый адаптер экспортирует метаданные и функции с предсказуемыми ошибками. В целевой реализации типы должны быть описаны TypeScript-интерфейсами и проверяться contract tests.

## Метаданные

`id`, `version`, `kind`, `operator`, `region`, `capabilities`, `limitations`, `pricing`, `dataCollected`, `retention`, `requiresAccount`, `requiresNetwork`, `consentScopes`, `disableMethod`, `supportUrl`.

## Операции

- `probe()` — проверяет доступность без передачи содержимого;
- `prepare(intent, recipient)` — возвращает маршрут/цену/требуемые разрешения;
- `send(object, route, consent)` — отправляет только после явного согласия;
- `getStatus(objectId)` — возвращает наблюдаемое состояние и источник доказательства;
- `cancel(objectId)` — best-effort отмена, не обещает отменить уже доставленное;
- `close()` — освобождает ресурсы;
- `exportData()` и `deleteLocalData()` — локальные действия, если применимы.

## Обязательные ошибки

`UNAVAILABLE`, `CONSENT_REQUIRED`, `INVALID_RECIPIENT`, `UNSUPPORTED_CAPABILITY`, `NETWORK_ERROR`, `RATE_LIMITED`, `PROVIDER_REJECTED`, `EXPIRED`, `UNKNOWN_DELIVERY`, `SECURITY_ERROR`.

## Обязательная карточка адаптера

Пользователь должен видеть: кто предоставляет канал; работает ли он сейчас; стоимость/комиссии, если известны; что провайдер может видеть; какие данные покидают устройство; требуется ли регистрация/документ; как отключить и экспортировать данные; какие ограничения по стране/устройству.

## Адаптеры по приоритету

1. `local`: сразу, без сети.
2. `file-export`: сразу, передача через существующие каналы пользователя.
3. `webrtc`: после спецификации сигналинга, ICE/TURN и E2EE.
4. `email`: сначала `mailto:`/экспорт, затем серверная доставка.
5. `telephony`: SMS/PSTN/виртуальный номер через провайдера; секреты только сервер-side.
6. `esim`: отдельный операторский provisioning; не притворяться браузерной функцией.
7. `value`: только после выбора юридически доступного провайдера и threat model.
