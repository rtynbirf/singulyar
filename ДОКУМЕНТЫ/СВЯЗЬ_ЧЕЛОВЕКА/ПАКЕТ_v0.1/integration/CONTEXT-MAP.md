# Карта интеграции по дверям

| Дверь | Предлагаемая роль | Что проверить в исходниках | Запрещённое предположение |
|---|---|---|---|
| ·21 ОБЩЕНИЕ | формы представления и содержание | текущие типы сообщений, TTS/STT, UI | что уже есть E2EE |
| ·22 СВЯЗЬ | транспорт и состояния доставки | WebRTC/BroadcastChannel/сигналинг | что BroadcastChannel работает между устройствами |
| ·24 ПОЧТА | почтовый маршрут/экспорт | существующий email workflow | что есть свой почтовый сервер |
| ·25 КОШЕЛЁК | намерение ценности/платёжный адаптер | типы операций, риски | что запись намерения равна переводу денег |
| ·26 ЛИНИЯ | телефон/SMS/PSTN | имеющиеся интерфейсы и ограничения | что браузер сам выпускает номер/SIM |
| ·27 ФУНДАМЕНТ | локальная идентичность и хранение | ключи, IndexedDB, экспорт, миграции | что localStorage зашифрован |
| ·51 ADAPTER-OS | platform capability adapters | API разрешений, системные API | что доступно одинаково на всех устройствах |

Перед изменением зафиксировать подтверждения для каждой строки в отчёте аудита. Если код недоступен — статус `UNKNOWN`, а не догадка.
