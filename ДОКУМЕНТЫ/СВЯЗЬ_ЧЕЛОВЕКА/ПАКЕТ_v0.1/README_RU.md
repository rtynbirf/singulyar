# СИНГУЛЯР · Контур человеческой связи — пакет прототипа v0.1

**Назначение:** интеграционный прототип и комплект инженерной документации для развития существующего «Дома дверей» СИНГУЛЯР, а не отдельный продукт и не обещание уже работающей глобальной телефонной сети.

## Что положено в архив

- `prototype/index.html` — локально запускаемый интерфейс: контакты, сообщения в локальном журнале, намерение передать ценность, профиль доступности, каталог адаптеров и экспорт/импорт данных.
- `integration/` — безопасный интеграционный контракт и фрагмент добавления двери в существующий `index.html`; исходную главную страницу архив не перезаписывает.
- `spec/` — архитектура, требования, модель угроз, протокол, JSON Schema, ADR, матрица проверки.
- `roadmap/` — этапы реализации, критерии входа/выхода и разбиение задач.
- `tests/` — ручные приёмочные проверки и небольшой автономный валидатор структуры пакета.
- `research/` — реестр стандартов и официальных первоисточников для следующего аудита.

## Запуск

1. Распаковать архив.
2. Открыть `prototype/index.html` в современном браузере. Для максимально совместимого режима можно запустить локальный сервер из каталога `prototype`: `python -m http.server 8000`, затем открыть `http://localhost:8000`.
3. Все записи прототипа хранятся только в `localStorage` текущего браузера. Это демонстрационный локальный журнал, **не зашифрованное хранилище** и не синхронизация между устройствами.
4. Экспортируйте JSON перед очисткой данных браузера.

## Честный статус реализации

| Возможность | Статус в v0.1 |
|---|---|
| Интерфейс «Дом связи», контакты, локальные сообщения | Работает локально в одном браузере |
| Экспорт/импорт собственного JSON | Работает локально; импорт проверяет базовую форму |
| Профиль сенсорных/коммуникационных предпочтений | Демонстрационный локальный профиль |
| Намерение перевода ценности | Только запись намерения; деньги не переводятся |
| Peer-to-peer/WebRTC | Спецификация и интеграционные границы; реального соединения в UI нет |
| Виртуальный телефонный номер/SMS/eSIM | Не предоставляются; нужны лицензированный оператор/провайдер и устройство с поддержкой eSIM |
| Почтовый адрес/доставка почты | Не предоставляются; нужен выбранный почтовый домен/сервер/провайдер |
| Сквозное шифрование | Не реализовано в прототипе; локальный журнал хранится открытым текстом |
| Синхронизация между устройствами, push, relay | Не реализованы |
| Подключение к действующему репозиторию/публикация | Не выполнялись: пакет содержит безопасный overlay и инструкции, но не изменяет удалённый GitHub автоматически |

## Важное архитектурное решение

СИНГУЛЯР должен соединять людей и их намерения, а не выдавать себя за оператора связи. Веб-страница не может самостоятельно выпускать глобальные телефонные номера, профили eSIM, почтовые домены или переводить деньги вне реальных сетей. Эти возможности проектируются как заменяемые адаптеры, с ясным указанием владельца данных, цены, юрисдикции, зависимости и выхода из сервиса.

## Порядок внедрения

1. Прочитать `spec/00-ARCHITECTURE.md` и `spec/02-THREAT-MODEL.md`.
2. Проверить интеграционный контракт в `integration/` и добавить новую дверь рядом с существующими дверями, не ломая текущую главную страницу.
3. Выполнить все тесты `tests/ACCEPTANCE.md`.
4. До любых реальных сообщений/платежей реализовать и независимо проверить криптографию, управление ключами, восстановление и модель злоупотреблений.

Точка интеграции: `https://rtynbirf.github.io/singulyar/index.html`. На публичной странице уже перечислены двери `·21 ОБЩЕНИЕ`, `·22 СВЯЗЬ`, `·24 ПОЧТА`, `·25 КОШЕЛЁК`, `·26 ЛИНИЯ`, `·27 ФУНДАМЕНТ`, `·51 ADAPTER-OS` и другие. Новый контур должен дополнять эти двери через контракты и ссылки, не создавать параллельный «второй СИНГУЛЯР» и не объявлять существующие модули проверенными без чтения их исходников.
