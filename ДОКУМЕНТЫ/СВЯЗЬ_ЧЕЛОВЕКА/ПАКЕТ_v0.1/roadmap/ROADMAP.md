# Дорожная карта

## Фаза 0 — проверка основы (1–3 дня инженерной работы)

- Получить актуальную копию репозитория и зафиксировать commit SHA.
- Найти фактические исходники дверей `21`, `22`, `24`, `25`, `26`, `27`, `51`.
- Создать таблицу `CLAIM → CODE → OFFICIAL SPEC → TEST → VERDICT`.
- Проверить лицензии, CSP, service worker, размер загрузки, accessibility, существующие локальные схемы.
- **Выход:** baseline report, без изменения поведения пользователей.

## Фаза 1 — UI и локальный контракт (прототип v0.1)

- Добавить дверь «СВЯЗЬ · человеческий контур» через ссылку, без перезаписи `index.html`.
- Встроить локальный intent composer, contacts, status semantics, export/import.
- Пройти keyboard/screen reader checks.
- **Выход:** локальная демонстрация; никакого заявления о реальной доставке.

## Фаза 2 — доменная модель и IndexedDB

- Реализовать typed models, migrations, repository interfaces, IndexedDB transactions.
- Экспортировать versioned JSON и проверять импорт по schema.
- Добавить восстановление/удаление и тесты больших/повреждённых экспортов.
- **Выход:** локальные данные устойчивы к перезагрузке и миграциям.

## Фаза 3 — отношения и доверие

- Invite/accept/revoke; одноразовые коды/ссылки с TTL и одноразовым использованием.
- Стабильные отношения после первоначального согласия; блокировка/удаление.
- Identity key lifecycle и проверка отпечатка — только после security design.
- **Выход:** тесты гонок, повторов, истечения, смены устройства.

## Фаза 4 — текстовая доставка P2P/relay

- Специфицировать signaling; WebRTC DataChannel; ICE; TURN fallback; rate limits.
- Внешняя проверка протокола, E2EE, key verification, anti-replay.
- Contract tests с разными браузерами/сетями и отключением relay.
- **Выход:** реальные сообщения с доказуемой семантикой статусов.

## Фаза 5 — мультимодальность и доступность

- Файлы с manifest/chunking/resume; TTS/STT по согласию; субтитры; ручной текстовый путь.
- Capability negotiation; никакого обязательного распознавания жестов камерой.
- Тесты с клавиатурой, screen readers, low vision, speech input, switch controls.
- **Выход:** минимум две независимые формы представления на каждом поддерживаемом действии.

## Фаза 6 — почта и телефония

- Сначала `mailto:`/экспорт; затем выбрать оператора для email relay.
- Отдельно исследовать виртуальный номер, SMS, PSTN, eSIM по странам и устройствам.
- Прописать цену, KYC, ограничения, перенос номера и выход от провайдера.
- **Выход:** адаптер только в юрисдикциях, где он легален и поддерживается.

## Фаза 7 — ценность и платежи

- Зафиксировать threat model: мошенничество, отмена, возврат, двойная трата, ошибочный адресат.
- Выбрать реальные интеграции после юридического и security review.
- Подтверждение получателя, суммы, комиссии, валюты и обратимости перед отправкой.
- Офлайн-ценность — отдельная исследовательская ветка, не продакшен-функция до аудита.

## Фаза 8 — аудит и выпуск

- Независимый security/privacy/accessibility review.
- SBOM, pinning зависимостей, reproducible build, release signing, incident response.
- Пройти весь acceptance suite, опубликовать known limitations и changelog.
- **Выход:** релиз-кандидат с воспроизводимыми доказательствами.

## Стратегические запреты

Не начинать с виртуальной SIM или токена/криптовалюты. Не писать собственную криптографию. Не создавать серверную зависимость до доказательства необходимости. Не объявлять E2EE/анонимность/доставку без тестов. Не внедрять скрытую телеметрию.
