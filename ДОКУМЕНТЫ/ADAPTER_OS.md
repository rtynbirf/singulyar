# SINGULYAR ADAPTER OS v0.1 — интеграция в платформу

## Что это

Инженерный слой поверх ·19 ЧЕЛОВЕК → ·21 ОБЩЕНИЕ → ·22 СВЯЗЬ, собранный из
присланного пакета `singulyar-adapter-os-v0.1.zip` (SHA-256
`6ab03a4f…74af`, проверен байт-в-байт). Ядра страниц **не тронуты** — мост
только регистрирует их проверенные механизмы как адаптеры, ведёт шину
смыслов и даёт честные статусы.

```text
ЧЕЛОВЕК → ПРЕДПОЧТЕНИЯ → ВОЗМОЖНОСТИ → СМЫСЛ → АДАПТЕР → ПРЕДСТАВЛЕНИЕ
```

## Как подключён (v0.1, срез №1)

Каждая страница получает маленький `<script type="module">` перед
UX-движком. На file:// module-import браузер блокирует → блок ловит ошибку
и честно пишет `window.SingulyarOS = {state:'unavailable'}`; страница
работает как раньше.

| Страница | Что регистрируется мостом | Источник правды |
|---|---|---|
| ·19 ЧЕЛОВЕК | предпочтения человека (`singulyar.adaptation.v1`) → capability-модель + адаптер-источник `source.19-адаптация` | localStorage ·19 |
| ·21 ОБЩЕНИЕ | `output.21-брайль` (реальная функция S21.braille), `tool.21-маршрутизация` (S21.route) | ядро S21 |
| ·22 СВЯЗЬ | `channel.22-зал` — транспорт зала как адаптер-канал (проверка BroadcastChannel) | ядро ·22 |

Шина смыслов (`singular-meaning-bus-v1`, конверты
`{id,type,payload,createdAt,author}`) — отдельный транспорт моста; живой
мост ·21⇄·22 (`singular-most-21-22-v1`) работает как работал.

## Срез 4 — МОЗГ: локальная модель и голос (v1.14.0)

Запрос РУВСОН: «залить ЛЛМ-модель из репы… важно как ты её обучишь… любой
может голосом давать инструкции, а она шустрит». Разрезан на два слоя,
и это не украшение, а честная архитектура:

**Веса — в соседней репе `rtynbirf/singulyar-llm`** (отдельно, потому что
веса не влезают в лимиты git по-честному и не должны: они чужие,
Apache-2.0, у них своя история происхождения). Qwen2.5-0.5B-Instruct
GGUF (q4_k_m), 469 МБ, разрезан на 6 частей ≤100 МБ — обычные бинарные
куски без LFS, склейка 01→06 байт-в-байт даёт оригинал (SHA-256 в
MANIFEST.txt той репы, проверка — `СБОРКА/ПРОВЕРКА_ЦЕЛОСТНОСТИ.py`).

**«Обучение» — инструкционный слой, и он как раз наш:** файл
`ОБУЧЕНИЕ/ПРАВИЛА_СИНГУЛЯРА.txt` (системный промпт: язык, честность,
границы, формат, запрет подхалимажа) и `ОБУЧЕНИЕ/ПРИМЕРЫ_КОМАНД.jsonl`
(словарь голосовых команд, v0.3 — 41 фраза). Поправил правило или добавил
фразу — модель стала умнее для всех без GPU и новых весов (пункт 9
правил). Веса не дообучались — для этого нужен GPU и корпус; здесь этого
нет, и мы не притворяемся.

**Проводка (БИБЛИОТЕКИ/adapter-os/llm.mjs):**
- `llm.local` (kind `llm`): грузит 6 частей (Cache API — один раз,
  дальше из кеша браузера), склеивает в Blob, отдаёт wllama
  (llama.cpp → WebAssembly; WebGPU включается сам, где поддержан).
  Статусы честные: `UNAVAILABLE` с причиной до загрузки → `READY`.
- `input.speech` (kind `input`): Web Speech API браузера. Честно:
  в Chrome звук распознавания уходит на серверы Google
  (`privacy: cloud-input`) — единственное облако в цепочке, названо
  прямо; без поддержки — `UNAVAILABLE`, текстовый ввод работает всегда.
- **Правило-слой** исполняет команды словаря БЕЗ модели: «статус»,
  «отправь: …», «прочитай поле сообщения», «прочитай журнал», «очисти
  журнал», «очисти поле сообщения», «стоп», «помоги», «загрузи модель».
  Платформа управляема голосом даже на слабой машине.
- Свободная речь: модель не загружена → честное «модель не загружена,
  скажи „загрузи модель"», никакого выдуманного ответа.
- Панель «МОЗГ» на ·21 собрана DOM-фабрикой (0 innerHTML), каждая
  инструкция оставляет конверт `meaning.21.инструкция {фраза,
  намерение, via: rule-layer|llm.local|none}` в шине смыслов.

**Тесты (правило №10: сначала RED против живых файлов, потом проводка):**
- `ИНСТРУМЕНТЫ/test_llm_logic.mjs` — 35/35: словарь, нормализация живой
  речи (регистр, ё/е, пунктуация), префиксы, честный null, статусы до
  загрузки; файл llm.mjs чистый ESM — проверяется node-ом;
- `ИНСТРУМЕНТЫ/test_llm_wire.py` — 22/22: панель, статусы реестра,

- `ИНСТРУМЕНТЫ/test_llm_real.py` — НАСТОЯЩИЙ e2e: wllama реально

## Срез 5 — ДОУЧКА v0.4: голос ходит по СИНГУЛЯРУ (v1.14.1)

Продолжение срез 4 по прямому приказу «доуставляй, доучивай». Словарь
инструкционного слоя вырос с 41 до 76 фраз, и главное — из МОЗГа можно
голосом ходить по всей платформе, без модели, на любой машине:

- **Навигация (open):** «открой зал», «пойди в суфлёр», «открой,
  пожалуйста, связь», «вернись на главную» — `решитьСтраницу()`
  резолвит живую речь (стемы, запятые, падежи) в реальные файлы
  страниц репы: ·01 «когда теряем», ·02 фабрика/резонанс, ·15–·22,
  главная. Незнакомая цель — честный список того, что знает, без
  выдумок; пустое «открой» — встречный вопрос.
- **Эхо (repeat):** «повтори: …» / «скажи: …» — произнести текст вслух
  (префикс «скажи получателю:» стоит раньше и не перехватывается).
- **Связь (ping):** «пинг», «ты здесь», «откликнись» — подтверждение
  без модели с версией словаря и честным состоянием модели.
- **Счёт (count):** «сколько команд ты знаешь» — число фраз из живого
  словаря, не из головы.
- **Само-ответ (identity):** «кто ты» — правило-слой отвечает без
  модели; свободный «привет, кто ты» остаётся примером llm-речи.
- Расширены старые намерения: «прекрати», «перестань», «состояние
  системы», «стереть журнал», «что в поле сообщения», «зачитай
  сообщение», «покажи журнал», «включи мозг», «подними модель»,
  «скачай мозг».

**Технически:** запятые больше не режутся глобально — Chrome вкладывает
пунктуацию в транскрипт, и payload «отправь: …» должен доходить без
потерь; сверка с префиксами/картой идёт в отдельной командной форме
(запятые → пробелы), payload берётся из строки с сохранёнными запятыми.

**Тесты:** logic 77/77 (включая решитьСтраницу: 13 страниц, честный
null), wire 27/27 (включая НАСТОЯЩУЮ навигацию: «открой зал» переводит
браузер на СИНГУЛЯР_17_ЗАЛ.html и возвращение на ·21 без ошибок
консоли); тестовый сервер получил SO_REUSEADDR — прогоны не зависят от
TIME_WAIT прошлых запусков. ОБУЧЕНИЕ/ репы singulyar-llm синхронно
поднято до v0.4 (правила + jsonl). Ядра ·21/·22 не тронуты.

## Срез 6 — MeaningRouter на шину (v10.74 «СВОД»)

Закрыта открытая граница среза 2: «при смешении нескольких кандидатов на
один смысл роутер подключится следующим срезом». Правило №10 соблюдено
буквально: сначала тест против живых файлов — RED 12 OK / 5 FAIL на
непроводных файлах (`ИНСТРУМЕНТЫ/test_meaning_router.mjs`), потом
проводка. Итог GREEN 38/38; регресс: adapter-os 4/4, llm logic —
111 OK / 1 FAIL, ровно как на HEAD до среза (тот единственный FAIL —
давний дефект самого теста: строковое сравнение `СЛОВАРЬ_ВЕРСИЯ >=
'v0.6'` ложно при живой версии 'v0.10'; файлы срезов 4/5 срезом 6 не
трогались).

**Что сделано.**

- `src/core.mjs` — минимальная правка `MeaningRouter.route`: тотальная
  детерминированная сортировка кандидатов; canUse зовётся ровно один
  раз на адаптера; форма ответа прежняя (message/selected/candidates),
  поле `match` в candidates — добавочное (0 — generic, 1 — полное
  совпадение capability). Остальное ядро пакета — байт-в-байт.
- `bridge.mjs` — только добавочное: `os.routeMixed(meaning,
  {preferred, target})` — смешение кандидатов на один смысл. Роутер
  выбирает ровно одного; доставка — render выбранного адаптера, ТОЛЬКО
  если передан target; след — конверт `meaning.router`
  `{via:'router', selected, candidates, policy, delivered, reason}` в
  шину (и в возврате, и в bus.log()); отказ честный: никого готового →
  selected:null, delivered:false, render не зовётся ни разу.
  `os.routeOut` (срезы 1–5) не изменился и конвертов не публикует.

**Политика выбора (одной формулой):**

```text
выбор = preferred человека (правило ·19) > capability-full (canUse объявлен и вернул истину) > priority (больше) > id (лексикографически, по возрастанию)
```

Сортировка тотальная → при одинаковых входах выбор один и тот же,
порядок регистрации адаптеров на результат не влияет. Раньше при равных
приоритетах побеждал порядок регистрации (недетерминизм при смешении) —
теперь побеждает меньший id, и это задокументированный контракт.

**Как проверено (38 проверок, node, против живых файлов):** (a) два
кандидата на один смысл → ровно один победитель, одинаковый при любом
порядке регистрации и при повторе; (b) каждая ступень политики
проверена по отдельности + preferred остаётся выше автоматики; (c)
одиночный кандидат и `routeOut` идут как в срезах 1–5 (прежняя форма
ответа, без конвертов в шину); (d) конверт `meaning.router` —
настоящий конверт шины (id/type/payload/createdAt/author), несёт
via:'router', выбранного, ПОЛНЫЙ список кандидатов со статусами и
