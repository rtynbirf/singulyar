# SINGULYAR ADAPTER OS v0.1 — интеграция в платформу

## Что это

Инженерный слой поверх ·19 ЧЕЛОВЕК → ·21 ОБЩЕНИЕ → ·22 СВЯЗЬ, собранный из
присланного пакета `singulyar-adapter-os-v0.1.zip` (SHA-256
`6ab03a4f…74af`, проверен байт-в-байт). Ядра страниц **не тронуты** — мост
только регистрирует их проверенные механизмы как адаптеры, ведёт шину
смыслов и даёт честные статусы.

```text
ЧЕЛОВЕК → ПРЕДПОЧТЕНИЯ → ВОЗМОЖНОСТИ → СМЫСЛ → АДАПТЕР → ПРЕДСТАВЛЕНИЕ
```

## Состав в репо

`БИБЛИОТЕКИ/adapter-os/` — пакет из архива байт-в-байт + один новый файл:

| Файл | Статус | Что это |
|---|---|---|
| `src/core.mjs` | из архива | CapabilityModel · AdapterRegistry · MeaningRouter |

| `bridge.mjs` | **новый** | мост: загрузка OS, шина смыслов, окно `window.SingulyarOS` |

## Как подключён (v0.1, срез №1)

Каждая страница получает маленький `<script type="module">` перед
UX-движком. На file:// module-import браузер блокирует → блок ловит ошибку
и честно пишет `window.SingulyarOS = {state:'unavailable'}`; страница
работает как раньше.

| Страница | Что регистрируется мостом | Источник правды |
|---|---|---|
| ·19 ЧЕЛОВЕК | предпочтения человека (`singulyar.adaptation.v1`) → capability-модель + адаптер-источник `source.19-адаптация` | localStorage ·19 |
| ·21 ОБЩЕНИЕ | `output.21-брайль` (реальная функция S21.braille), `tool.21-маршрутизация` (S21.route) | ядро S21 |
| ·22 СВЯЗЬ | `channel.22-зал` — транспорт зала как адаптер-канал (проверка BroadcastChannel) | ядро ·22 |

Шина смыслов (`singular-meaning-bus-v1`, конверты
`{id,type,payload,createdAt,author}`) — отдельный транспорт моста; живой
мост ·21⇄·22 (`singular-most-21-22-v1`) работает как работал.

## Доступ из консоли/тестов

```js
SingulyarOS.version            // '0.1'

```

## Запуск прототипа — ВАЖНОЕ ИСПРАВЛЕНИЕ

В README архива команда указана неверно: `python -m http.server 8080 -d
prototype` обрезает импорты `../src/*.mjs` (404, прототип мёртв при живом
HTTP 200). Правильно — из корня пакета:

```bash
cd БИБЛИОТЕКИ/adapter-os
python -m http.server 8080
# открыть http://localhost:8080/prototype/
```

## Срез 2 — production-проводка (v1.13.3)

Правило №10 плана пакета выполнено буквально: сначала тесты против живых
файлов (`ИНСТРУМЕНТЫ/test_adapter_os_wire.py`, RED 14/19 на прежних
файлах), затем проводка. Итог GREEN 19/19 + вся регрессия
(54/54, 49/49, 17/17, 36/36).

**·21 ОБЩЕНИЕ.** В реестре — по одному адаптеру на каждый канал человека
(`output.21-канал-text/speech/braille/haptic/aac/sign`); `render` строит
ровно те же объекты `{ch,label,view[,voice]}`, что и ветки ядра.
`S21.route` переведён на реестр: реестр выбирает адаптер по каналу
получателя, адаптер строит представление средствами ядра. Реестр ответил
не полностью, статус не READY или упал → исходная функция ядра без
изменений (фолбэк). Контракт среза 1 (output.21-брайль,
tool.21-маршрутизация) не тронут. Блок ядра между маркерами
`S21:CORE-BEGIN/END` — байт-в-байт прежний (node-тест 54/54 это
подтверждает).

**·22 СВЯЗЬ.** Когда ·22 пересылает смысл зала на представление в ·21,
зеркальный инстанс моста (только читает, формат `singular-most-21-22-v1`
не изменён) публикует конверт `meaning.22.зал` в шину. Представление
по-прежнему строит получатель. Вся цепочка смысла теперь имеет след в
шине: зал → `meaning.22.зал` (·22) → `meaning.21.route` (·21, через
новую проводку).

**Честные границы среза 2:** канальные адаптеры сообщат `READY` как
объявленные страницы каналы (это статусы канала, не железа); роутер
`MeaningRouter` (выбор одного лучшего) в проводке не участвует — выбор
делает реестр по каналам получателя, потому что получатель уже назвал
свои каналы; при смешении нескольких кандидатов на один смысл роутер
подключится следующим срезом.

## Срез 3 — инструкция без автора

Принцип, сформулированный автором проекта: он не строит — он делает так,
чтобы его инструкция была понятна любому без него. Машинальная проверка
этого принципа — `ИНСТРУМЕНТЫ/test_instruction_alone.py`: любой, кто
склонировал репо, может понять и проверить всё, не спрашивая автора.

Что проверяется (18 проверок против живых файлов): контракт ядра ·21 по
маркерам-комментариям; честные строки index.html (карточки ·19/·21/·22
говорят про Adapter OS v0.2); документы ссылаются только на существующие
файлы репо; в ИНСТРУМЕНТАХ ноль путей машины автора; у каждого инструмента
шапка «что это», у каждого теста строка «Запуск»; синтакс-чистота всего
python/js; ключевые зависимости в репо; wire-тесты среза 2 лежат в репо.

Что было исправлено в этом срезе (найдено самим тестом):

- wire-тесты среза 2 (`test_adapter_os_wire.py`, `test_live_wire.py`)
  лежали только на машине автора — перенесены в `ИНСТРУМЕНТЫ/`, пути
  считаются от файла;
- 11 инструментов были привязаны к путям машины автора — отвязаны
  (корень репо от `__file__`/`__dirname`, временные файлы — в системный
  temp);
- `ДОКУМЕНТЫ/ADAPTER_OS.md` ссылался на несуществующий уровень путей
  (вне репо) — путь исправлен на `ИНСТРУМЕНТЫ/`;
- эталонная сверка QR (`test_qr_vs_python.py`) зависела от внешнего
  файла `qr_dev.js`, утраченного даже у автора — JS-класс теперь
  извлекается в рантайме из живой страницы ·17, эталон — python qrcode;
- `test_s16_logic.js` читал `/tmp/s16.js`, собранный вручную — теперь
  извлекает код из живой страницы ·16 сам;
- QR-сверка в `test_s17_fusion.js` сравнивала страницу с dev-копией —
  заменена на проверку детерминизма и полноты масок средствами самого
  класса (эталонная сверка живёт в `test_qr_vs_python.py`);
- `assemble_s18.py` — исторический инструмент одноразовой сборки: честная
  шапка и честный отказ, если parts отсутствуют (пересборка не канонична —
  живая страница эволюционировала после сборки);
- `build_s18_catalog.py` пишет каталог в `ИНСТРУМЕНТЫ/s18_catalog.json`
  (в репо), а не на машину автора.

**Честные границы среза 3:** «понятно без автора» здесь проверено
машинально для структуры (пути, шапки, зависимости, синтаксис) и
фактически — для тестов (свежий клон, полный прогон без машины автора:

## Срез 4 — МОЗГ: локальная модель и голос (v1.14.0)

Запрос РУВСОН: «залить ЛЛМ-модель из репы… важно как ты её обучишь… любой
может голосом давать инструкции, а она шустрит». Разрезан на два слоя,
и это не украшение, а честная архитектура:

**Веса — в соседней репе `rtynbirf/singulyar-llm`** (отдельно, потому что
веса не влезают в лимиты git по-честному и не должны: они чужие,
Apache-2.0, у них своя история происхождения). Qwen2.5-0.5B-Instruct
GGUF (q4_k_m), 469 МБ, разрезан на 6 частей ≤100 МБ — обычные бинарные
куски без LFS, склейка 01→06 байт-в-байт даёт оригинал (SHA-256 в
MANIFEST.txt той репы, проверка — `СБОРКА/ПРОВЕРКА_ЦЕЛОСТНОСТИ.py`).

**«Обучение» — инструкционный слой, и он как раз наш:** файл
`ОБУЧЕНИЕ/ПРАВИЛА_СИНГУЛЯРА.txt` (системный промпт: язык, честность,
границы, формат, запрет подхалимажа) и `ОБУЧЕНИЕ/ПРИМЕРЫ_КОМАНД.jsonl`
(словарь голосовых команд, v0.3 — 41 фраза). Поправил правило или добавил
фразу — модель стала умнее для всех без GPU и новых весов (пункт 9
правил). Веса не дообучались — для этого нужен GPU и корпус; здесь этого
нет, и мы не притворяемся.

**Проводка (БИБЛИОТЕКИ/adapter-os/llm.mjs):**
- `llm.local` (kind `llm`): грузит 6 частей (Cache API — один раз,
  дальше из кеша браузера), склеивает в Blob, отдаёт wllama
  (llama.cpp → WebAssembly; WebGPU включается сам, где поддержан).
  Статусы честные: `UNAVAILABLE` с причиной до загрузки → `READY`.
- `input.speech` (kind `input`): Web Speech API браузера. Честно:
  в Chrome звук распознавания уходит на серверы Google
  (`privacy: cloud-input`) — единственное облако в цепочке, названо
  прямо; без поддержки — `UNAVAILABLE`, текстовый ввод работает всегда.
- **Правило-слой** исполняет команды словаря БЕЗ модели: «статус»,
  «отправь: …», «прочитай поле сообщения», «прочитай журнал», «очисти
  журнал», «очисти поле сообщения», «стоп», «помоги», «загрузи модель».
  Платформа управляема голосом даже на слабой машине.
- Свободная речь: модель не загружена → честное «модель не загружена,
  скажи „загрузи модель"», никакого выдуманного ответа.
- Панель «МОЗГ» на ·21 собрана DOM-фабрикой (0 innerHTML), каждая
  инструкция оставляет конверт `meaning.21.инструкция {фраза,
  намерение, via: rule-layer|llm.local|none}` в шине смыслов.

**Тесты (правило №10: сначала RED против живых файлов, потом проводка):**
- `ИНСТРУМЕНТЫ/test_llm_logic.mjs` — 35/35: словарь, нормализация живой
  речи (регистр, ё/е, пунктуация), префиксы, честный null, статусы до
  загрузки; файл llm.mjs чистый ESM — проверяется node-ом;
- `ИНСТРУМЕНТЫ/test_llm_wire.py` — 22/22: панель, статусы реестра,
  исполнение команд без модели, конверты шины, маршрут «отправь» через
  реестр, 0 ошибок консоли;
- `ИНСТРУМЕНТЫ/test_llm_real.py` — НАСТОЯЩИЙ e2e: wllama реально
  запускает модель в браузере (веса с локального сервера или из репы
  singulyar-llm), загрузка и живой ответ; на машине срезу 4 модель
  загрузилась за 7,5 с и ответила: «Я — локальный голос СИНГУЛЯРА
  RUVSON… работаю по правилам РУВСОН» (правило 7 сработало);
- регресс: логика ·21 54/54, ·22 49/49, мост 33/33, adapter-os 4/4,
  проводка среза 2 19/19, «инструкция без автора» 17/17.

**Честные границы среза 4:** первый запуск качает ~469 МБ из репы
singulyar-llm (дальше кеш браузера); скорость генерации зависит от
