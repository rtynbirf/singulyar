## 1. Зачем этот документ

В доме сложилась практика: каждая большая мысль должна иметь одно место,
где она сверена с кодом и с правдой. Треки HARMONIA и HIR велись отдельно
от дома и принесли с собой готовую документацию: два ТЗ, две дорожные
карты, модель угроз, спецификацию профиля доступности, формат событий и
два работающих прототипа. Пока эти документы лежали в стороне, дом и
треки решали одни и те же задачи дважды и по-разному. Этот документ
сшивает всё в одну ткань: что уже готово в доме, что готовы треки, где
они совпадают, где противоречат друг другу, и в каком порядке двигаться
дальше. Он же — учебник для Малыша и для любого нового агента, который
придёт в проект: прочитал КОДЕКС — знаешь, что где живёт и почему.

Дом не поглощает треки, а берёт из них лучшее. Треки не спорят с домом,
а получают в нём второй голос. Роль «двери» в доме — честный способ
показать прототип трека живьём, не выдавая его за прод: обе двери
помечены фасетом `lab` (лаборатория), как ·39 ОРГАНИЗМ.

## 2. Треки: что привезли

### 2.1 HARMONIA — адаптивные события (дверь ·40 ГАРМОНИЯ)

Платформа событий (концерт, лекция, тренинг, детский праздник), где
**одно событие подстраивается под каждого участника**: свет, звук, вибро
и текст подбираются под его профиль доступности. Формально выросла из
страницы ЛАДОМ — то есть это не чужой проект, а вторая жизнь нашей же
идеи. Пакет: 11 документов, JSON-схема `.harm`, пример события, рабочий
прототип в одном файле (17 КБ, без сети), лицензия MIT/CC BY 4.0.

Ключевые вещи, которых в доме до сих пор не было в формализованном виде:

1. **Профиль доступности как самостоятельный объект** (`harm-profile/0.1`):
   десять независимых осей — движение, гранулярность текста (буква/слог/
   слово/строка), размер, контраст, темп, громкость, вибро/свет, сдвиг
   синхронизации, ввод, вывод. Профиль живёт на устройстве; событие
   получает только производные значения («motion=none»), но не ярлыки и
   не причины. Пресеты без медицинских терминов («минимум стимулов»,
   «читаю медленно»).
2. **Формат `.harm` — «партитура намерений»**: маркеры `text` / `accent` /
   `scene` / `prompt` / `pause` во времени, заданном в долях (beat), а не
   секундах — смена темпа не ломает синхронизацию. Событие — данные, не
   код; подпись автора Ed25519; плеер отказывается открывать более новую
   мажорную версию схемы.
3. **Журнал доступа**: каждое обращение приложения к устройству
   (микрофон, вибро) пишется в видимый пользователю журнал. Звук хлопков
   анализируется локально и не записывается.
4. **Модель угроз** (документ 05): девять угроз и мер, от «событие
   вытягивает профиль» до «ложные обещания забыть меня». Это самый
   зрелый приватностный текст из всех, что писались в проекте.

### 2.2 HIR — Human Intent Runtime (дверь ·41 НАМЕРЕНИЕ)

ТЗ общего рантайма, связывающего намерение, участников, смысловое
событие, представление и транспорт. Это не competitor дому — это попытка
назвать общие контракты, которые дом уже интуитивно исполняет, но
нигде не зафиксировал. Пакет: ТЗ, архитектура, отчёт с критическими
решениями, исследование, дорожная карта, приёмочные проверки и
исследовательский прототип (15 КБ, без сети).

Ключевые контракты: `PersonRef` (человек без автоматических категорий),
`Relationship` (удаление отношения прекращает доступ), `Intent`
(исходный текст намерения никогда не затирается выводом модели),
`MeaningEnvelope` (событие как конверт с провенансом, не как HTML),
`RepresentationPreference` (представление меняется — смысл и
идентификатор события нет), `TransportCapability` (возможность
заявляется только при наличии теста). Инвариант, который стоит
высечь: **«сохранено локально» не равно «доставлено»** — и честная
цепочка CLAIM → CODE → SPEC → TEST → RESULT → VERDICT для каждого
существенного обещания.

## 3. Карта соответствий: треки ↔ дом

Здесь — главная ценность синтеза: каждый контракт трека положен на
конкретный механизм дома. Дом уже исполняет больше, чем думал.

| Контракт/механизм трека | Где живёт в доме | Состояние |
|---|---|---|
| `PersonRef` — человек без ярлыков | ·19 ЧЕЛОВЕК: человек как вместилище, категории не назначаются автоматически (правило Малыша 12) | совпадает |
| `Relationship` — отзыв прекращает доступ | ·23 КРУГ / ·22 СВЯЗЬ: роли хозяин/гость, КАЗНА семьи | совпадает частично; формальный отзыв отношения — открытый ход |
| `Intent` — исходный текст не затирается | поле намерения на главной ·01; Малыш: свободный текст ≠ интерпретация (правило 11) | совпадает |
| `MeaningEnvelope` — событие-конверт | ·21 ОБЩЕНИЕ, ·24 ПОЧТА: сообщения как смысл, представления отдельно | частично; схему конверта зафиксировать при доработке ·21 |
| `RepresentationPreference` | ·31 ЛАДОМ: темы day/kids/kraft/hc, сцены, ТИХО, строка-герой, гранулярность подсветки | совпадает по духу; осей меньше — см. §5 |
| `TransportCapability` — честность о транспорте | ЩИТ приватности v10.53: правда о сигналинге PeerJS в приглашении зала; «СВОЁ · 0 облаков» | совпадает; канон UNKNOWN ≠ FAIL |
| Маркер `.harm` `text` (слово/длительность в долях) | строки песни КОНВЕЙЕРА ·31; будущий СЛОВО-ПУЛЬС (подсветка слова по word-timestamps) | синергия: СЛОВО-ПУЛЬС = «text»-маркеры на нашем треке |
| Маркер `.harm` `scene` | сцены дома day/party/kids/romantic ≈ темы day/kids/kraft/hc | совпадает; имена привести к одному словарю при импорте |
| Маркер `.harm` `accent` | аккорды DM/E на сцене, пульс баса → аура, ПУЛЬС ГОСТЯМ (haptic) | совпадает |
| Маркер `.harm` `prompt` | приглашения зала (хост-руль, кнопка-ссылка ≥44px) | совпадает; правило «у каждого жеста есть кнопка» уже канон |
| Маркер `.harm` `pause` | ТИХО v10.53 (calm-час): дом присыпается, песня не гаснет | совпадает по смыслу: тишина — намерение, а не баг |
| Профиль: ось `motion` | гарды data-motion off / calm / prefers-reduced-motion на ауре | совпадает |
| Профиль: ось `gran` | подсветка слова/строки; строка-герой 1.045 | частично; слог/буква — открытый ход |
| Профиль: ось `offset` (−300…+300 мс) | нет в доме | принять: калибровка задержки — честный ответ на «звук отстаёт от текста» |
| Журнал доступа | ЗДОРОВЬЕ (томограф, 148 проб) + ЩИТ: точка микрофона, aria-live | совпадает; журнал как лента событий — кандидат в ЗДОРОВЬЕ |
| Подпись автора `.harm` Ed25519 | импорт в БИБЛИОТЕКУ ·31 проверяет тип/размер, подписи нет | открытый ход: подпись файла библиотеки (WebCrypto, non-extractable) |
| «Событие — данные, не код» | дом: inline-скрипты свои, внешних скриптов нет (NFR-01 HIR совпадает) | совпадает |

Вывод из карты: **дом уже исполняет ~70% контрактов HIR и большую часть
формата `.harm` де-факто**. Треки дают то, чего дому не хватало: имена
для того, что уже работает, и формальные заготовки для того, чего нет
(профиль как объект, подпись, ось синхронизации).

## 4. Синтез дорожных карт: один порядок движения

Три дороги (дом/ШТАБ, HARMONIA, HIR) после наложения дают одну:

### Уже готово (перекрытие треков и дома)
- Локальность и офлайн: дом работает без облака для всего своего; оба
  трека требуют того же (0 запросов в сеть у HARMONIA — совпадает с
  «СВОЁ · 0 облаков»).
- Доступность как ядро, не как кожух: WCAG 2.2 цели ≥24/44px, reduced
  motion, контраст, клавиатура — в доме уже канон (ЭП, пробы).
- Честные статусы вместо обещаний: UNKNOWN ≠ FAIL (дом), «сохранено
  локально ≠ доставлено» (HIR), «приложение не обещает того, что не
  может гарантировать» (HARMONIA). Это одна и та же мораль в трёх
  формулировках.

### Ближайшие ходы (недели, не месяцы)
1. **Профиль доступности дома** — поднять оси `harm-profile/0.1` до
   уровня настроек дома: тема/сцена/ТИХО/аура уже есть; добавить оси
   `gran` (слог/слово/строка) и `offset` (калибровка). Хранить в
   localStorage дома, экспорт/импорт файла — по спецификации трека
   (схема + диапазоны, значение вне диапазона → ближайшее допустимое).
2. **СЛОВО-ПУЛЬС через `.harm`** — не ждать Whisper-word-timestamps:
   сгенерировать `.harm`-документ для «Просто люби» (текст уже разбит на
   строки с таймкодами в LYR; слово/доля — ручная разметка куплета) и
   подсветку слова вести по маркерам. Формат трека становится
   транспортным форматом дома.
3. **Подпись библиотеки** — Ed25519 WebCrypto при экспорте события из
   БИБЛИОТЕКИ; проверка при импорте с явным подтверждением при
   несовпадении (как в модели угроз трека).
4. **Валидатор `.harm`** — маленькая функция в ИНСТРУМЕНТЫ: схема,
   диапазоны, «текст у каждого маркера», «у каждого prompt — кнопка».
   Демо-событие `examples/demo.harm.json` — первый тестовый файл.

### Средний горизонт (месяцы)
5. **ЛАН-ЗАЛ (ЭП-11)** соединяется с Фазой 4 HARMONIA: живые события
   до 8 пиров, агрегаты хлопков/ответов вместо аудио — тот же
   WebRTC-сигналинг, что у зала ·31, но обмен только агрегатами
   (интенсивность 0–1, номер ответа), без аудио и имён. Один движок —
   два сценария.
6. **Редактор событий** (Фаза 3 HARMONIA): временная шкала с
   предпросмотром на трёх профилях. Для дома это авторская тетрадь
   СЦЕНЫ ·32.
7. **HIR-контракты в ·21/·24** — зафиксировать MeaningEnvelope как
   JSON-схему почты и общения; транспорт-реестр ·22 получает
   `TransportCapability` с обязательным тестом на каждую заявленную
   возможность.

### Дальний горизонт (годы)
8. Заявка в W3C Community Group на формат `.harm` (Фаза Годы 3–5
   HARMONIA) — от дома, как от первого воплощения формата.
9. Федерация событий (ActivityPub-подобно) и Solid-поды — только после
   того, как локальный сценарий останется таким же простым.
10. Нативные обёртки ради вибро на iOS — в порядке HARMONIA (год 2),
    не раньше живого спроса.

### Метрика одна на всех
Из ROADMAP HARMONIA + REPORT HIR, сверено с ШТАБом: ценность =
завершённые сценарии и устранённые барьеры, не количество дверей.
Дрейф синхронизации ≤ 25 мс; 0 критичных a11y-нарушений; 0 сетевых
запросов у локального сценария; ≥ 90% людей завершают сценарий без
помощи; каждая заявленная возможность дома имеет тест.

## 5. Закон СИНГУЛЯРА — сверка треков

| Требование закона | HARMONIA | HIR | Дом |
|---|---|---|---|
| Эргономика | профиль доступности, пресеты без диагнозов, ≥24px цели | крупный текст, клавиатура, reduced motion | строки-герой, ≥44px, ТИХО |
| Приватность | профиль не покидает устройство; журнал доступа; 0 запросов | нет телеметрии по умолчанию; экспорт только по явному действию | ЩИТ, «СВОЁ · 0 облаков», ЗДОРОВЬЕ |
| Конфиденциальность | агрегаты вместо аудио в общих событиях; случайный id сессии | сообщения не попадают в логи; отзыв прекращает доступ | КАЗНА семьи, локальные хранилища |
| Юзабилити | событие = файл, открыл и работает; честные ограничения в README | «не заявлять успех без подтверждения»; понятный fallback | пробы-томограф, правдивые жёлтые/красные |

Ни один трек не противоречит закону. HARMONIA 05 (модель угроз) —
рекомендуется к прочтению каждому, кто трогает приватность дома:
девять угроз покрыты мерами, включая неудобную правду про «забыть
меня» (данные у третьих лиц удалить нельзя — поэтому мы им их не
передаём).

## 6. Малыш — чему научили в такте «КОДЕКС» (v0.8)

- Новые двери: «гармония» → ·40, «намерение» → ·41, «кодекс»/«треки» →
  этот документ.
- Слова формата: «харм» / «.harm» — Малыш объяснит, что это партитура
  намерений дома.
- Правило 15 «ТРЕКИ ДОМА»: документация треков живёт в ДОКУМЕНТЫ/ТРЕКИ,
  прототипы треков — двери ·40/·41 с фасетом lab; трек питает дом, но
  не заменяет его.
- Апстрим `singulyar-llm` (ОБУЧЕНИЕ/ПРАВИЛА_СИНГУЛЯРА.txt,
  ПРИМЕРЫ_КОМАНД.jsonl) обновляется отдельным ходом в своей репе;
  вшитая копия в `llm.mjs` до v0.8 синхронна по смыслу.

## 7. Что сделано в такте и что дальше

Сделано: паблик-архив треков в репо (`ДОКУМЕНТЫ/ТРЕКИ/`), прототипы
подняты в двери ·40 ГАРМОНИЯ и ·41 НАМЕРЕНИЕ (фасет lab, честные
кратко-описания), Малыш доучен до v0.8, журнал README дописан (хвост
R-13 закрыт), кэш воркера поднят, верификация и смоук пройдены.

Дальше — по порядку §4: профиль доступности (оси gran/offset), СЛОВО-
ПУЛЬС через `.harm`, валидатор + подпись библиотеки, ЛАН-ЗАЛ как
общий движок с Фазой 4 HARMONIA. Хвосты ШТАБа (ЭП-10 «вес и архив» —
решение владельца о mp3/LFS) остаются честно открытыми.
