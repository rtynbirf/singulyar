# ADR-0004 · Дефолт-ветка rumu и рабочая ветка main: статус-кво с защитной пломбой

- Статус: принято (волна FIX-2, 2026-11-08, мандат Хозяина «СТАНЬ МНОЙ · ИСПРАВЛЯЙ И ДОДЕЛЫВАЙ ПО КАЖДОМУ ПУНКТУ»)
- Контекст: issue #62 п.1, T11/П-11, аудит 2026-11-08
- Пломба-исполнение: `.github/workflows/main-drift-watch.yml`

## Контекст

В репозитории две живые ветки: `rumu` (дефолт, несёт Pages/живой сайт) и `main`
(рабочая линия). К 2026-11-08 они разъехались: main опережает rumu по части
латок, но отстаёт по объёму истории; зеркально rumu не содержит части работы
main. Одновременный «перескок» дефолта на main без подготовки сломал бы:

1. GitHub Pages (сборка живого сайта идёт от дефолтной ветки);
2. воркфлоу, запускаемые только из дефолтной ветки (cron);
3. ссылки документов на «главу» репы.

## Решение

1. **Статус-кво**: дефолтной остаётся `rumu`. Финальный флип — одна команда
   Хозяина (`PATCH /repos/rtynbirf/singulyar {"default_branch": "main"}`),
   выполняется ТОЛЬКО после: (а) main доритован до parity по контенту Pages,
   (б) зелёного такт-гейта на main, (в) явного слова Хозяина.
2. **Защитная пломба**: воркфлоу `main-drift-watch.yml` (cron, ежедневно)
   сравнивает `main` с `rumu` живым compare API и открывает issue-сводку,
   если расхождение растёт или main уходит вперёд без зеркала в rumu.
   Так дрейф двух голов становится видимым фактом, а не сюрпризом.
3. **Могильник хвостов** (issue #62 п.2) исполнен 2026-11-08: ветки
   `latka-c141-wip` и `minus-fond` удалены после пломбы; кончики живут в
   тегах `LATKA-C141-WIP-2026-11-08` (7f9edc2a) и `MINUS-FOND-2026-10-30`
   (695bfb63); оф-сайт бандл — release-vault, релиз `import/branches-2026-11-08`,
   ассет `singulyar-tails-tomb-2026-11-08.bundle` (sha256 474b5d6f…).

## Последствия

- Плюс: живой сайт и cron-пломбы не ломаются; дрейф под ежедневным контролем.
- Минус: два источника правды до флипа; цена — один issue в день при дрейфе.
- Отмена: флип дефолта Хозяином + удаление watch-воркфлоу.
