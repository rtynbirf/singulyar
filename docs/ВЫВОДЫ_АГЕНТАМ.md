# ВЫВОДЫ АГЕНТАМ — реестр уроков волны (ошибка → корень → починка → страж)

> **Статус:** ✅ Актуально · **Введён:** 2026-11-10 приказом владельца:
> «СДЕЛАЙ ВЫВОДЫ!!! И ЗАНЕСИ ВСЁ В РЕПО, ЧТОБ ОДНИМ АГЕНТАМ БЫЛО НЕ ПОВАДНО, А ДРУГИМ ПОЛЬЗА!!!!!»
> **Источник:** кампания «ЛКГ-1 + ПРАВДА-2» и её хвосты (2026-11-09…10): коммиты rumu `b2d5f47` → `abd3ee7` → `0247fa1`, пины cell-swarm `015a4814` → `0786b7c`, чужие (параллельные) ходы `3b178e1` (W1) и `200c0f6` (волна ×9).
> **Формула урока:** ошибка → корень → починка → страж. Страж — то, что делает повторение либо невозможным, либо громким.

## Зачем этот реестр (двойное назначение)

Тому, кто ошибся или соблазнится повторить, — **НЕ ПОВАДНО**: каждый урок здесь назван честно, с ценой (лишний круг, перепуш, красный ран, нервы владельца). После этого реестра повторить то же самое — уже не «случайность», а игнорирование писаного; это красный след, и он остаётся в журнале.

Тому, кто работает дальше, — **ПОЛЬЗА**: каждый приём из колонки «починка» выкопан из живой волны и готов к повторению: имена шагов, порядок, конкретные ша-якоря. Не изобретай то, что уже было выстрадано.

Правило пополнения: урок попадает сюда, если он (а) уже случился и стоил времени/перепуша/красного рана и (б) обобщается на любую будущую волну. Частные опечатки не заносятся. Новые уроки — append-only в конец своего раздела.

## А. Среда и доступ

### У-1. Шелл без памяти: экспорт не переживает следующую команду

- **Ошибка.** Токен вынесли `export GH_TOKEN=…` в одной команде шелла; следующая команда ушла без заголовка `Authorization` → GitHub ответил `401 Bad credentials`. Диагноз «токен мёртв» оказался неверным — владелец поправил: «ТОКЕН НЕ МёРТВ!!! НЕ ТУПИ=)».
- **Корень.** Каждая команда шелла — новый сеанс: переменные окружения не живут между вызовами. Пустой заголовок GitHub отвечает тем же кодом 401, что и отозванный токен, — код не различает «нет заголовка» и «плохой токен».
- **Починка.** Токен инлайнится в КАЖДУЮ команду: `GH_TOKEN=… python3 скрипт.py`. Скрипты читают `os.environ['GH_TOKEN']` на своём старте. Никаких ставок на экспорт.
- **Страж.** Прежде чем объявить «токен мёртв» — докажи, что запрос вообще нёс заголовок (минимальный GET того же токеном). Диагноз без вскрытия = домысел; в этой волне он стоил лишнего круга и нерпов владельца.

## Б. Git Data API (пуш без локального push-цепа)

### У-2. `parents` — это SHA КОММИТА, а не дерева

- **Ошибка.** Первый пушер волны собрал коммит, указав в `parents` SHA базового **дерева** (`base_tree`). Git Data API не валидирует родителя как коммит и молча создал осиротевшую родословную: 56 блобов и дерево повисли без коммита, посадку пришлось повторять.
- **Корень.** Механическая путаница двух SHA, которые пушер держит в руках одновременно: дерево (`base_tree`) нужно для сборки нового дерева, коммит (HEAD) — для родословной. API доверяет тебе и не проверит.
- **Починка.** В пушере переменные разнесены жёстко: `base_tree` — только в вызов `/git/trees`; `родитель = HEAD` (sha коммита) — только в вызов `/git/commits`; после посадки `родитель = коммит['sha']`, `base_tree = коммит['tree']['sha']` — следующий коммит встаёт поверх посаженного.
- **Страж.** Перед PATCH ref: `parents[0]` обязан быть sha, полученным из `/git/commits/…`, а не из `/git/trees/…`. Осиротевшие объекты руками не убирать — GC подберёт; но в журнал волны записывается факт (что осиротело, почему, оценка безвредности) — молчаливый брак запрещён.

### У-3. Локальный клон отстаёт от живого HEAD — СТОП-ГОРН, а не «дотолкну»

- **Ошибка.** Первый запуск хвостового пушера встал СТОП-ГОРНом: локальный HEAD ≠ живому — собственный же коммит, посаженный через API, не был подтянут в клон. Позже тот же горн честно поймал чужие ходы параллельных волн (`3b178e1`, `200c0f6`), вставшие в доме, пока эта сессия не работала.
- **Корень.** Пуш через Git Data API меняет репозиторий на стороне GitHub; локальный клон об этом не узнаёт сам. Толкать поверх непроверенного расхождения — риск затереть чужие байты (нарушение З.5).
- **Починка.** `git fetch origin rumu && git reset --hard FETCH_HEAD` — чужие байты целиком, свои переносим; расхождение ДО работы — это показание «дом жил без тебя», а не помеха. Пушер однофайловых латок теперь сам сверяет локальный и живой HEAD и встаёт горном.
- **Страж.** Порядок любой волны: СВЕРКА → fetch+reset при расхождении → СВЕРКА → работа → пуш → СВЕРКА. Каждый горн — в летопись волны (З.6).

## В. Красные прогоны — читать, а не глушить

### У-4. «ПИН УСТАРЕЛ» — красный не дефекта, а дизайн-гейта

- **Ошибка.** После каждой посадки в `rumu` оракул `oracle-rumu` краснеет «ПИН УСТАРЕЛ» (раны `42638053885`, `42638047456`). Соблазн — «чинить CI» или глушить проверку.
- **Корень.** Так и задумано: оракул сверяет `cell-swarm/swarm.json → cells[singulyar].pin` с живым HEAD `rumu`. Любой честный пуш в `rumu` ОБЯЗАН покрасить этот прогон, пока пин не догнан. Красный — сигнал «дом ещё не догнал сам себя», а не авария.
- **Починка.** Догон пина одноцелевым коммитом (меняется ровно одно поле `cells[singulyar].pin`; чужие байты `swarm.json` не тронуты; blob → tree → commit → ref), затем реран оракула. Хвост волны: два догона `015a4814` (за `abd3ee7`) и `0786b7c` (за `0247fa1`) — оба зелёные на реране.
- **Страж.** Чек-лист чистого следа (КАНОН §4): «после пуша в rumu — догон пина волной с правом, либо пометка хозяину». Красный ПИН, не догнанный в течение волны, = брошенный след.

### У-5. Наследованный красный ≠ твой красный: дифференциальный прогон

- **Ошибка.** Такт-гейт после волны стоял красным по девяти JS-оракулам (`s31_chuvstva/kodex/obereg/ruchki/slovo`, `nasled_logic`, `modules_logic`, `s33_fond_logic`, `svyazi_niti`; ран `42638047437`). Два пути в пропасть: признать «наша волна всё сломала» (неправда) или замести под ковёр (запрещено).
- **Корень.** База волны `6e753d0` была посажена с `[skip ci]` — её красные проявились только на первом прогоне волны. Сам красный ран не говорит, КТО принёс красное.
- **Починка.** Дифференциальный метод: прогнать все 44 оракула на базе и на волне, сравнить списки. Вердикт: 9 красных наследованы, 0 добавлено, 2 вылечены (`s31_slog`, `test_цех_правды.mjs`). Запись в KNOWN_ISSUES с раном и списком; позже дом догнал красные сам (`200c0f6`, «волна ×9») — метод подтвердился.
- **Страж.** Формулировка в журнале: «красный наследован — доказано дифф-прогоном база↔волна, ран такой-то». Числа без прогона не называются.

### У-6. Фейк-зелёный — единственный непрощаемый красный

- **Ошибка-соблазн.** Любое из: глушение оракула, `[skip ci]` на волне, у которой есть красные, правка теста «под ответ», временно поднятый порог.
- **Корень.** Страх перед красным вместо уважения к сигналу.
- **Починка.** Красный либо чинится, либо получает запись в KNOWN_ISSUES (ран, причина, владелец хвоста) — оба пути честные. КАНОН §5: интерпретация красных — через KNOWN_ISSUES, не через фейк зелёного.
- **Страж.** Красный с записью и владельцем — здоровый дом. Зелёный, купленный глушением, — авария, которую отложили и спрятали.

## Г. Законы дома, на которых горели

### У-7. Ручное число на лице дома = красный CI, а не «мелочь в разметке»

- **Ошибка.** Класс «числа-ложь» (КРУ F-019): 174 ручных числа-фолбэка на лицах — такт/кэш/счётчики, впечатанные руками в футер, meta, JSON-LD, README. Каждый выпуск — шанс разъехаться с реестром.
- **Корень.** Число живёт не у себя дома: нет единого источника правды.
- **Починка.** Единый источник — `data/versions.json → счётчики` (определения — в `счётчики.словарь`, 8 строк). Лица читают механизм: бирки `data-реестр=…`, `sg-registry` раздаёт ключи, цех правды выравнивает фолбэки (45 лиц). Поколение честно выводится из `S15_CACHE` (v236→v237).
- **Страж.** T-071/T-072/T-073 (`test_лица_правды.mjs` 9/9) + шаг «Лица ≡ реестру» (`цех_правды.py` dry-run = «ДРЕЙФ НЕТ») в такт-гейте. Новое лицо дома подключается биркой, не руками.

### У-8. Ядро офлайна: брак не глотается, активация спрашивает человека

- **Ошибка.** Воркер активировал неполную сборку (провал обязательного файла глотался в null) и обновлялся без спроса (безусловный `skipWaiting`); потолок `S15_MAX=140` мерил ядро+не-ядро вместе и резал ~33 старейших ЯДРОВЫХ файла на первом же не-ядровом put.
- **Корень.** Нет дымовой приёмки, нет человеческого согласия, потолок считал не то.
- **Починка.** `S15_ЯДРО_ОБЯЗАТЕЛЬНОЕ` (11 файлов): провал обязательного = брак установки — воркер не встаёт, last-known-good служит; старые кэши стираются ТОЛЬКО после честной приёмки нового кэша; активация = приёмка ∧ согласие человека (`S15_ВХОД_В_ТАКТ`, UI-ритуал — волна W1); `S15_MAX` считает только не-ядро.
- **Страж.** `test_sw15_приёмка.mjs` 6/6 (T-010/T-070). Канон §3: агрессивный skipWaiting запрещён. Любая правка `sw15.js` = бамп `S15_CACHE` — без исключений.

## Д. Артефакты и чистый след

### У-9. Зависший CLI-инструмент и грязные имена — диагноз, а не повод для борьбы

- **Ошибка.** Перепаковка пакета системным `zip` ушла в многаминутное молчание до таймаута; в пакете к тому же нашёлся мусорный каталог `файлы/".github/` (кавычка в имени — артефакт чужой распаковки).
- **Корень.** CLI-инструменты с интерактивными ожиданиями плохо управляются из скриптов; грязные имена из чужих архивов сами себя не чистят.
- **Починка.** Пересборка Python'ом (`zipfile`, DEFLATED уровень 9, фильтр имён с кавычками/апострофами/обратными кавычками): 66 записей, 0 мусорных имён, байты идентичны.
- **Страж.** После любой сборки архива — проверка списка имён (мусор = 0) и сверка с исходником. Странные имена чинить ДО посадки, а не после.

### У-10. Пломба — один комментарий, реальные SHA, ноль заглушек

- **Ошибка-соблазн.** Размазать отчёт по десятку комментариев и тредов; опубликовать пломбу с «SHA уточню позже».
- **Корень.** Желание отчитаться раньше, чем сделано.
- **Починка.** Пломба волны — ОДИН комментарий в живом трекере (для кампании ЛКГ-1+ПРАВДА-2: github-runbook #10, комментарий `6743140281`) с реальными SHA всех посадок и догонов. Черновик пломбы держится рядом и обновляется до реальных значений ДО публикации.
- **Страж.** Чек-лист чистого следа (КАНОН §4). Вычитка на заглушки перед публикацией: `【…】`, `XXX`, `TODO`, `undefined` — всё должно быть заменено фактами.

## Чек-лист перед пушем (выучить; вытекает из уроков)

1. Токен инлайн в каждую команду (У-1).
2. Живой HEAD ↔ клон сверены; при расхождении — fetch+reset --hard FETCH_HEAD (У-3).
3. `parents` = sha коммита-HEAD, `base_tree` отдельно (У-2).
4. После пуша — догон пина; красный ПИН без догона = брошенный след (У-4).
5. Красные — дифф-прогоном и записью в KNOWN_ISSUES, не гашением (У-5, У-6).
6. Числа — только из реестра; лицо подключается биркой (У-7).
7. Правки `sw15.js` — по закону ЛКГ и с бампом поколения; агрессивный skipWaiting запрещён (У-8).
8. Артефакты пересобраны проверенным инструментом, список имён чист (У-9).
9. Пломба одним комментарием, реальные SHA, заглушек нет (У-10).
