## 3. Базис, который уже стоит в доме (не строить заново)

### 3.1 · `js/opfs-core.js` — канон opfs-core/0.1 (такт v11.23 «СТОЙКОСТЬ», С100)
Порт `window.__ОПФС`, ES2019, без сети и DOM-правок. Готовый API для W2:
`возможности()` · `постоянное()` · `закрепить()` (Storage persist — защита от вытеснения) ·
`положить(ид, данные)` · `взять(ид)` · `есть(ид)` · `убрать(ид)` · `список()` (точные иды файлов каталога) · `оценка()` (usage/quota от `navigator.storage.estimate()`).
Каталог по умолчанию — **«фонограммы»**; закон идов: ASCII `^[A-Za-z0-9][A-Za-z0-9._-]{0,119}$` без «..» — YouTube-иды проходят.
Подключён в **·15/·19/·38**; в **·32 НЕ подключён** (одна строка `<script src="js/opfs-core.js" defer>` — CSP ·32 уже разрешает `'self'`).

## 4. Карта посадки W2 (предложение разведки — волна решает)

1. **`js/room-38.js` (+ `СИНГУЛЯР_38_ПУЛЬС.html`)** — секция «Готовность дома»: четыре состояния + счётчик.
   - `CORE_READY` — приёмка ядра воркера (уже есть честный `S15_ПРИЁМКА`/PING от ЛКГ-1 — не выдумывать числа, читать воркера);
   - `MODEL_READY` — слух+мозг уже считает room-38 (кэши `s15-ai-v1`/`transformers-cache`/`singular-llm-parts-v1`);
   - `P2P_READY` — честное определение: модули связи в кэше ядра + поддержка `RTCDataChannel` браузером; число/факт — из реестра, не руками;
   - `SONG_READY`/счётчик — `__ОПФС.список()` каталога «фонограммы» (точные иды и их вес) + `__ОПФС.оценка()` для квоты;
   - **прогрев «вечера»**: выбор песен × языков → **прогноз объёма** (HEAD-запросы content-length — ноль тел, по образцу ПУЛЬСА) → скачивание в `__ОПФС.положить()` с прогрессом и **отменой** (AbortController); перед прогревом — предложить `__ОПФС.закрепить()`.
2. **`СИНГУЛЯР_32_СЦЕНА.html`** — лестница получает первую ступень OPFS: если песня выучена (есть в «фонограммах») — играть из OPFS (в самолёте поёт); далее дверь-0 → raw → jsDelivr. Полный отказ лестницы — **`SONG_UNAVAILABLE`**: честная карточка с причиной («внешние хосты не отвечают; песня не выучена»), не молчание, не автопереход.
3. **`data/versions.json`** — новые ключи словаря с определениями: `готовность_ядра`, `готовность_песен`, `готовность_моделей`, `готовность_p2p`, `аудио_в_хранилище` (счётчик), `песня_недоступна` (состояние) — имена ключей финализирует волна.
4. **Стражи (новые)** — `ИНСТРУМЕНТЫ/test_готовность_фонда.mjs` (+ браузерная проба по надобности): выученная поёт из OPFS без сети; невыученная честно помечена; отказ хоста объясним; счётчики из словаря; медиа не влезло в пре-кэш.
5. **`sw15.js`** — если правится: бамп `S15_CACHE` v240→v241; новые активы — только код/документы в `S15_CORE`; **медиа не класть**.
6. **Языки для «вечера»** — тексты языков живут в `ДАННЫЕ/…` (многоязык): тела выбираемых языков — тоже вне пре-кэша; класть в OPFS/склад по выбору человека, считать в прогнозе объёма.

## 6. Открытые вопросы волны W2 (решаются внутри волны)

1. **Иды OPFS** — рекомендация разведки: ид = YouTube id (единая правда с фондом ·31 и складом «s31-склад»); суффикс для ступени (`голос/`/`минус/`) — на совести волны.
2. **P2P_READY без вранья** — «модули в кэше + браузер умеет DataChannel» это *возможность*, не соединение; формулировка на лице должна это честно отделять.
3. **Тон-тест и шасси** — `./minus/prosto-lubi.mp3` в ядре — осознанное исключение с досье (TH-AUDIO-44/45); W2 его не «чинит» и в счётчик выученного не путает.
4. **Т-015/T-016** — номера КРУ V1 в репо не живут; стражи именовать по факту волны, в отчёте честно сослаться на приёмку ТЗ §2.
5. **Объём прогноза при отсутствии content-length** — часть ответов без заголовка: показывать «—» и честную оговорку (образец — таблица кэшей ·38).
