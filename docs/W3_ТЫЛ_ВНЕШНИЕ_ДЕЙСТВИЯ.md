## 4. Карта посадки W3 (предложение разведки — волна решает)

1. **Словарь состояний внешних действий** — единый канон: `не готово / готово / живое / отказано / истекло / отозвано` (имена финализирует волна). Каждое — в `счётчики.словарь` с определением (T-073).
2. **Журнал внешних действий** — append-only журнал у человека на устройстве (ключи kv/склад, не телеметрия): *когда · что · куда (провайдер/узел) · состояние · чем отозвано*. Определение «журнала» — по мировой практике: записи consequential-действий, по которым человек восстанавливает «что произошло, кто инициировал, что затронуто» (§5, saasframe).
3. **Capability-бейджи** — бейдж = способность (что разрешено, где, отозвано ли), читает состояние из реестра, не руками: ·48 К1–К4, ·42 инструменты Policy Engine, ·53 контур, ·54 приглашения.
4. **·54 invite/TTL/revoke** — канон приглашений pir-core: срок жизни вшивается в JSON-код при выдаче (поля «выдан»/«истекает»); приём кода проверяет часы получателя; отзыв — локальный список отозванных у выдающего; принимающий в глухом режиме честно видит окно, а не обещание. Страж обязан: просроченный код отклоняется, отозванный — отклоняется.
5. **·42 PIN** — сверка без открытого текста (SubtleCrypto/PBKDF2), ограничение попыток с честным бэк-оффом (локальным, без самозаточения), отзыв подтверждения виден в журнале и бейджем сразу.
6. **Статусы F-012 → ·33/·49** — карточка «внешние провайдеры»: узлы цепей ·33 (жив/отказ/задержка) и касса ·49 (законное «рельсы не подключены») читаются из реестра статусов; отказ узла объясним в UI (преемственность SONG_UNAVAILABLE W2).
7. **ГОТОВНОСТЬ.manifest → живой реестр статусов (F-011)** — производства переносятся в `data/статусы.json` (имя файла решает волна), sg-registry речитывает; карточки дверей и ·55 читают оттуда; `ГОТОВНОСТЬ.manifest.json` остаётся архивной пломбой либо гасится — решение с цехом правды (открытый вопрос №4).
8. **·47/·48 Device Flow — состояния** — лица показывают честные состояния авторизации (код выдан / ждёт / принят / истёк / отозван) и журнал; интервалы и сроки — по RFC 8628 (код ~15 мин, опрос от 5 с), сам OAuth-сервер домом не порождается: дом только честно отображает и журналирует.
9. **Страж волны** — `ИНСТРУМЕНТЫ/test_внешние_действия.mjs` (имя финализирует волна): журнал append-only цел и не переписывается; просроченное/отозванное отклоняется; бейджи — из реестра; словарь счётчиков полон; CSP не тронут; `node --check` всех правленых JS.
10. **sw15.js** — если волна вносит новые активы в пре-кэш: бамп `S15_CACHE` v245→v246; медиа и модели не класть; противном случае воркер не трогается (прецедент docs-хода W2-тыл).

## 6. Открытые вопросы волны W3 (решаются внутри волны)

1. **Нумерация ТЗ vs карта дома.** «·47 Device Flow» — Device Flow живёт и в ·47 (инструкция человека), и в ·48 (каналы К1/К2); «провайдеры» — это каналы вывода ·48 и касса ·49. Волна фиксирует справку в разборе и байты дверей не переезжает (З.5: чужие ходы не трогать).
2. **«Отзыв виден сразу» на статике без сервера.** Отзыв — локальный список отозванного у держателя права; принимающий без сети узнаёт о отзыве не сразу. Формулировка на лице обязана отделять «возможность» от «соединения» — преемственность W2 (`P2P_READY` ≠ соединение).
3. **Где живёт журнал.** localStorage против OPFS против обоих; срок хранения; экспорт/импорт; ноль телеметрии наружу (закон дома). Рекомендация разведки: append-only в kv с потолком и честным экспортом — решает волна.
4. **`ГОТОВНОСТЬ.manifest.json` — пломба или источник.** F-011 требует «живой» реестр; перенос в `data/статусы.json` меняет лицо v1.60.0 — проход цеха правды обязателен в той же волне.
5. **Механика PIN ·42.** Вскрывается волной; если PIN сверяется открытым текстом или без ограничения попыток — латка внутри волны, без отдельной дороги.
6. **Часы глухого режима.** TTL проверяется часами получателя; без сети расхождение часов делает окно неточным — честная оговорка в UI (образец — оговорки content-length в таблице кэшей ·38).
