## 2. Карта посадки ×10 — исполнение

1. **Словарь состояний** — 6 определений в версions.json (выше).
2. **Журнал внешних действий** — ядро `js/внешние-действия.js` (`внешние-действия/0.1`, ES2019, опоры-инъекция по канону opfs-core/0.1): `журнал.добавить/список/печатиСходятся/экспорт`, поля записи *когда · дверь · действие · куда · состояние · примечание · печать* (формат consequential-действий по карте посадки).
3. **Capability-бейджи** — `ВД.бейдж.для(ид)`: база — реестр статусов, факт устройства перекрывает; честный источник в каждой строке панели (`title`).
4. **·54 invite/TTL/revoke** — `pir-core/0.1 → 0.2`: срок вшивается в код при выдаче (`ид/выдан/истекает`, по умолчанию 30 минут, `срокМс` переопределяет); приём кода сверяет часы получателя (просроченный — честный отказ с оговоркой о расхождении часов, канон RFC 8628); ответ эхоит ид (чужой ответ слышен); `идПоследнегоПриглашения()` отдаёт держателю для журнала и отзыва. Комнаты и appId `singulyar-pir-0.1` не тронуты — обратная совместимость.
5. **·42 PIN** — ядро `js/pin-core.js` (`пин-ядро/0.1`): PBKDF2-SHA256 310 000 итераций (SubtleCrypto, соль 16 байт), сверка без открытого текста (открытый текст в хранилище табу — страж ловит), бэк-офф попыток 30 с × 2^k с потолком 15 минут (без самозаточения); лицо ·39 переведено с «любой 4-значный принимается» на честную механику: первое подтверждение задаёт PIN, далее сверка; статус-строка `#статусПин`.
6. **Статусы F-012 → ·33/·49** — панель на обоих лицах; ·33 пишет факт разведки в журнал (`ВД.опр`: живой узел + по дороге промолчавшие).
7. **Живой реестр (F-011)** — `data/статусы.json` + sg-registry (`SG_СТАТУСЫ` + событие `sg-статусы-готов`, кандидаты вверх по лестнице подпапок).
8. **·47/·48 Device Flow — состояния** — панели обеих дверей; дом OAuth-сервер не порождает: инструкции ·47 держат формулировку «вводить только на github.com/login/device», реестр держит состояние «не готово» + канон RFC 8628; журнал ловит факты устройства.
9. **Страж волны** — `ИНСТРУМЕНТЫ/test_внешние_действия.mjs`, 8 проб: словарь; реестр (приёмка «каждое действие имеет состояние и замер» + покрытие дверей + уникальность ид); ядро ВД (append-only, печати, подмена ловится, бейдж-слияние, отзыв); pir-core/0.2 (TTL-юнит + исходник); пин-ядро (PBKDF2, бэк-офф, потолок); лица (×7 нитей); воркер (v246 ≡ реестру, активы в пре-кэше, mp3-исключения прежние 2, ноль нового медиа); sg-registry + node --check.
10. **sw15.js** — бамп `S15_CACHE` v245→v246 по закону обновления; пре-кэш +7 лёгких активов (2 ядра, реестр статусов, 4 дока волны — закон новых активов, образец W1/W2); медиа и модели в пре-кэш не входят — mp3-исключения прежние 2.

## 5. Открытые вопросы волны (сняты честно, не молча)

1. **`ГОТОВНОСТЬ.manifest.json` — пломба или источник** — осталась пломбой; живой реестр построен рядом (`data/статусы.json`); демонтаж — слово владельца/цеха правды.
2. **Отзыв принимающему** — у держателя виден сразу; принимающий без сети узнаёт при следующей сверке — граница названа на лице ·54 (преемственность P2P_READY ≠ соединение).
3. **blockchain.info в CSP** — узел в авто-порядке разведки ·33, но `connect-src` его не пускает: разведка честно покажет отказ, реестр держит прореху открыто; латка CSP — слово владельца.
4. **Часы глухого режима** — TTL сверяется часами получателя; оговорка о расхождении часов вшита в отказ pir-core.
5. **Живая поверка ЭП-06 (скриншоты веток выдано/истекло/отозвано + отказ узла)** — за выпускающей волной/живым агентом (прецедент W2); страж держит канон байт.
