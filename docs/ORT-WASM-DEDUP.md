## Политика

1. **Канон одной копии**: `ort-wasm-*.wasm/.mjs` живут ОДНОЙ копией в
   `singulyar/vendor/ort/` (караоке-вселенная — основной потребитель).
   Второй сайт (`rtynbirf.github.io`) должен получать файл копированием на
   своей сборке (build-step склейка), а не хранить собственный бинарь.
2. **Агенты не удаляют чужие бинари.** Файл в `rtynbirf.github.io` — вне
   мандата волны: удаление/замена — отдельное решение владельца (одна команда
   в чужом репо + правка ссылки/склейки). Настоящая волна добавляет только
   детектор и эту политику.
3. **Детектор** `scripts/ort_wasm_dupes.py`:
   - инвентаризирует ort-wasm файлы локального дерева (путь, размер, blob sha);
   - через API (GITHUB_TOKEN) сверяет blob sha с деревом
     `rtynbirf/rtynbirf.github.io`; повторяется — рапорт о дубликате и экономии;
   - `--check` возвращает rc=2, пока дубликат существует (гейт для будущей
     волны дедупа); `--selftest` — детерминированный самотест на фикстурах.
4. **Офлайн-требование**: пока вторая копия не снята, плеер обеих площадок
   стартует офлайн (файлы в дереве). После дедупа офлайн-старт для
   `rtynbirf.github.io` обязана обеспечивать его сборка (копирование файла в
   артефакт деплоя) — проверять живым офлайн-прогоном, не по вере.
