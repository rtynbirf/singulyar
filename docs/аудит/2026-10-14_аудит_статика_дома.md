## 1. Вердикт в пяти строках

1. Дом **живой и дисциплинированный**: 44 двери по реестру, 161 файл в пре-кэше (ни одного отсутствующего), ноль битых локальных ссылок на дверях, ноль `eval`, ноль `tabindex>0`, у всех 20 картинок есть `alt`, у всех 42 страниц ядра есть `lang`, `viewport`, `title`. Для проекта с десятком агентов, пишущих параллельно, это сильный результат.
2. **Главный риск — вес.** Рабочее дерево 1738 МБ, из них `minus/` 1620 МБ (минусовки). У GitHub Pages потолок опубликованного сайта 1 ГБ \[ИСТОЧНИК\]. Я не могу проверить, как деплой с этим справляется, поэтому это пункт P0 «проверить немедленно».
3. **Главная дыра качества — тесты красные.** Из 37 JS-файлов тестов 11 падают на HEAD. Почти все — не поломки дома, а «протухшие оракулы»: числа и штампы зашиты в тесты (42, 23, v1.14.0), а дом вырос до 44–45. Но одно падение настоящее: нарушена симметрия нитей s31·s35.
4. **Главная дыра доступности — общее, а не частное.** Скип-ссылка есть на 1 из 42 страниц, `:focus-visible` в самой странице на 24 из 42, `prefers-reduced-motion` на 27 из 42, а в общем CSS дизайн-системы только одно правило `:focus-visible` и ни одного `forced-colors` / `prefers-contrast`. Для дома, чей закон — «эргономика во главе угла», это главный разрыв между заявленным и измеримым.
5. Идея «**смысл один — представление твоё**» в доме реализована для коммуникации (·19–·22), но **не применена к самому дому**: у каждой двери своя копия правил доступности. Ниже (раздел 5) моё предложение, как это превратить в свойство, которое возникает из архитектуры, а не пишется руками в каждой двери.

## 3. Находки по приоритетам

### P0 — проверить или исправить немедленно

**P0-1. Размер публикации против лимита GitHub Pages.** \[ИСТОЧНИК: docs.github.com, «GitHub Pages limits»\] Опубликованный сайт — не более 1 ГБ; репозиторий-источник — рекомендованный предел 1 ГБ; мягкий лимит трафика 100 ГБ в месяц; таймаут деплоя 10 минут; мягкий лимит 10 сборок в час (не действует при публикации через собственный GitHub Actions workflow). У вас 1738 МБ в дереве. Что делать: открыть вкладку Actions → последний деплой «pages build and deployment» и посмотреть размер артефакта и статус; если артефакт близок к 1 ГБ или деплой падает с таймаутом — тяжёлое выносить (см. ТЗ-2). Что проверено: только сам лимит. Что не проверено: как деплой ведёт себя фактически.

**P0-2. Красный CI.** 11 из 37 файлов тестов красные; ни один новый такт не может честно доказать «я ничего не сломал», пока норма — красное. Что делать: ТЗ-1.

**P0-3. Настоящее нарушение симметрии нитей s31·s35.** Тест нити падает не из-за устаревшего числа, а из-за асимметрии связи в манифесте. Это единственная красная проверка, указывающая на реальную поломку структуры. А вокруг ·55 асимметрия большая: манифест связывает s55 с ·18–·26, а мостов-ответов в этих файлах нет (дорожная карта дома называет это линией О-3).

### P1 — в ближайший месяц

**P1-1. Вес входа.** Три двери по 7,6–14,6 МБ одним HTML-файлом (·01, ·02, ·02б). Скрипт — 14,1 МБ из 14,6. Парсинг такого файла на среднем телефоне — секунды блокировки основного потока, что бьёт по INP/LCP. \[ОПЫТ\] Пороги Core Web Vitals на 14.10.2026: LCP ≤ 2,5 с, INP ≤ 200 мс, CLS ≤ 0,1 по 75-му процентилю реальных пользователей \[ИСТОЧНИК: Google web.dev / Search Central; в сети ходит слух о «2,0 с», он опровергнут сводкой, проверенной 14 августа 2026, поэтому я его не использую\]. Своих замеров у меня нет, их надо снять (ТЗ-2).

**P1-2. Доступность как общая инфраструктура.** См. раздел 1, п. 4. Стандарт-ориентир сегодня — **WCAG 2.2**, он же международный стандарт ISO/IEC 40500:2025; Европейский закон о доступности (EAA) опирается на EN 301 549, который сводится к WCAG 2.1/2.2. WCAG 3.0 остаётся рабочим черновиком (последняя редакция 3 марта 2026), финал ожидается не раньше 2028 \[ИСТОЧНИК: W3C WAI, обзоры\]. Значит, мерка для дома — 2.2 AA, а 3.0 — повод запланировать, но не сдавать на неё.

**P1-3. `CHANGELOG.md` в пре-кэше (0,4 МБ) и в корне.** README 107 КБ, CHANGELOG 399 КБ. Правило «один факт — одно место» нарушено самим объёмом: живая документация и летопись разработчиков смешаны с пользовательским телом. Что делать: убрать из пре-кэша; летопись перенести в `docs/`.

**P1-4. Архив публикуется как часть сайта.** 28 страниц-прототипов без CSP и описаний индексируются поисковиками и наследуют домен дома. Что делать: закрыть в `robots.txt` и поставить `noindex` (или вынести архив в отдельную ветку/репозиторий).

**P1-5. Цепочка поставки.** Пять внешних скриптов без SRI, 227 мест `innerHTML`. Что делать: ТЗ-5.

**P1-6. Лицензионная чистота музыки.** \[НЕ ПРОВЕРЕНО\] В `minus/` — минусовки песен, имена файлов — идентификаторы вида `Qb8xb0vUYDg`, похожие на идентификаторы видео YouTube. Я не знаю происхождения и лицензий этих записей и ничего не утверждаю. Но если сайт публично раздаёт чужие минусовки, это единственный пункт дома, где риск не технический, а правовой: проверить происхождение каждой из 62 записей и права на публичную раздачу, а там, где прав нет, перевести на режим «пользователь приносит свою». Большинство коммерческих продуктов таких вещей не имеют. Это нужно сохранить, а не «выровнять по рынку».

## 5. Своё: эмерджентное решение — «заявление = проверка»

Идея, из которой растёт остальное: **дом должен подчиняться собственному принципу.** Для коммуникации у вас уже сказано «смысл один, представление твоё». Для самого дома это пока не так: смысл («эта дверь работает, доступна, весит столько-то, связана с такими-то») записан десятком рук в README, тестах, манифесте и шапках, и расходится (43 / 44 / 45 дверей, v11.35 / v11.42, 23 вместо 44 в тестах). Предлагаю одну систему из пяти механизмов. Эмерджентное свойство появляется там, где механизм заставляет новое работать без правки старого.

**Э-1. Паспорт двери** \[ПРЕДЛОЖЕНИЕ\]. Для каждой двери CI порождает машинный файл: номер, имя, файл, статус по пяти ступеням дома, вес, модальности, измеренные (не заявленные) признаки доступности, офлайн-готовность, обращения к сети, что хранится на устройстве, связи. Хаб, поиск АРИАДНА, ·37 О ДОМЕ, тест нитей и счётчики читают только паспорта. *Эмерджентно*: добавленная дверь автоматически видна, честно помечена и проверена на симметрию нитей; число дверей одно во всех местах; класс дефектов «протухший оракул» исчезает. *Проверка*: дверь без паспорта роняет CI; ни один тест не содержит числа дверей литералом.

**Э-2. Профиль человека как слой дома** \[ПРЕДЛОЖЕНИЕ\]. ·19 ЧЕЛОВЕК хранит локальный профиль: размер текста и масштаб, движение, контраст, способ ввода (касание, клавиатура, переключатель, голос), способ вывода (текст, речь, Брайль, вибро), язык, нагрузка. Один общий слой переводит профиль в CSS-переменные и системные `prefers-*`/`forced-colors`; каждая дверь подключает его до собственных стилей и может только расширять. *Эмерджентно*: «смысл один — представление твоё» работает на всём доме; доступность перестаёт писаться руками в 44 местах и становится наследованием, а новая дверь получает её даром. Профиль не покидает устройство и экспортируется человеком. *Проверка*: переключение в ·19 меняет вид всех дверей из паспорта; скрипт обходит все паспорта.

**Э-3. Оболочка и тело** \[ПРЕДЛОЖЕНИЕ\]. Оболочка (навигация, ·19–·26, профиль, поиск) гарантированно офлайн и укладывается в бюджет. Тело (песни, минусовки, модели) подгружается по манифесту, с хэш-именами, докачкой, учётом квоты и видимым статусом «в доме / на устройстве / во внешнем хранилище». Медиа живёт вне Pages, а «принеси свою минусовку» из файла работает локально. *Эмерджентно*: дом растёт без раздувания публикации, хозяин сам решает, что хранить, а вопрос прав на чужие записи перестаёт быть вопросом хранилища. Обещание «поёт без сети» сохраняется для оболочки и для выбранных песен.

**Э-4. Намерение → путь** \[ПРЕДЛОЖЕНИЕ\]. Композер из пакета EMERGENT встраивается за ·21/·22, а не рядом, и выбирает путь по **паспортам**, а не по regex (аудит пакета: `/нем/`, `/лицо/`, `/связ/` срабатывали на любые слова). Каждый вариант несёт объяснение и статус; запасной путь — всегда текст. *Проверка*: таблица фраз и контрпримеров, ложных срабатываний 0 на ней.

**Э-5. Доказательство выпуска** \[ПРЕДЛОЖЕНИЕ\]. Каждый такт выпускает пакет доказательств: тесты, проверка доступности, бюджет веса, лабораторный замер LCP/INP/CLS на мобильном профиле, проверка ссылок и нитей. Условие ритуала «такт без живой поверки ЭП-06 не считается вышедшим» становится машинно проверяемым.

### Волна 4 — реальная связь (по готовности)

- Один сквозной сценарий с одним реальным адаптером и **подтверждением доставки** (то, чего в пакете EMERGENT пока нет: все внешние адаптеры `not-connected`).
- Мониторинг WCAG 3.0: пересмотр критериев, когда черновик станет кандидатом в рекомендацию.

### Чего не делать

- Не переписывать комод-архитектуру и не выносить вещи из ящиков.
- Не менять CSP-постур прода, пока report-only эксперимент не доказал безопасность.
- Не писать «соответствует WCAG» без протокола ручной проверки.
- Не называть композер «рабочим», пока нет подтверждённой доставки.
- Не «выравнивать под рынок» то, что у дома лучше рынка (честные статусы, офлайн-суверенитет).

### Риски и зависимости

- У меня нет токена на пуш, а по `AGENTS.md` пуш идёт только через Git Data API; значит, исполнение остаётся за вашими агентами или за вами. Я могу готовить идемпотентные патчи на закреплённый коммит.
- Репозиторий меняется каждые несколько часов, возможны «стоп-горны» (встречные такты): каждый патч нужно перепривязывать к актуальному `main`.
- Правовой блок (минусовки) может перекроить Волну 3.

## 8. Как повторить измерения

Скрипт `audit_singulyar_static.py` приложен отдельным файлом: он обходит все `.html` в клонированном репозитории и считает признаки из раздела 2. Он статический, поэтому он не заменяет прогон в браузере (раздел 0).

```
git clone --depth 1 https://github.com/rtynbirf/singulyar.git
cd singulyar && git rev-parse HEAD            # сверить с 4cb0217
python3 audit_singulyar_static.py              # страницы, ссылки, мета
node --test ИНСТРУМЕНТЫ/<файл>                  # тесты по одному, как велит AGENTS.md
```

Примечания по честности скрипта: он считает «битыми» также абсолютные пути `404.html` (`/singulyar/…`) и строки внутри JS вроде `src='demo'`. Это ложные срабатывания, я их вручную исключил из раздела 2. Проверка мета в нём смотрит первые 20 000 символов, поэтому для ·31 она сначала дала ложный минус; итоговые числа пересчитаны по полному файлу.
