# ЛЮК ВЕСОВ GAZE — процедура приведения взгляда в дом

**Такт v10.98 «ВЗГЛЯД» (С74) · строка А3, шаг 3 · владелец + агент**

Модель gaze (Face Landmarker / iris-рантайм) живёт у владельца (закон честности:
дом не тащит и не качает веса; репа весов `rtynbirf/singulyar-llm` — соседняя).
Эта процедура — полный путь модели: от локального файла до пина в ledger
адаптера `input.gaze`.

## Шаг 1 — взять модель (локально, вне Pages)

Подходят веса любого локального рантайма, который умеет давать «замороженный
ответ» (кадр → черта взора): MediaPipe Face Landmarker (`.task`), wasm-сборки
трекинга взгляда, локальный сервер вывода. **Размеры и SHA-256 дом по памяти
не называет** — пин фиксируется только по факту скачки файла. Граница дома:
файл ≤100 МБ; крупнее — раскрой на части инструментом `раскрой_весов.py`.

Веса взгляда нейтральны к языку — Закон о языках (rus → srp → kaz → deu) на
них не действует; он действует на СЛОВАРЬ калибровочного сеанса (подсказки
владельцу «смотрите в точку») и — при будущих голосовых подсказках —
выбирается по тому же закону.

## Шаг 2 — проверить и (если нужно) раскроить

```bash
sha256sum face_landmarker.task
# файл ≤100 МБ идёт одной частью; крупнее — тот же инструмент, что у Whisper/OCR:
python3 БИБЛИОТЕКИ/adapter-os/tools/раскрой_весов.py face_landmarker.task --вых GAZE
```

## Шаг 3 — выложить в репу весов

1. Клонировать `rtynbirf/singulyar-llm`.
2. Создать каталог `GAZE/`, положить файл(ы) + вписать раздел «GAZE» в
   `MANIFEST.txt` (имя — размер — SHA-256 каждой части).
3. Закоммитить и запушить (PAT — у агента).

## Шаг 4 — пин в доме

В `БИБЛИОТЕКИ/adapter-os/adapters/gaze.mjs` регистрируется модель с пином:

```js
registerGazeModel({
  id: 'face-landmarker',                  // имя читаемое, без «/»
  runner: <замороженный ответ рантайма>,  // кадр → { черта: { x, y, уверенность } }
  движок: 'wasm-воркер / локальный сервер вывода',
  веса: {
    имя: 'face_landmarker.task',
    sha256: '<64 шестнадцатеричных знака из шага 2>',
    байт: <размер файла>,
    частей: 1,
  },
});
```

С этого момента статус адаптера `input.gaze` — READY с пином; до этого —
EXPERIMENTAL, честно (критерий А3: «модель пинится и проходит контрактные
тесты»).

## Шаг 5 — калибровка (обязательный сеанс владельца)

Контракт честен: landmarks не являются calibrated gaze. Перед первым
указателем собирается калибровка `gaze-calib-affine/0.1` — пары «точка кадра →
точка экрана» (минимум 3, на практике 5–9 по углам и центру; сеанс —
десятки точек при точной подгонке). Дом считает аффинное соответствие
наименьшими квадратами и называет остаток честно (`ошибка_средняя` /
`ошибка_макс`): плохой сеанс виден числами, а не обещаниями. Держатель
калибровки — сторона владельца; адаптер принимает её в задании.

## Шаг 6 — бенчмарк (ledger трека)

Корпус владельца (размеченные пары «кадр → эталонная точка взгляда») прогоняется
через `gaze-bench.mjs::прогонБенчмаркаGaze`: протокол евклидовой ошибки +
доля точек в допуске (допуск называет запускающий) ложится в ledger трека.
Тайминги устройств измеряются снаружи. Качество калибровки меряется отдельно
(остаток соответствия) — две меры не подменяют друг друга.

## Оффлайн-кэш (закон приватности)

Кэширование модели в браузере — по образцу llm.mjs (срез 4): Cache API, один
раз, дальше из кеша; `защищённые_кэши` versions.json уже держит
`transformers-cache` — новый ключ (`singular-gaze-v1`) добавляется владельцем
при пине. Runner обязан быть 0 сети: контракт принимает замороженный ответ,
веса уже локальны. Камера не покидает устройство — кадры не пишутся и не
отправляются никуда.

## Сторожа люка

- подпись кадра проверяется адаптером по магическим байтам (не по ярлыку);
- SHA-256 целого = склейка частей по порядку — проверяется и раскроем, и
  `сверитьПин()` в рантайме (расхождение → данные не выдаются);
- веса НЕ попадают в Pages-репу дома;
- выход проекции за экран не поджимается — честный флаг `в_границах`;
- пока пина нет — нигде не пишется «проверено»: EXPERIMENTAL честно.
