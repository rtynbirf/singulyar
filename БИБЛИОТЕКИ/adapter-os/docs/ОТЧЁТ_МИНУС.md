## Что сделано (шаг 4 из пяти — Demucs)

### 1. `adapters/demucs.mjs` — реализация контракта разделения

- **Ledger `adapter-os.demucs.v1`** — пуст на импорте (моделей в доме нет, и
  это честно); записи возвращаются копиями.
- **Честное разделение труда** — контракт требует «audio → четыре стема»,
  дом берёт своё: ДВИЖОК — рантайм владельца (Demucs WASM / локальный
  сервер, дом не тащит и не запускает веса — правда платформы ≤100 МБ);
  ПОДПИСЬ АУДИО, СТРОГИЙ РАЗБОР, ЧЕСТНЫЕ ЧИСЛА — три детерминированных ядра
  дома, покрытых тестами байт-в-байт.
- **Контракт runner** — синхронный, чистый, 0 сети (родня speech.mjs /
  ocr.mjs / gaze.mjs): `runner(задание) → { стемы: { vocals, drums, bass,
  other }, смесь?, частота_дискретизации? } | { отказ }`; wasm-воркер и
  прочие асинхронные рантаймы приносят «замороженный ответ».
- **ПОДПИСЬ АУДИО** — магические байты, 5 форматов (wav RIFF/WAVE, mp3 ID3
  или frame-sync, ogg OggS, flac fLaC, m4a ftyp); «названо wav, лежит ogg» —
  честный отказ, звук не подменяется молча.
- **Строгий разбор** — ровно четыре канонических стема (лишний ключ — мусор,
  недостающий — отказ), равные длины (каналы одного микса), конечные
  отсчёты; **диапазона на отсчётах НЕТ** — конечность требует разбор,
  поджатие не делаем; смесь (если названа) — той же длины; частота (если
  названа) — конечное число > 0.
- **Честные числа стемов** (`числаСтемов`) — рмс/пик/громкость_дБ/доля
  мощности по каждому стему: кто главнее в миксе — видно числами, а не
  обещаниями; тишина стема названа честно (рмс 0 → громкость null,
  «тишина: true» — выдуманный −∞ в JSON — грех подмены); сумма долей —
  1 математически (один знаменатель), у полной тишины доли не выдумываются.
- **Остаток микса** (`остатокМикса`) — смесь − сумма стемов, та же честность,
  что остаток калибровки gaze.mjs: расхождение названо числами
  (`рмс_остатка`, `против_смеси_дБ`), полная сходимость названа словами;
  f32-остаток тождественного микса (~1e-8, −153 дБ — за порогом слуха) тоже
  назван числом, а не скрыт обещанием.
- **Пин весов all-or-nothing** + `склеитьЧасти`/`сверитьПин` через
  crypto.subtle (SHA-256; вектор "abc" держат все четыре копии — speech, ocr,
  gaze, demucs; копия механики сознательна: самодостаточность адаптера,
  расхождение ловят тесты). Расхождение — данные не выдаются даже на байт.
- **Честный мок** — всегда отказ «МОК demucs: модели нет в доме…».
- **Дверь `разделить`** — никогда не бросает; порядок честный и
  детерминированный: валидация → ledger → runner → строгий разбор → честные
  числа → остаток (если смесь названа); одна модель — она, несколько — id
  обязателен.
- **`createDemucsAdapter`** — статус по ledger: EXPERIMENTAL (пусто/без пина)
  → READY (есть пин), privacy local — звук не покидает устройство.

### 2. `adapters/demucs-bench.mjs` — бенчмарк на своих честных мерилах

Разделению звука — своё честное мерило: **SDR без выравнивания**
(10·log10(||эталон||² / ||эталон − оценка||²)); граница названа в протоколе
(«bss_eval не притворяется»). **Идеальная сходимость пишется словом, не
числом** — JSON.stringify(Infinity) молча дал бы null, а это грех подмены;
тишина в эталоне — «не мера», число не выдумывается. Энергопрофиль оценок
(рмс) назван даже там, где SDR не мера. Текстовые мерила speech-bench и
геометрия gaze-bench сюда не тянутся. Протокол `adapter-os.demucs.bench.v1`
без часов, детерминирован байт-в-байт (стемы идут по канону).

### 3. `docs/ЛЮК_ВЕСОВ_DEMUCS.md` — процедура приведения весов

Модель → раскрой (`tools/раскрой_весов.py`; htdemucs крупнее 100 МБ — части)
→ репа весов `singulyar-llm → DEMUCS/` → пин → контрактные ожидания движка →
бенчмарк корпуса. Веса Demucs нейтральны к языку (Закон о языках действует
на словарь UI: «голос / ударные / бас / остальное»); оффлайн-кэш по образцу
llm.mjs (ключ `singular-demucs-v1` при пине); для караоке-минуса склейка
стемов в минусовку — дело вызывающего слоя, адаптер честен и не обещает
«минус» раньше времени.

### 4. `tests/test-demucs.mjs` — контрактные тесты **16/16 PASS**

ledger/мок/регистрация (полупин запрещён, дубликат — false)/статусы/валидация
5 форматов по подписи байтов (wav≠mp3 ловится, обе подписи mp3)/копия
входа/12 провалов разбора (лишний пятый стем, недостающий, NaN/∞ с индексом,
длины, смесь, частота)/дверь (мок, одна, несколько, чужой id, бросок)/
детерминизм/вектор SHA-256/пин-ветки/READY в реестре дома/честные числа
(рмс синуса = 0.5/√2, тишина — null, доли сходятся в 1)/остаток микса
(тождество на дайадиках — точный ноль, шум 0.25 → −13 дБ, тишина смеси)/
бенчмарк (SDR ×0.9 → 20 дБ, идеальная сходимость словом, отказы не метрики,
детерминизм протокола)/схемы и канон.

## Честные границы

- МОДЕЛИ DEMUCS В ДОМЕ НЕТ: `tool.demucs` — EXPERIMENTAL честно; критерий А3
  «модель пинится и проходит контрактные тесты» — тесты зелёные (16/16;
  регресс 4/4 + 16/16 + 14/14 + 16/16), пин ожидает люка владельца.
- Дом не проверяет КАЧЕСТВО разделения — он называет числа (рмс, пик, доли,
  остаток); качество против эталонных стемов мерит demucs-bench.mjs по
  корпусу владельца.
- Двигатель не выбран гвоздями: runner принимает любой рантайм с замороженным
  ответом; фиксируется при пине (поле `движок`).
- Минус для караоке (склейка стемов в минусовку) — дело вызывающего слоя:
  адаптер даёт стемы и честные числа, а не обещает готовую минусовку.
- f32-остаток тождественного микса (~−153 дБ) назван числом — honest
  engineering: не «идеально», а «за порогом слуха».
- Брайль (шаг 5) — контракт в `contracts.mjs` не тронут (байт-в-байт);
  очередь по приоритету владельца, шаг последний.
