# ЛЮК ВЕСОВ WHISPER — процедура приведения голоса в дом

**Такт v10.94 «ГОЛОС» (С70) · строка А3, шаг 1 · владелец + агент**

Веса локального Whisper живут у владельца (закон честности: дом не тащит и не
качает веса; репа весов `rtynbirf/singulyar-llm` — соседняя, отдельно от
Pages). Эта процедура — полный путь весов: от локального файла до пина в
ledger адаптера. Всё программно: владелец говорит агенту, агент делает.

## Шаг 1 — взять модель (локально, вне Pages)

Официальные ggml-модели whisper.cpp лежат на странице модели whisper.cpp
(ggml-tiny / ggml-base / ggml-small — по-русски: крошечная ~75 МБ, базовая
~142 МБ, маленькая ~466 МБ; для старта дома рекомендуется **base**: точность
заметно выше tiny, вес подъёмен). **Размеры и SHA-256 дом не называет по
памяти** — пин фиксируется только по факту скачки файла (закон честности).

## Шаг 2 — раскроить на части ≤ 100 МБ

```bash
python3 БИБЛИОТЕКИ/adapter-os/tools/раскрой_весов.py ПУТЬ/ggml-base.bin --вых WHISPER
```

Скрипт (проверен тестом такта: 3-частный и одночастный раскрой, склейка
байт-в-байт = оригинал): считает SHA-256 целого и каждой части, пишет части
`<имя>.part-NN-of-MM.bin` и готовый фрагмент манифеста
`WHISPER/МАНИФЕСТ_ФРАГМЕНТ.txt`.

## Шаг 3 — выложить в репу весов

1. Клонировать `rtynbirf/singulyar-llm`.
2. Создать каталог `WHISPER/`, положить части + вписать фрагмент манифеста
   в `MANIFEST.txt` (раздел «WHISPER» рядом с разделом Qwen).
3. Закоммитить и запушить (PAT — у агента).

## Шаг 4 — пин в доме

В `БИБЛИОТЕКИ/adapter-os/adapters/speech.mjs` регистрируется модель с пином —
SHA-256 целого файла из шага 2:

```js
registerWhisperModel({
  id: 'base-ru',                       // имя читаемое, без «/»
  runner: <замороженный ответ двигателя whisper.cpp/wasm>,
  движок: 'whisper.cpp/wasm',
  веса: {
    имя: 'ggml-base.bin',
    sha256: '<64 шестнадцатеричных знака из шага 2>',
    байт: <размер целого файла>,
    частей: <сколько частей>,
  },
});
```

С этого момента статус адаптера `input.whisper-local` — READY с пином;
до этого — EXPERIMENTAL, честно (критерий А3: «модель пинится и проходит
контрактные тесты»).

## Шаг 5 — бенчмарк (ledger трека)

Корпус владельца (размеченные пары «аудио → эталонный текст», по-русски —
первый язык дома) прогоняется через `speech-bench.mjs::прогонБенчмарка`:
протокол WER/CER ложится в ledger трека. Тайминги устройств измеряются
снаружи (performance.now) и вписываются в протокол отдельным полем — внутри
бенчмарка 0 часов: один прогон → один протокол, байт-в-байт.

## Сторожа люка

- части ≤ 100 МБ — правда платформы (лимит git), не украшение;
- SHA-256 целого = склейка частей по порядку — проверяется и скриптом
  раскроя, и `сверитьПин()` адаптера в рантайме (расхождение → данные
  не выдаются);
- веса НЕ попадают в Pages-репу дома (лимит честности: дом ≤1 ГБ и это
  не место для весов);
- пока пина нет — нигде не пишется «проверено»: EXPERIMENTAL честно.
