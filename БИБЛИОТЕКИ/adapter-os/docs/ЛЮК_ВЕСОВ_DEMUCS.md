# ЛЮК ВЕСОВ DEMUCS — процедура приведения разделителя в дом

**Такт v10.99 «МИНУС» (С75) · строка А3, шаг 4 · владелец + агент**

Модель Demucs (htdemucs / htdemucs_ft) живёт у владельца (закон честности:
дом не тащит и не качает веса; репа весов `rtynbirf/singulyar-llm` — соседняя).
Эта процедура — полный путь модели: от локального файла до пина в ledger
адаптера `tool.demucs`.

## Шаг 1 — взять модель (локально, вне Pages)

Подходят веса любого локального рантайма, который умеет давать «замороженный
ответ» (аудио → четыре стема): Demucs WASM-сборки, ONNX-экспорт, локальный
сервер вывода (Python/demucs, охваченный прокладкой). **Размеры и SHA-256 дом
по памяти не называет** — пин фиксируется только по факту скачки файла.
Граница дома: файл ≤100 МБ; крупнее — раскрой на части инструментом
`раскрой_весов.py` (htdemucs укладывается в 4 части — см. тест-фикстуру
`готовая` в test-demucs: 300 МБ → 4 части).

Веса Demucs нейтральны к языку — Закон о языках (rus → srp → kaz → deu) на
них не действует; он действует на СЛОВАРЬ интерфейса разделения (названия
стемов в UI дома: «голос / ударные / бас / остальное» по этому закону).

## Шаг 2 — проверить и (если нужно) раскроить

```bash
sha256sum htdemucs.th
# файл ≤100 МБ идёт одной частью; крупнее — тот же инструмент, что у Whisper/OCR/GAZE:
python3 БИБЛИОТЕКИ/adapter-os/tools/раскрой_весов.py htdemucs.th --вых DEMUCS
```

## Шаг 3 — выложить в репу весов

1. Клонировать `rtynbirf/singulyar-llm`.
2. Создать каталог `DEMUCS/`, положить файл(ы) + вписать раздел «DEMUCS» в
   `MANIFEST.txt` (имя — размер — SHA-256 каждой части).
3. Закоммитить и запушить (PAT — у агента).

## Шаг 4 — пин в доме

В `БИБЛИОТЕКИ/adapter-os/adapters/demucs.mjs` регистрируется модель с пином:

```js
registerDemucsModel({
  id: 'htdemucs',                         // имя читаемое, без «/»
  runner: <замороженный ответ рантайма>,  // аудио → { стемы: { vocals, drums, bass, other } }
  движок: 'wasm-воркер / локальный сервер вывода',
  веса: {
    имя: 'htdemucs.th',
    sha256: '<64 шестнадцатеричных знака из шага 2>',
    байт: <размер файла>,
    частей: 1,
  },
});
```

С этого момента статус адаптера `tool.demucs` — READY с пином; до этого —
EXPERIMENTAL, честно (критерий А3: «модель пинится и проходит контрактные
тесты»).

## Шаг 5 — что честно ждёт движок (контракт runner)

Runner получает конверт `{ аудио: { данные: Uint8Array, формат: 'wav'|'mp3'
|'ogg'|'flac'|'m4a' }, параметры }` и отдаёт конверт `{ стемы: { vocals,
drums, bass, other }, смесь?, частота_дискретизации? }`. Требования дома
строгие и честные:

- ровно четыре канонических стема (лишний ключ — мусор, недостающий — отказ);
- все стемы одной длины (каналы одного микса), отсчёты конечные (диапазон
  дом не поджимает);
- смесь и частота дискретизации — по желанию движка, но если названы —
  дом проверяет длину/диапазон и считает по ним остаток микса (смесь −
  сумма стемов), называя расхождение числами (`рмс_остатка`,
  `против_смеси_дБ`), а не обещанием «идеального разделения»;
- «замороженный ответ»: асинхронные рантаймы (wasm-воркер, локальный
  сервер) гоняются ЗА пределами синхронного контрактного цикла.

## Шаг 6 — бенчмарк (ledger трека)

Корпус владельца (аудио + эталонные стемы) прогоняется через
`demucs-bench.mjs::прогонБенчмаркаDemucs`: протокол SDR без выравнивания
(10·log10(||эталон||² / ||эталон − оценка||²)) + энергопрофиль оценок (рмс)
ложится в ledger трека. Границы названы: bss_eval-выравнивание дом не
притворяется делать; идеальная сходимость пишется словом, а не Infinity
(JSON.stringify(Infinity) молча дал бы null — грех подмены); тишина в
эталоне — «не мера», число не выдумывается. Тайминги устройств измеряются
снаружи; внутри 0 часов.

## Оффлайн-кэш (закон приватности)

Кэширование модели в браузере — по образцу llm.mjs (срез 4): Cache API, один
раз, дальше из кеша; `защищённые_кэши` versions.json уже держит
`transformers-cache` — новый ключ (`singular-demucs-v1`) добавляется
владельцем при пине. Runner обязан быть 0 сети: контракт принимает
замороженный ответ, веса уже локальны. Звук не покидает устройство — аудио
не пишется и не отправляется никуда.

## Сторожа люка

- подпись аудио проверяется адаптером по магическим байтам (wav/mp3/ogg/
  flac/m4a — не по ярлыку);
- SHA-256 целого = склейка частей по порядку — проверяется и раскроем, и
  `сверитьПин()` в рантайме (расхождение → данные не выдаются);
- веса НЕ попадают в Pages-репу дома;
- для караоке-минуса дом честен: «минус» из стема other/vocals — дело
  вызывающего слоя (склейка стемов в минусовку — следующий слой, не
  обещание адаптера);
- пока пина нет — нигде не пишется «проверено»: EXPERIMENTAL честно.
