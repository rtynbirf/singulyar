## Что сделано (шаг 1 из пяти — Whisper, приоритет №1 владельца)

### 1. `adapters/speech.mjs` — реализация контракта Whisper

- **Ledger `adapter-os.speech.v1`** — реестр моделей Whisper дома: пуст на
  импорте (весов в доме нет, и это честно); записи возвращаются копиями.
- **Контракт runner** — синхронный, чистый, 0 сети (тот же дух, что
  `ladom.open-model.v1`): `runner(задание) → {сегменты, язык} | {отказ}`;
  асинхронные рантаймы (whisper.cpp→wasm и др.) приносят «замороженный ответ».
- **Строгий разбор ответа**: наложение таймингов, ход назад по времени,
  пустой текст, нечитаемый язык, граница `МАКС_СЕГМЕНТОВ = 4096` — всё
  честные отказы с названной причиной; ничего не чинится молча. Доказано
  тестом: при `конец > начало` наложение полностью покрывает нарушение
  порядка — мёртвой ветки «назад по времени» в парсере не держим.
- **Пин весов**: `registerWhisperModel({веса:{имя, sha256, байт, частей}})`
  — all-or-nothing (полупиннинг запрещён); `склеитьЧасти()` +
  `сверитьПин()` через `crypto.subtle` (SHA-256): расхождение — данные не
  выдаются даже на байт. Проверено известным вектором SHA-256("abc").
- **Честный мок** `mockRunner()`: всегда отказ «МОК whisper: весов нет…» —
  мок не притворяется распознаванием (родня MOCK_NO_TOKEN адаптера Reve).
- **Дверь `распознать()`**: никогда не бросает наружу; одна модель в ledger —
  она, несколько — id обязателен («дом не выбирает за человека»), бросок
  runner'а — отказ в конверте.
- **`createSpeechAdapter()`** — тот же `id: 'input.whisper-local'`, что у
  контрактной заглушки, но статус живёт по ledger: пусто/без пина —
  EXPERIMENTAL честно, есть пин — READY. Интеграция с `AdapterRegistry`
  дома проверена тестом.

### 2. `adapters/speech-bench.mjs` — бенчмарк (требование карты: «бенчмарки, ledger трека»)

- WER (по словам) и CER (по символам) против размеченного корпуса; нормализация
  названа честно (нижний регистр, ё→е, пунктуация прочь) — это договор мерила,
  а не подгонка ответа.
- Протокол `adapter-os.speech.bench.v1` детерминирован байт-в-байт: 0 часов,
  0 случайности; тайминги устройств измеряет запускающий снаружи и вписывает
  отдельным полем.
- Отказы runner'а не превращаются в выдуманный WER: строка с отказом уходит
  с отказом; если отказали все строки — протокол честно помечает «не мера
  качества» (прогон мока ≠ метрика).

### 3. `tools/раскрой_весов.py` — инструмент люка весов

Локальный ggml → части ≤ 100 МБ (лимит git) + SHA-256 целого и частей +
готовый фрагмент манифеста репы весов. Проверен на фикстурах: 3-частный
и одночастный раскрой, склейка байт-в-байт = оригинал. 0 сети.

### 4. `docs/ЛЮК_ВЕСОВ_WHISPER.md` — процедура приведения весов

Полный путь: взять модель (размеры/хэши публичных моделей дом по памяти не
называет — пин только по факту) → раскроить → выложить в
`rtynbirf/singulyar-llm → WHISPER/` (по образцу Qwen-частей) → пин в ledger →
бенчмарк корпуса владельца.

### 5. Тесты

- `tests/test-speech.mjs` — **16/16 PASS** (node): пустой ledger, честный мок,
  регистрация (дубликат/полупин/плохой хэш — false), статусы адаптера до/после
  пина (EXPERIMENTAL→READY, privacy local), валидация задания (typed array,
  частота, язык ru/kk/sr/zh-Hans/auto), копия данных (вход не мутируется),

  id/бросок), детерминизм байт-в-байт, вектор SHA-256 склейки, все ветки
  `сверитьПин`, метрики WER/CER с делением на ноль названным, детерминизм
  протокола бенчмарка.
- Регресс дома не тронут: `tests/run-tests.mjs` — **4/4 PASS** (их файл не
  менялся, отдельный тест-файл).

## Честные границы

- ВЕСОВ В ДОМЕ НЕТ: статус `input.whisper-local` после этого такта —
  EXPERIMENTAL честно (модели в ledger нет вовсе). Критерий закрытия А3 —
  «модель пинится и проходит контрактные тесты» — выполнен наполовину по
  построению: контрактные тесты есть и зелёные, пин ожидает весов владельца
  (люк готов и проверен).
- Двигатель (whisper.cpp→wasm) не выбран гвоздями: runner принимает любой
  рантайм с замороженным ответом; выбор двигателя фиксируется при пине
  (поле `движок`). Это осознанная развязка: дом не привязывается к чужой
  сборке до факта.
- OCR / gaze / Demucs / Брайль — очередь по приоритету владельца; их
  контракты в `contracts.mjs` не тронуты (байт-в-байт).
