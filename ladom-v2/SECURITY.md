# Конкретные косяки безопасности оригинала (СИНГУЛЯР ·31 ЛАДОМ)

## 1. Content-Security-Policy ослаблена до дырявого состояния
```
script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net 'wasm-unsafe-eval' blob:
style-src  'self' 'unsafe-inline'
```
- `'unsafe-inline'` для script и style = XSS через внедрённый код практически не блокируется.
- `'wasm-unsafe-eval'` открывает дополнительный вектор.
- В реальном мире это считается критическим ослаблением CSP.

## 2. Прямое использование eval()
В коде присутствует `eval()`.  
Любой eval — это прямой путь к выполнению произвольного кода, если туда попадёт пользовательский или скомпрометированный ввод.

## 3. Массовое использование innerHTML (85 присваиваний)
`.innerHTML = ...` без санитизации = классический DOM-based XSS.  
При 1.33 МБ inline-JS проверить все 85 мест вручную практически невозможно.

## 4. Гигантский объём inline-скриптов (1.33 МБ)
- Невозможно нормально аудитировать.
- Невозможно выдать нормальные hash/nonce для CSP.
- Любая ошибка в одном из огромных блоков ломает всё приложение.
- Увеличивает поверхность атаки.

## 5. Заявление «сеть не нужна» при фактической загрузке
- Тянется prosto-lubi.max.webm (14.2 МБ)
- Тянутся singulyar-modules.js и singulyar-ux-engine-v9.js
- В CSP прописаны cdn.jsdelivr.net, huggingface.co, translate.googleapis.com, wss:
Это не «полная автономность», а «работает оффлайн после первой загрузки» + потенциальные внешние точки отказа/слежки.

## 6. Отсутствие Subresource Integrity (SRI) на внешних ресурсах
Внешние скрипты подключаются без `integrity="sha384-..."`.  
При компрометации CDN или MitM можно подменить код.

## 7. Смешение доверенного и недоверенного в одном гигантском файле
Комментарии, «приказы владельца», пользовательский UI, движок, WebRTC-библиотека, лаборатория цветов — всё в одном контексте.  
Нет изоляции привилегий.

## 8. localStorage без явной защиты
6 ключей. Данные настроек лежат в открытом виде.  
При XSS их можно прочитать/перезаписать.

# Как исправлено в этом прототипе
- Никакого eval
- Никакого innerHTML для пользовательских данных (только textContent / createElement)
- Модульная структура → можно поставить жёсткий CSP с nonce/hash
- Один источник версии
- Внешние ресурсы отсутствуют
- Готовность к Service Worker + SRI
- Минимальная поверхность атаки
