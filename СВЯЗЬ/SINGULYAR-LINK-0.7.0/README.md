## 0.7.0 — МОСТЫ: СМС — ТЕЛЕФОН (круг 9 мировых практик: docs/МИРОВЫЕ-ПРАКТИКИ-2026-11-12.md, п.17)

Слово владельца: **СВЯЗЬ ПОЛНОЦЕННАЯ — ДО ПРЯМОГО ТЕЛЕФОНА.** Дверь «СМС» в приглашении была только дверью: открывала приложение СМС, но разговор туда не возвращался. Круг 9 ставит за дверью настоящий мост:

- **СМС-мост** (`server/bridges/sms.mjs`): бабушка с кнопочным телефоном пишет обычную СМС — она падает в пространство от «Бабушки» (карта `contacts`: номер → имя — дом не показывает людям безликие номера); всё, что говорят в комнате, уходит ей обычной СМС; сигналы (🔔 просит позвонить, 🆘 СРОЧНО, 💧 ВОДА, ⚠️ ОПАСНО) доезжают текстом. Из комнаты тексты идут и на обычный телефон, и в мессенджеры — один разговор.
- **Два честных транспорта**: `twilio` — входящий webhook проверяет подпись **X-Twilio-Signature** (Base64(HMAC-SHA1(AuthToken, полный URL + сортированные POST-поля)) — twilio.com/docs/usage/security), чужой POST отбивается 403; исходящие — REST Messages.json. `android` — **SMS Gateway for Android** (docs.sms-gate.app, github.com/capcom6/android-sms-gateway): старый телефон с СИМ дома, БЕЗ облака и ключей — webhook `sms:received` → мосту, исходящие — `POST /message` на телефон (порт 8080; пароль обычный или SHA-256+base64 через `passwordHashMode`).
- **Сегментация честная** (3GPP TS 23.038; twilio.com/docs/glossary/what-sms-character-limit): латиница 160 (сцепка по 153), кириллица и эмодзи — UCS-2 70 (сцепка по 67); мост считает КОД-ПОИНТЫ (эмодзи — один знак, не два), `maxChars` (по умолчанию 480) бережёт кошелёк семьи.
- **Фильтр `allowFrom`** — кого пускать (регэксп на номер), как у телефонного моста 0.5.5.
- **Перевод в мосты закрыт архитектурой 0.6.0**: мостовая СМС-строка приходит в комнату обычным сообщением — и на устройстве адресата переводится Translator API (проверено: `translateIncoming` срабатывает на каждое входящее не от меня, `via` не важен). Бабушка пишет по-русски — внук читает по-немецки, НА ЕГО устройстве, офлайн.
- Страж `tests/sms.test.mjs` — 2 теста, 27 проверок против фальшивых Twilio и шлюза: верная подпись / чужая → 403 / чужой токен → 403 / не-то событие шлюза молча игнорируется / номер вне семьи не проходит / контакты превращают номер в имя / текст комнаты уходит СМС (включая речь 🎙 и сигналы) / эхо СМС запрещено / Basic-пароль шлюза именно SHA-256+base64 / сегментация 160·153 и 70·67 (эмодзи по код-поинтам).

## 0.6.0 — ГОЛОС КАЖДОГО — НА ЯЗЫКЕ КАЖДОГО (круг 8 мировых практик: docs/МИРОВЫЕ-ПРАКТИКИ-2026-11-12.md, п.16)

Слово владельца: **УНИКАЛЬНОЕ = УНИВЕРСАЛЬНОЕ = СИНГУЛЯРНОЕ = ЭМЕРДЖЕНТНОЕ.** Мир (Google Meet, Teams, Zoom) даёт перевод как ОБЛАЧНУЮ опцию конференции — с аккаунтом, подпиской и уходом речи на чужой сервер. Дом делает наоборот: перевод становится **свойством адресата** в разговоре семьи:

- **Перевод на устройстве** (мировой стандарт Translator API: Chrome 138+ с июня 2025, Edge 148+ — 145+ языков): входящее сообщение переводится на твой язык **на твоём устройстве** — модель пары скачивается один раз по твоей кнопке и дальше работает офлайн; текст никуда не уходит, ключей и квот нет. Источники: developer.chrome.com/docs/ai/translator-api · MDN «Translator and Language Detector APIs».
- **Письмо входящего определяет браузер** (LanguageDetector): русский, английский, арабский, иврит, хинди — не важно; уверенность мала («ок», «ага») — дом не портит короткое.
- **Перевод — в тот же контур доступности**: озвучка говорит перевод (не оригинал), брайль-строка переписывается по письму перевода, крупный текст — тот же. Одно сообщение — каждый берёт его своими ушами/глазами/пальцами на своём языке.
- **Модель пары — только по кнопке человека** (активация пользователя — требование API): дом не ставит гигабайты молча; кнопка показывает прогресс скачивания.
- **Честные отказы**: нет API (Firefox/WebKit) — честная надпись и оригинал с остальными трубами; недоступная пара — «перевода нет — показываю как есть»; никаких выдуманных переводов — дом не выдумывает. Ядро `public/translate.js`, страж `tests/translate.test.mjs` — 11 проверок (последовательная очередь — мировая практика API, кэш на устройстве, «same» без движка, «no-api»/«unavailable»/«downloadable»/«need-action» без фейка, письмо из детектора, порог уверенности, список 39 языков).
- **ВПЕРВЫЕ в мире**: перевод как свойство ЧЕЛОВЕКА в живом семейном разговоре на устройстве без облака, аккаунта и слежки — вшитый в один контур с голосом, брайлем и тактилью; у мира перевод — либо облачная функция конференции, либо перевод страниц браузером, но не оба сразу в одной комнате без посредников.

## 0.5.5 — ПОЛНОЦЕННАЯ СВЯЗЬ: ОБЫЧНЫЙ ТЕЛЕФОН (круг 7 мировых практик: docs/МИРОВЫЕ-ПРАКТИКИ-2026-11-12.md, п.15)

Слово владельца: **СВЯЗЬ ПОЛНОЦЕННАЯ, А НЕ УЗЕЛКИ НА ПАМЯТЬ.** Настоящая связь — голос: человек говорит, слышит и его слышат. Кнопочный телефон без интернета — не повод держать человека в стороне:

- **Телефон — участник разговора** (мост `server/bridges/sip-phone.mjs`): телефон — или АТС/транк (Twilio Elastic SIP Trunking, Asterisk PJSIP, любой по RFC 3261) — звонит на SIP-порт сервера → в пространстве появляется участник «Телефон: +7…», голос в обе стороны, слышит всех и его слышат.
- **Из комнаты можно позвонить на обычный номер**: кнопка **☎ Телефон** (видна, когда мост включён) → INVITE через АТС из конфига → телефон звонит, снял трубку — в разговоре.
- **Звук без перекодирования** — мировая практика WebRTC↔SIP-шлюзов: телефоны говорят G.711 (PCMU/PCMA), браузеры умеют G.711 тоже — RTP проходит насквозь, мост лишь держит один постоянный SSRC и непрерывные seq/ts (правило SFU 0.5.1). Кого слушать — решает сервер, как у моста WhatsApp.
- **Кнопки телефона — в чат дома** (DTMF, RFC 4733): нажал «5» — дом показывает.
- Страж `tests/sip-call.test.mjs`: фальшивая АТС + настоящий WebRTC (werift) — 16 проверок всего звонка по RFC 3261/3264/3551/4733: сигналинг, медиа в обе стороны без перекодирования, DTMF, отказы 403/488, BYE в обе стороны.

## 0.5.4 — АЗБУКИ ВСЕХ (круг 6: docs/МИРОВЫЕ-ПРАКТИКИ-2026-11-12.md, п.14)

Слово владельца: **ЕСТЬ ЧЕЛОВЕК — НЕТ НАЦИЙ.** Письмо принадлежит человеку, механизм — один на всех:

- **Морзе — 8 писем мира в одном ключе**: латиница (ITU-R M.1677), кириллица, греческая, иврит, арабская, персидская, хангыль (전보장정, 1888), японская Wabun — селектор «Авто · все азбуки» + выбор вручную; точка/тире остаются точкой/тире для любого письма.
- **Брайль — одна 6-точечная клетка на всех**: письмо по языку сообщения — латиница, кириллица, греческий (Modern Greek), иврит (International Hebrew Braille Code), арабский (с огласовками); цифры — числовой знак ⠼; смешанное письмо — каждая буква своей клеткой.
- **Честно исправлено против 0.5.3**: пять клеток кириллического брайля стояли неверно (й, ъ, ы, ь, я) — пересверено по ГОСТ Р 58511-2019/Wikipedia; две клетки персидского морзе (غ, ق) взяты из первоисточника fa:کد مورс. Занесено в тесты: `tests/azbuki.test.mjs` — 12 проверок по якорям из первоисточников.
- Знака нет в сверенной таблице — знак не переводится. Дом не выдумывает.

## 0.5.3 — КОММУНИКАТОР ЧЕЛОВЕКА (круг 5 мировых практик: docs/МИРОВЫЕ-ПРАКТИКИ-2026-11-12.md, п.12–13)

Слово владельца: сообщение должно дойти до КАЖДОГО доступным ЕМУ каналом — слепоглухому тактильно, неграмотному пиктограммой, без связи — прямой связью. Каждый пункт ниже — изученная мировая практика, переведённая из «демо для инженера» в кнопку для человека:

- **RTT-набор** (практика RFC 4103 / EAA для глухих): текст едет по буквам, пока пишешь — без кнопки «отправить»; на отправке строка гаснет.
- **Морзе-ключ** (практика Gboard/Hello Morse): ТОЧКА / ТИРЕ / Буква / Слово — полная клавиатура одной-двумя кнопками; азбука — на выбор человека (8 писем мира), цифры, живой буфер «·−·− = Я».
- **Тактиль-морзе входящих**: сообщение вибрирует своей морзянкой (первое слово — предел W3C Vibration API: 10 звеньев; дальше тактильный тик «есть продолжение»). Работает в Chromium на Android (Vibration API жив только там — честная граница круга 3).
- **Брайль под сообщениями**: 6-точечная клетка — одна на всех; письмо — по языку сообщения (сверено по Wikipedia/ГОСТ Р 58511-2019/UNESCO), цифры со знаком ⠼; знак вне сверенной таблицы не переводится — дом не выдумывает. Брайль-дисплей по USB HID (стандарт USB-IF 2018) — записан следующим шагом, не притворяемся что подключён.
- **Пиктограммы не-читающим**: 💧 ВОДА · 🤕 БОЛИТ · 📍 Я ЗДЕСЬ · ⚠️ ОПАСНО — тем же аренам чистки/лимитов/истории, что и старые сигналы (практика AAC: W3C AAC Registry, Blissymbolics, круг 3).
- **Письмо на бумагу** (Easy Read): весь разговор — одним печатным листом, одна мысль — одна строка; можно передать человеку без связи, ответ — тем же путём.
- **Прямая связь БЕЗ дома** (`public/duet.js`): два телефона соединяются напрямую — «Я зову» / «Меня зовут», код-приглашение QR + текстом, любым путём (глаза, письмо, СМС, голосом); разговор живёт, когда сервер выключен. Практика manual SDP exchange (lesmana, hexshift, videosdk) — впервые собранная для живого человека, а не для программиста.
- Пиктограммные сигналы проверены юнитом (water/danger в tests/hub.test.mjs); RTT/морзе/брайль/duet — живые проверки руками семьи, прежде чем объявлять их стражами.

## 0.5.1 — смена ведущего не рвёт звонок

- **Микс-трек держит каждый браузер всегда** (труба не рвётся), а кого слушать — решает сервер.
- **Сервер берёт любую живую трубу текущего участника**, если у избранного ведущего тишина >1.5 с (фоновая страница, холодный старт).
- **SFU-переписка RTP**: исходящая труба несёт один постоянный SSRC и непрерывные seq/timestamp — приёмник (Meta) больше не отбрасывает поток как реплей при смене ведущего (`SrtpReplayError` устранён).
- Страж `tests/wa-call.e2e.mjs` проверяет инвариант состояниями, а не таймингами; 6/6 прогонов подряд зелёные.

## Запуск (3 шага)

```bash
# из дома: cd СВЯЗЬ/SINGULYAR-LINK-0.6.0
./start-public.sh          # сам поставит зависимости → сервер на 8787 + публичная HTTPS-ссылка (нужен cloudflared)
# или локально для проверки:  npm install && node server/index.mjs   → http://localhost:8787
```

1. Открой адрес **https://…trycloudflare.com**, который напечатает скрипт (именно его, не localhost).
2. «Создать пространство» → «Войти» → кнопка **«Пригласить»**.
3. Выбери для каждого человека его мессенджер (WhatsApp, Viber, Telegram, Teams, СМС, почта, меню телефона, QR). Человек нажимает ссылку — он в разговоре.

Node.js 20+. Зависимости (`ws`, `werift`) ставятся командой `npm install`; при первом запуске `start-public.sh` делает это сам. В комплекте `node_modules` нет — пакет лёгкий.

## Что умеет

**Под человека, а не человек под программу.** Ты пишешь/говоришь один раз — канал сам подстраивается под каждого получателя:

| Получателю удобно | Что происходит |
|---|---|
| Слушать | входящие сообщения и сигналы озвучиваются |
| Не слышит | включает «субтитры» → у всех, кто говорит в микрофон, речь **сама** превращается в текст; текст едет по буквам (RTT), пока пишешь |
| Не видит | крупный текст, озвучка; брайль-строка под сообщением (одна 6-точечная клетка; письмо — по языку сообщения) |
| Слепоглухой | входящее вибрирует своей морзянкой под палец + морзе-строка; сигналы — вибро-рисунком |
| Одна подвижная рука | морзе-ключ: ТОЧКА / ТИРЕ / Буква / Слово — пишет как Gboard; азбука — любая из 8 писем мира |
| Не читает | пиктограммы: ВОДА · БОЛИТ · Я ЗДЕСЬ · ОПАСНО + старые сигналы ✋ 👍 ❤️ 🔔 🆘 |
| Нет связи вообще | «Письмо на бумагу» — печатный лист одной мыслью в строке; **прямая связь без дома**: два телефона по коду через QR/письмо/СМС/голос |
| Говорит на другом языке | включи «Переводить мне на моём языке» → входящие приходят строкой перевода **на твоём устройстве** (модель пары — по кнопке, дальше офлайн); озвучка и брайль — тоже перевод; оригинал всегда рядом |
| Есть только обычный телефон, без интернета | **телефон — участник разговора**: голосом — набрал номер пространства (мост SIP) или позвонил в WhatsApp; **буквами — мост СМС (0.7.0): пишет СМС — приходит в комнату от «Бабушки», комната отвечает СМС**; из комнаты звонят кнопкой ☎; кнопки телефона видны в чате |
| Телефон в кармане | все сигналы приходят вибрацией своего рисунка + звук |

Дальше: голос и видео (WebRTC, до ~6 человек), чат с историей для опоздавших, переподключение при обрыве, работа с телефона и ПК, установка как приложение (PWA).

**Реальные мосты** (текст, речь-в-текст и сигналы):
- **Telegram** — группа Telegram ↔ пространство через официальный Bot API. Бабушка в Telegram читает всё и отвечает там же.
- **Обычный телефон** — бабушка набирает номер с кнопочного телефона и **слышит всех в пространстве, а они слышат её** (мост SIP, G.711). Из комнаты можно позвонить ей. См. ниже «Звонок на обычный телефон».
- **Обычная СМС** — бабушка **пишет СМС — текст падает в пространство от «Бабушки»**, комната отвечает ей обычной СМС (мост `sms`: Twilio или домашний Android-шлюз без облака). См. ниже «Мост обычной СМС».
- **WhatsApp-звонки** — бабушка звонит на бизнес-номер в WhatsApp и **слышит всех в пространстве, а они слышат её** (официальный Calling API). См. ниже «Звонок из WhatsApp».
- **Webhook** — любой другой мир (Matrix-бот, n8n, Home Assistant, свой скрипт): входящие `POST /bridge/webhook?token=…`, исходящие на твой URL.

Настройка моста: скопируй `bridges.example.json` в `bridges.json`, впиши токен, id группы и код пространства, перезапусти.

## Звонок из WhatsApp (мост 0.4)

Как устроено: бабушка звонит на номер → Meta присылает серверу WebRTC-предложение → мост принимает звонок и становится в пространстве «участником» 📞. Звук WhatsApp приходит каждому в браузер, а звук комнаты уходит бабушке одним потоком: его смешивает браузер **ведущего** (первый вошедший; вышел — роль переходит следующему). Серверу не нужен аудиокодек, Opus просто пересылается.

Настройка (один раз):
1. Meta for Developers → приложение с продуктом WhatsApp → бизнес-номер; включи **Calling** на номере.
2. Webhook: URL `https://ТВОЙ-СЕРВЕР/bridge/whatsapp`, verify token — любая строка, подписка на поле **calls**.
3. Впиши в `bridges.json` (образец `bridges.example.json`): `phoneNumberId`, `accessToken`, `verifyToken`, `appSecret`, код пространства.
4. **Сервер должен быть доступен по UDP.** Туннель `cloudflared` UDP не пропускает, поэтому для звонков нужен VPS (или домашний сервер с пробросом): открой UDP-диапазон из `icePortRange`, укажи `publicIp`. Запуск: `docker build -t singulyar . && docker run --network host singulyar` или просто `node server/index.mjs` за HTTPS-прокси.

Только голос. Звонки на номер видят все, кто его знает, — пространство одно на номер.

## Звонок на обычный телефон (мост 0.5.5)

Как устроено: телефон (АТС/транк) звонит по SIP на наш порт → мост отвечает 200 OK (RFC 3261/3264) и становится участником «Телефон: +7…». Звук — G.711 (PCMU/PCMA) **насквозь, без перекодирования**: RTP в обе стороны с переписанными заголовками (один SSRC, непрерывные seq/ts). Кнопки телефона (DTMF) приходят в чат. Кнопка **☎ Телефон** в комнате делает обратное: INVITE на номер через АТС из конфига.

Настройка (один раз):
1. Серверу нужен **белый IP и UDP** — как для WhatsApp-звонков: открой UDP для SIP (например 5060/udp) и RTP-диапазон из `rtpStart` (например 40000–40100/udp).
2. В `bridges.json` (образец `bridges.example.json`):
   ```json
   { "type": "sip-phone", "room": "КОД_ПРОСТРАНСТВА",
     "listenPort": 5060, "publicIp": "ПУБЛИЧНЫЙ_IP", "rtpStart": 40000,
     "allowFrom": "^[+0-9]+$",
     "dial": { "host": "АДРЕС_АТС", "port": 5060 } }
   ```
3. Где взять телефонную сторону — мировые практики:
   - **Twilio Elastic SIP Trunking**: купи номер → Origination URI → `sip:КОД@ТВОЙ_IP:5060`; код пространства — user-часть URI.
   - **Asterisk / FreeSWITCH / miniSIPServer** в своей сети: PJSIP-транк на наш IP:5060, G.711 (alaw/ulaw).
   - Любая АТС по RFC 3261: INVITE → 200 OK → RTP G.711.
4. `allowFrom` — кого пускать (регэксп на номер из From); без него пускают всех — держи мост за VPS с фаерволом.

## Мост обычной СМС (мост 0.7.0)

Как устроено: телефон бабушки ничего не знает про интернет — он просто пишет СМС. Мост — сторона, где СМС становятся сообщениями комнаты, а комната — СМС:

- **Twilio** (транспорт `twilio`): купи номер → в консоли поставь webhook входящих на `https://ТВОЙ-СЕРВЕР/bridge/sms` (HTTP POST) → впиши в `bridges.json` `accountSid`, `authToken`, `from` (твой номер), `to` (номер бабушки), `contacts`. Каждый вход проверяется подписью X-Twilio-Signature — чужой POST не пройдёт. За прокси укажи `publicUrl` — так, как адрес видит Twilio.
- **SMS Gateway for Android** (транспорт `android`, без облака и покупок): старый Android-телефон с СИМ ставишь на зарядку, ставишь приложение SMS Gateway (docs.sms-gate.app), в приложении регистрируешь webhook `sms:received` на `https://ТВОЙ-СЕРВЕР/bridge/sms?token=ТВОЙ_СЕКРЕТ`; в `bridges.json` — `gatewayUrl` (адрес телефона в домашней сети, порт 8080), `gatewayLogin`/`gatewayPassword` (или `passwordHashMode: true`, если в приложении включён хешированный пароль), `to`, `contacts`.
- `contacts` — карта «номер → имя»: в комнате видят «Бабушка», а не номер.
- `to` — кому уходит разговор из комнаты (строка или список).
- `maxChars` (по умолчанию 480) — предел одного письма; мост считает сегменты честно: латиница 153 в сегменте, кириллица/эмодзи 67.

Честно: СМС платные по тарифу семьи; каждому сегменту — отдельная цена (длинное письмо режется); входящему webhook нужен публичный HTTPS-адрес; телефон-шлюз должен быть включён, в сети и с деньгами на счёте; у Twilio пробный номер пишет только на подтверждённые номера.

Честно: SIP — по UDP без TLS (связка рассчитана на АТС/транк на доверенной сети); REGISTER не поддерживается — мост принимает прямые звонки транка; звук — телефонное качество 8 кГц: таким его делает сам G.711-телефон, другим он в этом мосту и не притворяется.

## Прогон семьи вживую (Chrome 138+): протокол круга 9

Двенадцать шагов. Проверяет каждый шаг ту функцию, которая нужна живому человеку; что не заработало — пишем в отчёт честно, дом правит границы, а не притворяется:

1. **Ссылка открывается** — `./start-public.sh` → адрес `https://…trycloudflare.com` (именно его) → «Создать пространство» → «Войти».
2. **Приглашение** — кнопка «Пригласить»: QR в камеру, ссылка — в Telegram/Viber/WhatsApp, «СМС» — приложение СМС открывается с готовым письмом, «Отправить через меню телефона…» — системное меню.
3. **Голос** — зайти двоим с телефонов: оба слышат друг друга, эха нет, вышел — роль ведущего перешла.
4. **Видео** — камера включается, второй участник видит картинку.
5. **Субтитры** — у бабушки включены: твоя речь печатается у неё по буквам (Chrome 138+).
6. **Перевод** (главное круга 8) — профиль → «Переводить мне на моём языке» → язык → кнопка «Скачать модель» (один раз, дальше офлайн) → входящее на другом языке приходит строкой перевода; озвучка говорит перевод, брайль переписывается.
7. **Озвучка** — «Слушать сообщения»: входящие говорятся голосом.
8. **Брайль и тактиль** — брайль-строка под сообщением; сообщение в руке вибрирует своей морзянкой (Chromium на Android).
9. **Морзе-ключ** — ТОЧКА / ТИРЕ / Буква / Слово — пишет одна подвижная рука.
10. **Пиктограммы** — 💧 ВОДА · 🤕 БОЛИТ · 📍 Я ЗДЕСЬ · ⚠️ ОПАСНО — приходят всем.
11. **Телефон** — мост SIP: набрал номер пространства — голос в обе стороны; из комнаты ☎ дозвонились; DTMF виден в чате.
12. **СМС** (новое круга 9) — мост СМС: бабушка пишет СМС → в комнате падает от «Бабушки»; комната отвечает — ей приходит СМС; 🔔 🆘 доходят текстом.

**Что записать в отчёт прогона:** что открыл и на чём (телефон/ПК, версия Chrome, сеть), что увидел, что НЕ заработало, сколько качалась модель перевода (МБ/минуты), батарея/трафик за час разговора. Честный минус — тоже результат: он становится границей следующего круга.

## Честные границы

- Заставить WhatsApp, Viber и Teams показать один нативный групповой звонок нельзя: у них нет такого входа. Поэтому звонок идёт в общем окне, а мессенджеры — это **двери** в него (ссылки) и **мосты текста** там, где они реально существуют. WhatsApp открывает сторонние чаты только в ЕС, только 1-на-1 и только для подписавших соглашение приложений; звонки обещаны к 2027.
- Часть сетей (строгий NAT, мобильные операторы) без TURN-сервера не соединится по видео. Укажи свой: `TURN_URL=turn:host:3478 TURN_USER=… TURN_PASS=… node server/index.mjs`.
- Телефонный мост: SIP по UDP без TLS, REGISTER не поддерживается (см. выше); видео в WhatsApp-мосте появится, когда его выведет Meta — в Calling API оно заявлено «planned or in development».
- СМС-мост: текст письма проходит через сторону моста (Twilio или телефон-шлюз) — сервер видит текст, как и в остальных текстовых мостах; СМС платные, длинные письма тарифицируются по сегментам; дверь «СМС» в приглашении (`sms:`-ссылка) не работает внутри внутренних браузеров соцсетей (Instagram/X/TikTok рисуют ссылки в своём webview и молча блокируют передачу — senderz.com/blog/click-to-text-links): пользуйтесь «Отправить через меню телефона…» или QR.
- Сервер видит текст сообщений (шифруются только голос и видео между браузерами). Для семьи этого достаточно; сквозное шифрование текста — следующий шаг.
- «Речь в текст» использует распознавание браузера: работает в Chrome, Edge, Safari, в Firefox — нет.
- Перевод на устройстве жив в Chrome 138+ и Edge 148+ (десктоп): модель пары скачивается из браузера один раз (нужен интернет только на скачивание). Firefox — API нет (отрицательная позиция Mozilla), WebKit/Safari — API нет: дом показывает честный отказ и не выдумывает перевод. RTT-строка набора и пиктограммы не переводятся (переводится финальное сообщение; пиктограммы универсальны). Качество перевода — качество встроенной модели браузера.
- Вибрация жива только в Chromium на Android (W3C Vibration API); WebKit против, Firefox выпилил в 129. На iPhone — приложение или человек-мост: честно записано, не приукрашено.
- Брайль — буквы/цифры по сверенным таблицам пяти писем (латиница, кириллица, греческий, иврит, арабский); знак вне таблицы не переводится; клетки иврита — без огласовок, украинские клетки — следующий круг. Брайль-дисплей по USB HID — следующий шаг, сейчас строка на экране.
- Прямая связь (duet) — обмен кодами руками, один собеседник, без истории и мостов: это дверь на случай «всё выключили», а не замена пространству.
- Код пространства (10 символов) — это и есть ключ входа: у кого ссылка, тот внутри.

### Teams (скелет)

1. Зарегистрируй Azure AD App с правами `Calls.Initiate.All`, `Calls.AccessMedia.All` (или Delegated по политике tenant).
2. Создай Calling Bot в Teams Developer Portal, укажи `notificationUrl = https://ТВОЙ-СЕРВЕР/bridge/teams`.
3. В `bridges.json` добавь блок `"type": "teams"` (см. `bridges.example.json`).
4. Полноценный двусторонний звук потребует media-путь (Azure Communication Services или Media Platform SDK). Пока мост объявляет входящие звонки в комнате и готов принимать сигналинг.

### Viber (ПК-мост)

У Viber нет серверного Calling API. Путь:

1. На выделенном ПК запущен Viber Desktop.
2. Звук звонка → виртуальный кабель (VB-Cable / BlackHole / PulseAudio null-sink).
3. Локальный агент захватывает кабель, шлёт heartbeat/start/stop на `POST /bridge/viber-audio`.
4. Когда media-путь агента будет готов — звук пойдёт в пространство как участник-мост.

Конфиг: `"type": "viber-audio"` в `bridges.json`.

## Сервер с UDP (обязательно для WhatsApp-звонков)

`cloudflared` и большинство HTTP-туннелей **не пропускают UDP**. Без UDP WhatsApp Calling не установит медиа.

Минимальный рабочий вариант:

1. VPS или домашний сервер с белым IP.
2. Открой UDP-диапазон, например `40000–40100/udp` (и TCP 443/80 для HTTPS).
3. В `bridges.json` для `whatsapp-call` укажи:
   - `publicIp` — публичный IPv4 сервера
   - `icePortRange`: `[40000, 40100]`
4. Запуск за HTTPS-прокси (Caddy/Nginx) или напрямую с сертификатом:
   ```bash
   PUBLIC_IP=x.x.x.x node server/index.mjs
   # или
   docker run --network host -v $PWD/bridges.json:/app/bridges.json singulyar
   ```
5. Webhook Meta должен указывать на `https://твой-домен/bridge/whatsapp`.

Без этого шага текстовые мосты работают, голосовой WhatsApp — нет.
