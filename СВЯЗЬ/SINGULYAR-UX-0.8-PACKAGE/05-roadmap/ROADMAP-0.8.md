# СИНГУЛЯР · Дорожная карта UX 0.8 → 1.0

**Дата:** 12 ноября 2026  
**Исходная точка:** SINGULYAR-LINK 0.7.0 (функциональный прототип)  
**Цель 0.8:** привести интерфейс к лучшим практикам юзабилити и эргономики без потери философии «человек важнее канала».

---

## Текущее состояние (0.7.0)

| Слой | Уровень | Комментарий |
|------|---------|-------------|
| Идея и архитектура | высокий | Уникальный фокус на человеке, а не на аккаунте |
| Мосты (SMS, SIP, мессенджеры) | высокий | Реализованы и тестируются |
| Доступность (морзе, брайль, перевод на устройстве) | высокий | Глубокая реализация |
| UX / интерфейс | низкий (0.1–0.2) | «Порнота»: всё на одном экране, нет иерархии |
| Визуальная эргономика | низкий | Мелкие контролы, плотный текст, нет ритма |

---

## Этап 0.8 — UX-фундамент (текущий пакет)

**Срок ориентир:** 1–2 итерации разработки

### Must have
- [ ] Экран входа только с главным действием (создать / войти)
- [ ] Комната: лента + адаптивная панель ввода
- [ ] Профиль доступности как отдельный экран (свойство человека)
- [ ] Панель ввода переключается по профилю (текст / сигналы / голос / морзе)
- [ ] Шторка участников с указанием канала
- [ ] Микрокопирайт из спецификации
- [ ] Размеры касания ≥ 48–52 px, текст ≥ 18 px
- [ ] Контраст ≥ 7:1, поддержка тёмной темы и high-contrast
- [ ] Честные состояния ошибок и пустые экраны

### Deliverables уже готовы в этом пакете
- UX-спецификация 0.8 (PDF + MD)
- Чеклист для разработчика (PDF + MD + HTML для печати)
- CSS/HTML рекомендации
- Живой HTML-прототип (вход → комната → профиль)
- Критические сценарии (бабушка по СМС, слепоглухой, только голос, p2p)

### Критерий готовности 0.8
Все пункты чеклиста отмечены ☑ и проверены:
1. На реальном мобильном устройстве
2. Хотя бы с одним пожилым пользователем

## Этап 0.9 — Углубление и полировка

**Фокус:** реальные сценарии + обратная связь пользователей

- Прототип → рабочий фронт (интеграция с существующим бэкендом 0.7)
- Полный цикл «бабушка по СМС» end-to-end в UI
- Индикаторы доставки по каналам
- Пустые состояния и онбординг первого входа
- Тестирование с 5–7 людьми 65+
- Исправление по результатам тестов (обычно 3–4 главных боли)

---

## Этап 1.0 — Продуктовая готовность

**Фокус:** стабильность + понятность для семьи

- Все критические сценарии закрыты и документированы
- «Честные границы» видны пользователю (что работает / не работает)
- Минимальный онбординг без обучения
- Тёмная тема и крупный текст работают из коробки
- Готовность к передаче не-разработчикам (бабушка + внук)

---

## Принципы, которые сохраняем на всех этапах

1. Человек важнее канала
2. Сложность спрятана, простота — на поверхности
3. Честные границы важнее красивых обещаний
4. Один главный фокус на экране
5. Профиль доступности — свойство человека
6. Адаптивная панель ввода
7. Короткие прямые тексты

## Рекомендуемый порядок работ для разработчика

1. Прочитать `01-spec/SINGULYAR-UX-SPEC-0.8.pdf`
2. Открыть `03-prototype/singulyar-prototype-0.8.html` в браузере
3. Пройти чеклист `02-checklist/SINGULYAR-CHECKLIST-0.8.pdf`
4. Использовать `04-css-html/SINGULYAR-CSS-HTML-RECOMMENDATIONS-0.8.md` как основу стилей
5. Внедрять экран за экраном, сверяясь с чеклистом
6. После каждого экрана — быстрая проверка на телефоне

## Сделано в 0.8.1 (волна ×21, 2026-11-13)

- Живое превью в профиле (режим + модификаторы меняют сообщение мгновенно).
- Честные границы: автоопределение устройства + точные тексты ошибок для каждого режима (файл `07-honest-boundaries/ЧЕСТНЫЕ_ГРАНИЦЫ-0.8.1.md`).
- Профиль «режимы вместо категорий»: 4 карточки основного способа + плоские «Дополнительно».
- Чистый «бабушкин» вид: демо-бар спрятан (`?demo=1` — вид разработчика, один файл).
- Обычные люди — главный сценарий: каналы у сообщений, статусы по каналу, «печатает…», живой демо-диалог, приглашение с копированием, честный микрофон, рабочая морзе-клавиатура.

## Что дальше (0.9 — кандидаты в порядке ценности)

1. Короткий туториал при первом включении морзе (три буквы — и в бой).
2. Реальные статусы доставки по каналам из дома (события мостов LINK в ленту).
3. Полноэкранное ощущение режима «только сигналы» на телефоне.
4. Вынести демо-диалог в отдельную «песочницу» — чистая комната без подставных людей.
5. Тесты с 4–5 людьми 65+ и хотя бы одним человеком с реальным нарушением зрения/слуха — до того, как полировать дальше.
