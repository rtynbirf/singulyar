# СИНГУЛЯР · UX-СПЕЦИФИКАЦИЯ 0.8

**Дата:** 2026-11-12  
**Статус:** Рабочая спецификация на основе разбора интерфейса 0.7.0  
**Цель:** Привести существующую функциональность к лучшим практикам юзабилити и эргономики, сохранив философию «человек важнее канала».

---

## 1. Информационная архитектура

```
СИНГУЛЯР
│
├── Вход / Создание
│   ├── Создать пространство
│   ├── Войти по ссылке
│   └── Прямая связь без сервера (вторичный путь)
│
├── Комната (основной экран)
│   ├── Лента сообщений
│   ├── Панель ввода (адаптивная)
│   ├── Участники (шторка)
│   ├── Быстрые действия (⋯)
│   │   ├── Позвать человека
│   │   ├── Позвонить на обычный телефон
│   │   ├── Пригласить
│   │   └── Выйти
│   └── Сигналы / Пиктограммы (контекст панели)
│
├── Профиль доступности
│   ├── Зрение
│   ├── Слух
│   ├── Моторика / Ввод
│   ├── Язык
│   └── Канал
│
└── Системные
    ├── Мои пространства
    ├── Честные границы
    └── О проекте
```

**Главный принцип:** 90% времени человек находится в «Комнате». Всё остальное — либо вход, либо редкие настройки.

## 3. Панель ввода (адаптивная логика)

Панель меняется в зависимости от профиля человека.

| Профиль                        | Что показывает панель                          |
|--------------------------------|------------------------------------------------|
| Обычный                        | Поле текста + 🎤 + «+»                         |
| Нужны сигналы                  | Крупные сигналы + поле текста                  |
| Не читает / пиктограммы        | Только крупные пиктограммы                     |
| Морзе                          | Клавиатура · − Буква Слово                     |
| Только голос                   | Огромная кнопка «Говорить»                     |
| Крупный текст                  | Те же элементы, увеличенные                    |

**Правила:**
- Панель читает профиль при входе и сразу подстраивается.
- Временное переключение возможно через «+» → «Другой способ ввода».
- После выхода из комнаты временный режим сбрасывается.

## 5. Визуальные требования (эргономика)

### Размеры
- Основной текст: 18–20 px
- Крупный режим: 24–28 px
- Высота кнопок: минимум 52 px
- Зоны нажатия: минимум 48×48 px
- Расстояние между кнопками: 12–16 px
- Поле ввода: высота 56 px

### Контраст
- Обычный текст: минимум 7:1
- Крупный текст: минимум 4.5:1
- Важные действия: максимальный контраст

### Цвета

| Назначение         | Светлая тема      | Тёмная тема       |
|--------------------|-------------------|-------------------|
| Фон                | #FFFFFF / #F7F7F5 | #121212 / #1C1C1E |
| Основной текст     | #111111           | #F2F2F2           |
| Вторичный текст    | #555555           | #A0A0A0           |
| Главная кнопка     | #1A1A1A           | #FFFFFF           |
| Срочно             | #C62828           | #FF8A80           |
| Успех              | #2E7D32           | #81C784           |

- Поддержка `prefers-color-scheme`
- Режим высокого контраста обязателен
- Смысл никогда не передаётся только цветом

## 7. Сценарий: Бабушка на кнопочном телефоне через СМС

### Контекст
Бабушка живёт одна. У неё кнопочный телефон без интернета. Внук создал пространство «Семья» и добавил её номер в контакты моста.

### Как это работает (цепочка)

1. **Внук** в комнате нажимает «Пригласить» → копирует ссылку и отправляет бабушке обычной СМС вручную (или система делает это через мост).
2. Бабушка получает СМС:  
   `Семья: открой ссылку или просто ответь на это сообщение. Я буду читать.`
3. Бабушка **не открывает ссылку** (у неё нет браузера). Она просто отвечает обычной СМС:  
   `Я дома`
4. СМС-мост получает сообщение → превращает номер в имя «Бабушка» → сообщение появляется в комнате от имени Бабушки.
5. Внук пишет в комнате: `Отлично, я заеду вечером`.
6. Мост сегментирует текст (кириллица = 70 знаков) и отправляет бабушке обычной СМС.
7. Бабушка получает:  
   `Семья: Отлично, я заеду вечером`
8. Если внук нажимает сигнал «Позвони» — бабушка получает СМС:  
   `Семья: 📞 Позвони`
9. Если бабушка пишет `Срочно` или `Болит` — в комнате это отображается как сигнал.

### Важные правила для этого сценария

- Номер бабушки должен быть в `allowFrom` и в карте контактов (номер → «Бабушка»).
- Сообщения из комнаты идут бабушке только текстом (без кнопок и разметки).
- Сигналы превращаются в понятный текст + эмодзи.
- Длинные сообщения режутся по правилам 70/67 (UCS-2).
- Эхо (сообщения самой бабушки) не возвращаются ей обратно.
- В шторке участников внук видит:  
  `Бабушка · СМС · кнопочный телефон`

### Что должно быть в интерфейсе внука

- В профиле участника видно канал («СМС»).
- При отправке сообщения, которое уйдёт на СМС, можно показывать маленький индикатор «уйдёт СМС».
- Кнопка «Позвонить на телефон» должна работать (SIP-мост), если настроен.

### Типичные боли, которые нужно закрыть

- Бабушка не понимает, от кого СМС → всегда подписывать «Семья:».
- Слишком длинные сообщения → честная сегментация + предупреждение внуку («сообщение разобьётся на 3 СМС»).
- Бабушка пишет «ок» или «ага» → система не пытается переводить и не портит короткие ответы.

## 8. Рекомендации по тестированию с пожилыми

### Кого звать
- 5–7 человек 65–80 лет
- Разный уровень владения смартфоном
- Хотя бы один человек, который почти не пользуется интернетом

### Как проводить
1. Не объяснять интерфейс заранее.
2. Давать жизненные задачи:
   - Создайте пространство
   - Пригласите меня
   - Напишите, что вы дома
   - Отправьте сигнал «Позвони»
   - Включите крупный текст
3. Смотреть:
   - Время до первого понимания
   - Куда человек тыкает первым
   - Какие слова не понимает
   - Где появляется страх
4. После задачи спрашивать только:
   - Что было непонятно?
   - Чего не хватало?
   - Что показалось лишним?

### Красные флаги
- Не понимает, что уже «в комнате»
- Не понимает, куда делась ссылка
- Боится нажимать сигналы
- Не замечает, что сообщение ушло

## 9. Принципы, которые нельзя нарушать

1. Человек важнее канала.
2. Сложность спрятана, простота — на поверхности.
3. Честные границы важнее красивых обещаний.
4. Один главный фокус на экране.
5. Профиль доступности — свойство человека, а не куча флажков на главном экране.
6. Адаптивная панель ввода — обязательна.
7. Все тексты — короткие и прямые.

## 10. Дополнение 0.8.1 (волна ×21, 2026-11-13)

Реализовано в прототипе `03-prototype/singulyar-prototype-0.8.html`; точные тексты — `07-honest-boundaries/ЧЕСТНЫЕ_ГРАНИЦЫ-0.8.1.md`.

### 10.1. Живое превью
- Превью в профиле реагирует на ЛЮБОЕ переключение мгновенно: меняется пример входящего сообщения (текст, брайль-строка, бейджи честности), пример субтитров и мини-панель «Так ты пишешь» (зеркало выбранного режима).
- Крупный текст и высокий контраст применяются ко всему телу — превью показывает их без отдельного кода.

### 10.2. Честные границы как первоклассный элемент
- Автоопределение устройства при открытии: вибрация, озвучка, микрофон, субтитры, WebRTC, сеть, буфер обмена — без запроса разрешений.
- Результат виден в трёх местах: статусные строки под переключателями, бейджи в живом превью (зелёный «✓» / янтарный «—»), свёрнутый раздел «Честные границы на этом устройстве».
- Каждый режим имеет точный текст подсказки ДО выбора и точный текст ошибки В момент отказа (разделы 2–4 файла честных границ).

### 10.3. Профиль «режимы вместо категорий» (жёсткая структура)
- Сверху — один главный выбор, карточки-радио: **Обычный · Сигналы и картинки · Только голос · Морзе** (взаимоисключающие).
- Ниже — плоский блок «Дополнительно» (крупный, контраст, озвучка, брайль, субтитры, вибрация, морзе-вибро, перевод) — можно любое сочетание, конфликтов нет.
- Панель ввода комнаты переключается строго по таблице режимов; морзе-клавиатура рабочая (· − ⌫ Буква Слово, расшифровка в поле отправки).

### 10.4. Чистый «бабушкин» вид
- Демо-бар спрятан из продакшен-вида. Вид разработчика возвращается параметром `?demo=1` — один файл, два режима, без копий.

### 10.5. Обычные люди — главный сценарий, а не побочный
- У каждого сообщения виден канал: «Бабушка · СМС», «Мама · WhatsApp», «Вы · браузер» — идея «один разговор, любой канал» видна глазами.
- Статусы честные и привязаны к каналу: «Доставлено на телефон», «Доставлено в WhatsApp», «Не отправилось: нет сети».
- Комната живая: индикатор «Мама печатает…» и один тёплый демо-ответ после первого сообщения.
- Приглашение в шторке участников: ссылка + «Скопировать» (с честным откатом, если буфер недоступен) + подсказка, откуда человек может зайти.
- Микрофон честный: без API — тост с текстом, а не молчаливая кнопка.

**Обычный режим — это режим большинства семьи. Он доводится до блеска первым; доступность — те же детали, включаемые один раз в профиле.**
